## 一、预处理是什么（和编译器无关）

### 1.1 完整的编译链

```
.c ──[预处理 cpp]──▶ .i ──[编译 cc1]──▶ .s ──[汇编 as]──▶ .o ──[链接 ld]──▶ elf
     ↑
     只做四件事：
     1. #include 展开（把整个头文件文本贴进来）
     2. #define 替换（纯文本替换，不理解类型和作用域）
     3. 条件编译（#if / #ifdef 决定留哪些行）
     4. 删注释、接续行（反斜杠）
```

**关键认知：预处理不理解 C**。它不知道什么是 `int`、什么是作用域、什么是函数。它只会做文本替换。

这解释了三件事：

- 为什么宏参数要加括号 —— 因为替换是**文本级**的，不是「传值」
- 为什么宏没有类型检查 —— 因为它根本不知道类型
- 为什么 `#define PI 3.14` 之后写 `PI` 会被替换，但 `PIx` 不会 —— 因为替换按**完整标识符**匹配

### 1.2 自己看展开结果

```bash
gcc -E main.c            # 输出预处理后的全文
gcc -E main.c | less     # 上千行，通常从 libc 头文件开始
gcc -E -P main.c         # -P 去掉行号标记，更干净
```

**这是排查宏问题的第一手段**。宏的行为和你想象的不一样时，`gcc -E` 看一眼就明白了。

### 1.3 宏不只是「常量」

```c
#define PI          3.14159
#define MAX(a,b)    ((a) > (b) ? (a) : (b))
#define STR(x)      #x
#define CAT(a,b)    a##b
#define VERSION     "1.2.3"
#define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))
```

五类用途：常量、函数式替换、字符串化、拼接、编译期计算。

## 二、对象宏 vs 函数宏

### 2.1 对象宏（无参数）

```c
#define BUFFER_SIZE  256
#define BIT(n)       (1UL << (n))
```

⚠️ **没有分号**。`#define X 1;` 会在展开时把分号带进去：

```c
#define BAD  256;

if (len > BAD) { }        // 展开成 if (len > 256;) { }  ← 编译错误
```

### 2.2 函数宏（带参数）

```c
#define MAX(a, b)  ((a) > (b) ? (a) : (b))
```

**参数和整体都要加括号**，原因见第三节。

### 2.3 一个必须知道的差异：宏没有类型检查

```c
#define MAX(a,b)  ((a) > (b) ? (a) : (b))

MAX(1, 2.5);        // 返回 double，1 被转成 double —— 能编译
MAX("a", "b");      // 编译错误（指针比较），但错误信息难懂

// 用 inline 函数则有类型检查
static inline int max_int(int a, int b) { return a > b ? a : b; }
max_int(1, 2.5);    // 隐式转换警告（如果开了 -Wconversion）
```

**能写 `static inline` 就别写宏**。宏只在三种情况下不可替代：

1. 需要在**编译期**求值（数组维度、`_Static_assert`、`case` 标签）
2. 需要**字符串化**或**拼接**（`#`、`##`）
3. 需要接受**任意类型**（如 `ARRAY_LEN`）

## 三、括号：宏的第一杀手

### 3.1 不加括号的真实后果

```c
#define SQUARE(x)  x * x
```

```c
SQUARE(3 + 1)      // 展开：3 + 1 * 3 + 1 = 3 + 3 + 1 = 7  ← 不是 16！
```

```c
#define DOUBLE(x)  (x) + (x)
2 * DOUBLE(3)      // 展开：2 * (3) + (3) = 6 + 3 = 9  ← 不是 12！
```

**正确写法：每个参数加括号，整体再加一层**：

```c
#define SQUARE(x)    ((x) * (x))
#define DOUBLE(x)    ((x) + (x))
```

### 3.2 一个可运行的实验

```c
#include <stdio.h>

#define BAD_SQ(x)   x * x
#define GOOD_SQ(x)  ((x) * (x))

int main(void) {
    printf("%d %d\n", BAD_SQ(3 + 1), GOOD_SQ(3 + 1));
    return 0;
}
```

实测输出：**`7 16`**。

### 3.3 三重括号的完整规则

```c
#define MULT(a, b)  ((a) * (b))
//                   ↑  ↑      ↑
//                   参数括号  整体括号
```

三条规则：

| 位置 | 为什么 |
|:--|:--|
| 每个参数外面 | 防止参数自己是表达式时优先级错 |
| 整个替换体外面 | 防止宏用在更大的表达式里时优先级错 |
| 参数在宏体里出现多次 | 考虑副作用（见下） |

### 3.4 副作用：宏无法避免的硬伤

```c
#define MAX(a, b)  ((a) > (b) ? (a) : (b))

int i = 5;
int m = MAX(i++, 10);
// 展开：((i++) > (10) ? (i++) : (10))
// i 被加了两次！而且第二次加的值不确定
```

实测（`SQ(i++)`）：

```
警告：operation on 'i' may be undefined [-Wsequence-point]
i=3  r=2   ← i 从 1 变成 3（加了两次）
```

**这是宏的固有限制，加括号也解决不了**。有三个解法：

```c
// ① GCC 扩展：语句表达式（能保证只求值一次）
#define MAX(a, b) ({          \
    __typeof__(a) _a = (a);   \
    __typeof__(b) _b = (b);   \
    _a > _b ? _a : _b;        \
})

// ② 用 inline 函数（推荐）
static inline int max_int(int a, int b) { return a > b ? a : b; }

// ③ 在宏文档里明确写「参数不能有副作用」
```

⚠️ `({ ... })` 是 **GCC/Clang 扩展**，不是标准 C。MSVC 不支持。

## 四、多重语句宏：`do { } while (0)`

### 4.1 问题：`if` 后面接多语句宏

```c
#define BAD_MACRO(x)  \
    x = 1;            \
    x += 2;

if (cond)
    BAD_MACRO(a);
else
    b = 0;
```

展开后：

```c
if (cond)
    a = 1;      // ← if 只管这一句
a += 2;         // ← 无条件执行！
else            // ← 编译错误：没有对应的 if
    b = 0;
```

### 4.2 标准解法

```c
#define GOOD_MACRO(x)  \
    do {               \
        (x) = 1;       \
        (x) += 2;      \
    } while (0)
```

展开后：

```c
if (cond)
    do { a = 1; a += 2; } while (0);
else
    b = 0;
```

**`do { } while (0)` 是一个语法上的单条语句**，所以 `if` / `else` 配对正确。而且 `while(0)` 保证了只执行一次，编译器会把它优化掉。

### 4.3 真实工程里的写法

`multi_cyc_fifo.c` 里所有多语句宏都是这个形式：

```c
#define AddCounter(i_xFifoLen, m_pxCounter)  \
    do {                                     \
        (*(m_pxCounter))++;                  \
        if (*(m_pxCounter) >= (i_xFifoLen))  \
        {                                    \
            *(m_pxCounter) -= (i_xFifoLen);  \
        }                                    \
    } while (0)

#define CheckAndChangeWriteFIFOStatus(m_pstNode)      \
    do {                                              \
        DisableAllInterrupts();                       \
        if ((m_pstNode)->xWriteAddr == (m_pstNode)->xReadAddr)  \
        {                                             \
            (m_pstNode)->eFifoStatus = FIFO_FULL;     \
        }                                             \
        else                                          \
        {                                             \
            (m_pstNode)->eFifoStatus = FIFO_USING;    \
        }                                             \
        EnableAllInterrupts();                        \
    } while (0u)
```

注意 `while (0u)` 里也用了 `0u` —— 保持无符号一致性，MISRA 的要求。

### 4.4 为什么不用 `{ }`

```c
#define BAD(x)  { x = 1; x += 2; }

if (cond)
    BAD(a);      // 展开：if (cond) { a = 1; a += 2; };
else             // ❌ 编译错误：else 前面有个多余的分号
    b = 0;
```

`{}` 后面跟着宏调用处的 `;`，就变成了「空语句」，`else` 就找不到 `if` 了。

**`do { } while (0)` 的核心价值就在于：它自己带分号语义，宏调用处的 `;` 是合法的。**

### 4.5 `while (0)` 会不会真的循环

```c
do { ... } while (0)
```

条件恒假，**必然只执行一次**。任何 `-O1` 以上的优化都会把 `while` 条件消除。所以没有运行时开销。

## 五、`#` 与 `##`：字符串化与拼接

### 5.1 `#`：把参数变成字符串

```c
#define STR(x)      #x

STR(hello)          // "hello"
STR(1 + 2)          // "1 + 2"    ← 原样文本，不求值
STR("quoted")       // "\"quoted\""  ← 引号被转义
```

⚠️ **`#x` 不做任何求值**，只是把源码文本变成字符串。这一点很重要：

```c
#define VALUE  42
STR(VALUE)          // "VALUE"    ← 不是 "42"！
```

### 5.2 两阶段展开：想要 "42" 怎么办

```c
#define STR_(x)   #x
#define STR(x)    STR_(x)     // 多一层间接

#define VALUE  42
STR(VALUE)      // "42"   ← 先展开 VALUE → 42，再字符串化
```

**原理**：外层宏 `STR` 的参数会先被完全展开（`VALUE` → `42`），然后再传给 `STR_`，`STR_` 里的 `#x` 才生效。

**这条「两级宏」技巧在需要字符串化任何宏值时都要用**，包括 `##`。

### 5.3 `##`：拼接两个记号

```c
#define CAT(a, b)   a##b

CAT(foo, bar)       // foobar  ← 变成一个标识符
CAT(1, 2)           // 12      ← 变成一个数字
```

**典型用途：按前缀生成变量名/函数名**

```c
#define DECLARE_GETTER(type, name)     \
    static type get_##name(void) {     \
        return g_##name;               \
    }

DECLARE_GETTER(int, counter)
// 展开成：static int get_counter(void) { return g_counter; }
```

### 5.4 拼接也需要两级

```c
#define CAT_(a, b)  a##b
#define CAT(a, b)   CAT_(a, b)

#define PREFIX  my
CAT(PREFIX, _var)   // my_var  ✅
// 单级写法 CAT_(PREFIX, _var) 会得到 PREFIX_var ❌
```

### 5.5 一个真实用途：带文件名的日志宏

```c
#define LOG(fmt, ...) \
    printf("[%s:%d] " fmt "\n", __FILE__, __LINE__, ##__VA_ARGS__)
```

`##__VA_ARGS__` 是 GCC 扩展：当可变参数为空时，去掉前面的逗号。C23 开始 `__VA_OPT__` 是标准写法。

⚠️ **`printf` 在中断里不能用**（阻塞、不可重入）。资源受限环境里日志宏通常是这样：

```c
#ifdef EN_DEBUG_PRINT
  #define DBG(fmt, ...)  printf("[%s:%d] " fmt "\r\n", __FILE__, __LINE__, ##__VA_ARGS__)
#else
  #define DBG(fmt, ...)  do { } while (0)     // 编译后完全消失
#endif
```

这样 Release 版本里所有 `DBG(...)` 都变成空语句，**零代码零开销**。

## 六、条件编译

### 6.1 三种基本形式

```c
// ① 简单开关
#ifdef EN_CRC_HARDWARE
    #include "crc_cfg.h"
#endif

// ② 二选一
#ifdef EN_CRC_HARDWARE
    crc = hw_crc(data, len);
#else
    crc = sw_crc(data, len);
#endif

// ③ 多选一
#if defined(EN_CAN_TP)
    #include "can_tp.h"
#elif defined(EN_LIN_TP)
    #include "lin_tp.h"
#else
    #error "必须定义一种传输层"
#endif
```

### 6.2 `#ifdef` vs `#if defined()`

```c
#ifdef A                  // 只看「有没有定义」，不管值
#if defined(A)            // 完全等价

#if A                     // 看「值是不是非零」
```

**差别在这里**：

```c
#define EN_DEBUG 0

#ifdef EN_DEBUG
    printf("debug\n");     // ✅ 会编译进来！因为「定义了」，值是 0 也算定义
#endif

#if EN_DEBUG
    printf("debug\n");     // ❌ 不会编译进来，因为值是 0
#endif
```

**这就是为什么 `#define EN_DEBUG 0` 关不掉调试输出** —— 必须用 `#if` 或者干脆注释掉 `#define`。

### 6.3 真实工程：feature 开关集中管理

很多项目用一个 `user_config.h` 集中管理所有开关：

```c
#define EN_DEBUG_IO
//#define EN_DEBUG_TIMER
//#define EN_ASSERT
//#define EN_UDS_DEBUG

#define EN_ZLG_SA_ALGORITHM         /* 某厂商专用安全访问算法 */
//#define EN_AES_SA_ALGORITHM_SW
//#define EN_AES_SA_ALGORITHM_HW

#define EN_CAN_TP
//#define EN_LIN_TP
//#define EN_ETHERNET_TP

//#define EN_CRC_HARDWARE
#define EN_CRC_SOFTWARE
```

**优点**：
- 一眼看出当前固件启用了什么
- 换配置只改这个文件
- 配合 CI 可以自动测「所有开关组合都能编译」（编译矩阵）

**缺点**（真实痛点）：
- 注释掉 `//` 和 `#if 0` 混用，风格不统一
- 开关之间可能有隐含依赖（开了 A 必须开 B），没人写文档
- 组合爆炸：10 个开关 = 1024 种组合，实际只测了几种

**改进方案**：用 `#if` + 明确取值，配合编译期检查：

```c
#define EN_CAN_TP   1
#define EN_LIN_TP   0

#if (EN_CAN_TP + EN_LIN_TP + EN_ETHERNET_TP) != 1
  #error "必须且只能启用一种传输层"
#endif
```

### 6.4 编译期断言 `_Static_assert`

C11 的标准特性，比 `#if ... #error` 更好用：

```c
#include <assert.h>

_Static_assert(sizeof(struct wire) == 6, "wire 必须是 6 字节");
_Static_assert(RB_SIZE && (RB_SIZE & (RB_SIZE - 1)) == 0, "RB_SIZE 必须是 2 的幂");
_Static_assert(sizeof(uint32_t) == 4, "需要 32 位 uint32_t");
```

**价值**：把「假设」变成「编译期错误」。换个编译器、换个架构、换个选项，违反假设就立刻报错，而不是运行时才发现。

**老编译器（C99 之前）的写法**：

```c
// 技巧：数组长度为负会编译错误
#define STATIC_ASSERT(cond, msg)  typedef char static_assert_##msg[(cond) ? 1 : -1]
```

### 6.5 平台/编译器检测

```c
#if defined(__GNUC__)
    #define PACKED   __attribute__((packed))
    #define ALIGNED(n) __attribute__((aligned(n)))
#elif defined(_MSC_VER)
    #define PACKED
    #pragma pack(push, 1)
    #define ALIGNED(n) __declspec(align(n))
#else
    #error "未支持的编译器"
#endif
```

```c
// 架构检测
#if defined(__ARM_ARCH_7M__)
    // Cortex-M3
#elif defined(__ARM_ARCH_6M__)
    // Cortex-M0
#elif defined(__riscv)
    // RISC-V
#endif
```

⚠️ **不要用 `__ARM__` 这种非标准宏**，用编译器文档里定义的（`__arm__`、`__ARM_ARCH`）。

## 七、头文件保护与 `#include` 的正确姿势

### 7.1 `#ifndef` 保护（最经典）

```c
// gpio.h
#ifndef GPIO_H
#define GPIO_H

void gpio_init(void);
int  gpio_read(int pin);

#endif /* GPIO_H */
```

**为什么必须加**：同一个头文件可能被间接包含多次（A 包含 C，B 包含 A 和 C）。没有保护，`void gpio_init(void);` 会被声明两次 —— **函数声明重复是合法的**，但**结构体定义、`typedef`、`static` 变量重复就报错**。

### 7.2 `#pragma once`（更简洁，非标准但广泛支持）

```c
// gpio.h
#pragma once

void gpio_init(void);
```

**优点**：一行搞定，不会因宏名冲突而失效。
**缺点**：理论上非标准（但 GCC/Clang/MSVC/几乎所有主流编译器都支持）；某些特殊场景（同一文件通过符号链接以不同路径包含）行为不同。

**实践建议**：**两个都写**。

### 7.3 宏名冲突的真实事故

```c
// a.h
#ifndef CONFIG_H        // ← 用了太通用的名字
#define CONFIG_H
...
#endif

// b.h（第三方库）
#ifndef CONFIG_H        // ← 撞了！
#define CONFIG_H
// b.h 的全部内容被跳过
#endif
```

**后果**：`b.h` 里的声明全部消失，链接时一堆 `undefined reference`。

**防范**：宏名带项目前缀和路径。

```c
#ifndef MYPROJECT_BSP_GPIO_H
#define MYPROJECT_BSP_GPIO_H
```

### 7.4 `#include` 的两种括号

```c
#include <stdio.h>      // 尖括号：从系统/工具链路径找
#include "myheader.h"   // 引号：先从当前文件所在目录找，再找系统路径
```

⚠️ **工程里的常见坑**：`#include "stdint.h"` 会先找当前目录，如果恰好有个同名的本地 `stdint.h`，就会把系统那个屏蔽掉。**标准头文件一律用尖括号**。

### 7.5 头文件里不要做的事

| 不要 | 为什么 | 例外 |
|:--|:--|:--|
| 定义变量（`int g_x;`） | 每个包含它的 .o 都会有一份 → 重复定义 | `static`（每个 .o 一份，浪费）或 `extern` 声明 |
| 定义函数（非 `static inline`） | 同上 | `static inline` |
| `using namespace`（C++） | 污染所有包含者 | 无 |
| 大段实现代码 | 编译时间爆炸 | `static inline` 小函数 |

**头文件的正确内容**：

```c
#ifndef X_H
#define X_H

#include <stdint.h>          // 需要的类型

// 类型定义
typedef struct { uint32_t a; } x_t;

// 宏/常量
#define X_MAX  100

// extern 变量声明
extern x_t g_x;

// 函数声明
void x_init(void);

// static inline 小函数（可选）
static inline int x_get(const x_t *p) { return (int)p->a; }

#endif
```

### 7.6 `extern` 声明 vs 定义

```c
// header.h
extern int g_counter;      // 声明：告诉编译器「有这么个东西，在别处」

// a.c
int g_counter = 0;         // 定义：真正分配内存

// 常见错误：在头文件里写
int g_counter;             // ❌ 这是「暂定定义」，每个包含它的 .o 都分配一份
                           //    C 老标准允许合并，C99 之后是 UB（重复定义）
```

**规则**：头文件里**只放 `extern`**，定义放 `.c`。

## 八、X-Macro：宏的高级用法

### 8.1 问题：同一组数据要写三遍

```c
enum color { RED, GREEN, BLUE };

const char *color_name[] = { "RED", "GREEN", "BLUE" };

uint32_t color_value[] = { 0xFF0000, 0x00FF00, 0x0000FF };
```

**问题**：加一个新颜色要改三处，漏一处就错位（`color_name[BLUE]` 拿到 "GREEN"）。

### 8.2 X-Macro 解法：单一数据源

```c
// 数据表只写一次
#define COLOR_LIST  \
    X(RED,   0xFF0000) \
    X(GREEN, 0x00FF00) \
    X(BLUE,  0x0000FF)

// 生成 enum
enum color {
#define X(name, val) name,
    COLOR_LIST
#undef X
    COLOR_COUNT
};

// 生成名字表
const char *color_name[] = {
#define X(name, val) #name,
    COLOR_LIST
#undef X
};

// 生成值表
const uint32_t color_value[] = {
#define X(name, val) val,
    COLOR_LIST
#undef X
};
```

**实测预处理展开结果**：

```c
enum color {
  RED, GREEN, BLUE,
  COLOR_COUNT
};
```

**实测运行**：`COLOR_COUNT=3  name[1]=GREEN`。

### 8.3 为什么这很强

| 好处 | 说明 |
|:--|:--|
| 单一数据源 | 加一行动作，enum / 名字 / 值全部同步 |
| 编译器检查 | 少写一个 `X` 定义就编译错误 |
| 用在 switch | 可以生成 `case` 分支 |
| 用在解析 | 可以生成「字符串 → 枚举」的查找函数 |

### 8.4 生成错误码表（很实用）

```c
#define ERROR_LIST                    \
    X(ERR_NONE,        "OK")          \
    X(ERR_TIMEOUT,     "Timeout")     \
    X(ERR_CRC,         "CRC error")   \
    X(ERR_BUFFER_FULL, "Buffer full")

typedef enum {
#define X(code, msg) code,
    ERROR_LIST
#undef X
    ERR_COUNT
} err_t;

static const char *const err_msg[] = {
#define X(code, msg) msg,
    ERROR_LIST
#undef X
};

const char *err_str(err_t e) {
    return (e < ERR_COUNT) ? err_msg[e] : "Unknown";
}
```

**这样错误码和文案永远一致**，不会出现「加了错误码忘了加文案」。

### 8.5 代价

- **可读性下降**：不熟悉的人看到一堆 `X(...)` 会懵
- **调试困难**：`gcc -E` 展开后行号全乱，报错信息指向宏定义行而不是使用行
- **IDE 跳转失效**：很多 IDE 不能从 `ERR_TIMEOUT` 跳到定义

**结论**：适合「同一份数据要生成多种表示」的场景（错误码、命令表、寄存器表），不适合为了炫技而用。

## 九、`#undef`、`#pragma`、`#error`

### 9.1 `#undef`

```c
#define MAX  100
...
#undef MAX
#define MAX  200     // 重新定义，不报警告
```

**X-Macro 里必须用 `#undef X`** —— 否则同一个名字的宏定义会冲突（重定义成不同内容会报警告）。

### 9.2 `#pragma`

编译器相关的指令，标准只规定了 `#pragma STDC ...` 几种：

```c
#pragma pack(push, 1)         // 结构体紧凑（见 03 文档）
#pragma pack(pop)

#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wunused-parameter"
void callback(int unused) { }
#pragma GCC diagnostic pop
```

⚠️ **`#pragma` 是不可移植的**，不同编译器行为可能完全不同。用之前确认目标编译器支持。

### 9.3 `#error`

```c
#if !defined(EN_CAN_TP) && !defined(EN_LIN_TP)
  #error "必须定义 EN_CAN_TP 或 EN_LIN_TP"
#endif
```

**用途**：配置错误在编译期就拦下来，而不是运行时才崩。

### 9.4 `#warning`（GCC 扩展）

```c
#if defined(EN_CRC_HARDWARE) && defined(EN_CRC_SOFTWARE)
  #warning "同时启用了硬件和软件 CRC，将使用硬件版本"
#endif
```

比 `#error` 温和，适合「能跑但有隐患」的情况。

## 十、什么时候不该用宏

### 10.1 优先用 `static inline`

```c
// ❌ 宏：无类型检查、无调试信息、副作用风险
#define MAX(a, b)  ((a) > (b) ? (a) : (b))

// ✅ inline：有类型检查、可调试、只求值一次
static inline int max_int(int a, int b) { return a > b ? a : b; }
```

`static inline` 在 `-O2` 下和内联宏生成一样的代码，但**有全部的类型安全**。

### 10.2 优先用 `const` / `enum`

```c
// ❌ 宏常量：无类型
#define MAX_CONN  100

// ✅ const：有类型，可在调试器里看到
static const int MAX_CONN = 100;

// ✅ enum：编译期常量，可作数组维度
enum { MAX_CONN = 100 };
```

⚠️ `const int` 在 C 里**不是编译期常量**，不能作数组维度：

```c
static const int N = 10;
int arr[N];        // ❌ C 里编译不过（C++ 可以）
```

**需要编译期常量时用 `enum` 或 `#define`**。

### 10.3 判断标准

| 需求 | 选什么 |
|:--|:--|
| 编译期常量、数组维度 | `enum` 或 `#define` |
| 有类型、只在运行时用 | `static const` |
| 有类型的「函数」 | `static inline` |
| 需要字符串化 / 拼接 | 宏（无替代） |
| 需要接受任意类型 | 宏（或用 `_Generic`） |
| 条件编译 | 宏（无替代） |
| 多语句封装 | `do { } while (0)` 宏 |

## 十一、错误清单

| 症状 | 原因 | 修法 |
|:--|:--|:--|
| `SQUARE(3+1)` 得 7 | 参数没加括号 | 每个参数 + 整体都加括号 |
| `i++` 在宏里被加两次 | 宏参数多次求值 | 改 `static inline`，或文档禁止副作用 |
| `if` 后面的宏导致 `else` 报错 | 多语句宏没用 `do{}while(0)` | 改成 `do { } while (0)` |
| `#define X 1;` 编译错误 | 宏定义带了分号 | 去掉分号 |
| `STR(VALUE)` 得 "VALUE" | 少一层间接 | 加两级宏 `STR_` / `STR` |
| `CAT(PREFIX, x)` 得 `PREFIXx` | 少一层间接 | 加两级宏 `CAT_` / `CAT` |
| `#define DEBUG 0` 关不掉输出 | 用了 `#ifdef` 而非 `#if` | 改 `#if DEBUG` |
| 头文件保护失效 | 宏名撞车 | 宏名带项目前缀+路径 |
| `undefined reference` 一堆 | 头文件里定义了变量 | 头文件只放 `extern` |
| 系统头被本地同名文件顶掉 | `#include "stdint.h"` | 标准头用 `<>` |
| `1 << 31` 出错 | `int` 溢出 | `1UL << 31` |
| 位域/结构体大小随编译器变 | 用了 `#pragma pack` 无断言 | 加 `_Static_assert` |
| 宏展开后看不懂 | 需要看展开结果 | `gcc -E -P file.c` |
