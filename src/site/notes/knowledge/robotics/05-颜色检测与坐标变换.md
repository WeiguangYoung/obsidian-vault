## 一、4.1 颜色检测

### 1.1 数据流

```
Gazebo camera → ignition.msgs.Image
     ↓ ros_gz_bridge
ROS 2 /camera/image_raw (sensor_msgs/Image)
     ↓ cv_bridge
OpenCV Mat (BGR)
     ↓ cvtColor + inRange
HSV 掩码 → 轮廓 → 质心
     ↓
/target_pixel (PointStamped: x=u, y=v, z=area)
```

### 1.2 关键代码

```python
img = self.bridge.imgmsg_to_cv2(msg, desired_encoding='bgr8')
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv, np.array([h_low, 80, 80]),
                         np.array([h_high, 255, 255]))
contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
largest = max(contours, key=cv2.contourArea)
M = cv2.moments(largest)
cx, cy = int(M['m10']/M['m00']), int(M['m01']/M['m00'])
```

**为什么用 HSV 不用 RGB**：

| 色彩空间 | 光照变化时 |
|---|---|
| RGB | 亮度变化直接影响三个通道 |
| **HSV** | **H（色相）与亮度解耦**，阴影下也能识别 |

### 1.3 实测结果

World 里加了红色立方体：

```xml
<model name="red_target">
  <pose>2 0 0.3 0 0 0</pose>     <!-- 正前方 2m -->
  <material><ambient>1.0 0.0 0.0 1</ambient></material>
</model>
```

检测输出：

```yaml
point:
  x: 319.0      # 像素横坐标（640 宽，中心 320）
  y: 43.0       # 像素纵坐标
  z: 9615.0     # 轮廓面积（像素）
```

**x=319 ≈ 320（画面中心）** —— 说明相机正对红色立方体，与世界文件 `pose 2 0 0.3` 吻合。

## 二、4.2 相机标定（原理）

### 2.1 内参矩阵

```
     ┌ fx   0   cx ┐
K =  │  0  fy   cy │
     └  0   0    1 ┘
```

| 参数 | 含义 | 典型值 |
|---|---|---|
| **fx, fy** | 焦距（像素单位）= 物理焦距 / 像素尺寸 | 640 宽 → ~554 |
| **cx, cy** | 主点（光轴与成像面交点） | ≈ 图像中心 (320, 240) |

### 2.2 畸变系数

```
径向畸变：k1, k2, k3      （桶形/枕形）
切向畸变：p1, p2          （透镜安装偏差）
```

**去畸变公式**（简化）：

```
x_corrected = x * (1 + k1*r² + k2*r⁴ + k3*r⁶)
y_corrected = y * (1 + k1*r² + k2*r⁴ + k3*r⁶)
```

### 2.3 标定流程

```bash
# 1. 打印棋盘格（推荐 9x6 内角点）
# 2. 拍 15-20 张不同角度的照片
# 3. 跑标定
ros2 run camera_calibration cameracalibrator \
    --size 9x6 --square 0.025 \
    image:=/camera/image_raw camera:=/camera
# 4. 界面变绿后点 CALIBRATE → SAVE
# 5. 生成 /tmp/calibrationdata.tar.gz
```

**产出**：内参矩阵 K、畸变系数 D、重投影误差（< 0.5 像素算好）。

> **本次没做实际标定**——仿真相机的内参是理想的（无畸变），用典型值即可。
> 公式里的 `fx=554.3` 是 640x480 / 60° FOV 的理论值。

## 三、4.3 像素 → 世界坐标

### 3.1 完整反投影链

```
像素 (u, v)
   ↓ 减去主点、除以焦距（内参）
归一化坐标 (x_n, y_n) = ((u-cx)/fx, (v-cy)/fy)
   ↓ 乘深度 Z
相机光学系 (Xo, Yo, Zo) = (x_n*Z, y_n*Z, Z)
   ↓ 坐标系转换（光学系 → ROS 常规系）
ROS 系 (Xr, Yr, Zr) = (Zo, -Xo, -Yo)
   ↓ 加相机安装位置（外参）
base_link (X, Y, Z) = (Xr+cx_cam, Yr+cy_cam, Zr+cz_cam)
```

### 3.2 两个容易搞错的坐标系

| 坐标系 | X 轴 | Y 轴 | Z 轴 |
|---|---|---|---|
| **相机光学系**（opencv） | 右 | **下** | **前** |
| **ROS 常规系**（REP-103） | **前** | 左 | 上 |

**转换关系**：

```python
Xr = Zo          # 前方
Yr = -Xo         # 左侧为正（光学系的 Y 向下 → 取负）
Zr = -Yo         # 上方为正
```

> **这是最容易出错的地方**：如果把光学系的 Y 直接当成 ROS 系的 Y，所有目标的上下位置都会反。

### 3.3 深度从哪来

| 方案 | 说明 | 成本 |
|---|---|---|
| **单目 + 平面假设**（本次） | 假设目标在地面上，用几何关系反算 | 0 |
| 双目相机 | 视差算深度 | ¥1000+ |
| RGB-D（RealSense/Orbbec） | 直接出深度图 | ¥1500+ |
| 激光雷达 + 相机融合 | 对齐后取点云 | 需要标定外参 |

**本次用固定深度 2.0m**（因为红色立方体就在 2m 处）。生产环境要根据实际场景选方案。

### 3.4 实测结果

输入：检测到像素 (319, 43)，假设深度 2.0m，相机在 base_link 前方 0.1m、上方 0.1m

输出：

```yaml
frame_id: base_link
point:
  x: 2.100      # 前方 2.1m
  y: 0.004      # 几乎正中
  z: 0.811      # 高度 0.81m
```

**误差分析**：

| 项 | 真值 | 计算值 | 误差 | 原因 |
|---|---|---|---|---|
| X | 2.0m（立方体位置） | 2.100m | +0.1m | 相机前移量，符合预期 |
| Y | 0（正前方） | 0.004m | **4mm** | 像素 319 vs 中心 320，完全对得上 |
| Z | ~0.3m（立方体中心） | 0.811m | 偏大 | 固定深度假设导致 |

**X 和 Y 精确**说明反投影链路正确。Z 的偏差来自「假设深度 2m」这个简化——实际几何是斜视，应解三角形。

## 四、踩的坑

### 坑 1：numpy 2.x 与 cv2 4.5.4 不兼容

**现象**：
```
AttributeError: _ARRAY_API not found
ImportError: numpy.core.multiarray failed to import
```

**根因**：之前为装 onnxruntime 升了 numpy 2.2.6，但系统 cv2 4.5.4 是用 numpy 1.x 编译的，ABI 不兼容。

**解法**：
```bash
python3 -m pip install --user 'numpy<2'
# 降到 1.26.4，cv2 / onnxruntime / ROS 三者都正常
```

> **教训**：Python 科学计算栈的 ABI 耦合很紧。**装任何新包前先看它会不会动 numpy**——动了就可能搞崩别的。

### 坑 2：TF 树缺 base_link

**现象**：`Invalid frame ID "base_link" - frame does not exist`

**根因**：只启动了 Gazebo，没启动 `robot_state_publisher`。Gazebo 自带的 `/tf` 是 `diffbot/*` 命名空间，与 ROS 常规帧名对不上。

**解法（两条路）**：

| 路线 | 做法 | 适用 |
|---|---|---|
| A. 补 TF | 启动 `robot_state_publisher` + `joint_state_publisher` | 生产环境 |
| **B. 用外参**（本次） | 相机安装位置离线标定，直接写进参数 | 相机固定不动时更简单 |

**为什么选 B**：机器人上相机位置是固定的（装在车体上），外参标一次就够，不需要每帧查 TF。这比 TF 查询还快。
