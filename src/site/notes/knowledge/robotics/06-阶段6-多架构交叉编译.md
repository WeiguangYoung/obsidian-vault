# 🔀 ROS 2 多架构交叉编译实战（x86 → aarch64）

## 摘要

在 x86_64 的 Ubuntu 22.04 上，把 **真实的 rclcpp 节点**交叉编译成 aarch64 制品，并用 QEMU 验证可执行。全程不依赖目标硬件，**0 元成本**。

**最终验证**：

```
$ file cross_ros_test
cross_ros_test: ELF 64-bit LSB pie executable, ARM aarch64, version 1

$ readelf -h cross_ros_test | grep Machine
  Machine:  AArch64

$ ./cross_ros_test        # QEMU 用户态模拟执行
[INFO] [cross_node]: === Built for aarch64 ===
[INFO] [cross_node]: pointer=8 bytes, c++=201703
```

**核心结论**：交叉编译 ROS 2 的难点**不是编译器**（装个 `gcc-aarch64-linux-gnu` 就行），而是：

1. **Debian 多架构的限制** —— `Architecture: all` 的包不生成 `:arm64` 变体
2. **ROS 依赖链的深度** —— rclcpp 递归依赖 ~93 个包
3. **ament 构建系统对环境的假设** —— 它假设"本机能 import ament_package"

---

## 一、为什么需要交叉编译

| 场景 | 说明 |
|---|---|
| **CI 构建 ARM 制品** | 服务器是 x86，要产出 Jetson / RK3588 能跑的二进制 |
| **无目标硬件时的验证** | 编译错误能在 x86 上提前暴露，不用等硬件 |
| **构建速度** | x86 编译比 ARM 板子上快 5-10 倍 |

**关键认知**：交叉编译产出的二进制**和真机编译的是同一个东西**（相同 ABI）。区别只在"用的编译器跑在哪"。

---

## 二、三步走（从简单到完整）

### 步骤 1：装交叉编译工具链

```bash
sudo apt install -y gcc-aarch64-linux-gnu g++-aarch64-linux-gnu
```

**实测**：`aarch64-linux-gnu-gcc (Ubuntu 11.4.0-1ubuntu1~22.04.3) 11.4.0`

**验证**：
```bash
cat > /tmp/hello.c << 'EOF'
#include <stdio.h>
int main(void) {
#if defined(__aarch64__)
    printf("ARCH=aarch64 OK\n");
#endif
    return 0;
}
EOF

aarch64-linux-gnu-gcc -o /tmp/hello /tmp/hello.c
file /tmp/hello
# → ELF 64-bit LSB pie executable, ARM aarch64
```

**此时在 x86 上跑会失败**：
```
bash: ./hello: cannot execute binary file: Exec format error
```

### 步骤 2：装 QEMU 让 x86 能跑 ARM 二进制

```bash
sudo apt install -y qemu-user-static binfmt-support

# 验证 binfmt 已注册
ls /proc/sys/fs/binfmt_misc/ | grep qemu-aarch64
# → qemu-aarch64
```

**但还缺动态链接器**：
```bash
./hello
# → qemu-aarch64-static: Could not open '/lib/ld-linux-aarch64.so.1'
```

需要 arm64 的运行时库。这引出步骤 3。

### 步骤 3：加 arm64 软件源

```bash
sudo dpkg --add-architecture arm64
```

**关键**：Ubuntu 的 arm64 包不在 `archive.ubuntu.com`，而在 **`ports.ubuntu.com`**（或国内镜像的 `ubuntu-ports`）。

```bash
sudo tee /etc/apt/sources.list.d/arm64-ports.list > /dev/null << 'EOF'
deb [arch=arm64] http://mirrors.tuna.tsinghua.edu.cn/ubuntu-ports/ jammy main universe
deb [arch=arm64] http://mirrors.tuna.tsinghua.edu.cn/ubuntu-ports/ jammy-updates main universe
EOF

sudo apt update
sudo apt install -y libc6:arm64 libstdc++6:arm64
```

**此时 ARM 二进制能跑了**：
```bash
./hello
# → ARCH=aarch64 OK
```

## 三、坑 1：`Architecture: all` 包没有 `:arm64` 变体

### 现象

```bash
sudo apt install -y ros-humble-rclcpp:arm64
```

```
ros-humble-ament-cmake-core:arm64 : Depends: python3-catkin-pkg-modules:arm64
  but it is not installable
ros-humble-rosidl-cli:arm64 : Depends: python3-argcomplete:arm64
  but it is not installable
```

### 根因

```bash
$ apt-cache show python3-catkin-pkg-modules | grep Architecture
Architecture: all
```

**Debian 多架构规则**：`Architecture: all` 的包（纯 Python、纯数据）**不生成架构限定变体**。你没法用 `:arm64` 去装它——它本来就和架构无关。

但 ROS 的 arm64 包在 `Depends` 里写的是 `python3-catkin-pkg-modules:arm64`（自动加的架构限定），于是 apt 找不到。

**这是 Debian 多架构的已知限制**，短期无解。

### 解法：绕开 apt 的依赖解析

**不要用 `apt install`，改用 `apt-get download` + 手动解压**：

```bash
cd /tmp/sysroot-dl
apt-get download ros-humble-rclcpp:arm64      # 只下载，不检查依赖
dpkg-deb -x ros-humble-rclcpp_*.deb /opt/ros-aarch64-sysroot
```

**Python 包怎么办**：它们是纯 Python，**直接用宿主机的版本**，只需要让 CMake 能找到（见坑 3）。

## 四、坑 2：ROS 依赖链深不见底

### 现象

下载完 `rclcpp` 后，CMake 报缺 `ament_cmake_libraries`。

补上后，又缺 `libstatistics_collector`。

再补，又缺 `ament_cmake_export_definitions`。

**一个接一个，看不到尽头。**

### 解法：递归解析脚本

```bash
#!/bin/bash
SYSROOT=/opt/ros-aarch64-sysroot
WORK=/tmp/sysroot-dl
mkdir -p "$WORK" && cd "$WORK"
touch .seen

fetch() {
  local pkg="$1"
  local base="${pkg%%:*}"
  grep -qx "$base" .seen && return
  echo "$base" >> .seen

  if ! ls "${base}"_*.deb >/dev/null 2>&1; then
    apt-get download "${base}:arm64" >/dev/null 2>&1 || return
  fi

  local deb=$(ls "${base}"_*.deb 2>/dev/null | head -1)
  [ -n "$deb" ] && dpkg-deb -x "$deb" "$SYSROOT" 2>/dev/null

  # 递归处理 Depends
  local deps=$(dpkg-deb -f "$deb" Depends 2>/dev/null \
    | tr ',' '\n' | sed 's/(.*//; s/|.*//; s/^ *//; s/ *$//' | grep -v '^

**实测结果**：递归处理后，`rclcpp` 及其依赖共 **93 个包**，sysroot 达 **120MB**。

## 五、坑 3：ament 的 Python 包导入失败

### 现象

```
ModuleNotFoundError: No module named 'ament_package'
```

CMake 配置时，ament_cmake 会执行 Python 脚本生成模板，但宿主 Python 没有 `ament_package`。

### 根因

sysroot 里**有** `ament_package`：
```
/opt/ros-aarch64-sysroot/opt/ros/humble/lib/python3.10/site-packages/ament_package/
```

但宿主 Python 的 `sys.path` 里没有这个路径。

### 解法

```bash
export PYTHONPATH=/opt/ros-aarch64-sysroot/opt/ros/humble/lib/python3.10/site-packages:$PYTHONPATH
```

> **为什么这样可行**：`ament_package` 是纯 Python，不编译、不调本地库，所以 x86 的 Python 跑它完全没问题。

## 六、坑 4：`get_used_typesupports` 找不到实现

### 现象

```
CMake Error at rosidl_typesupport_c/cmake/get_used_typesupports.cmake:35:
  No 'rosidl_typesupport_c' found
```

库明明在 sysroot 里（`librosidl_typesupport_c.so`）。

### 根因

该 CMake 函数通过扫描 **`AMENT_PREFIX_PATH`** 查找 typesupport 实现。没设这个环境变量，它就找不到。

### 解法

```bash
export AMENT_PREFIX_PATH=/opt/ros-aarch64-sysroot/opt/ros/humble
```

## 七、坑 5：链接时找不到 `libpython3.10.so`

### 现象

```
make[2]: *** No rule to make target
  '/usr/lib/aarch64-linux-gnu/libpython3.10.so'
```

### 根因

CMake 引用了**宿主机的绝对路径** `/usr/lib/aarch64-linux-gnu/`（由交叉工具链注册），而不是 sysroot 里的路径。

### 解法

把 sysroot 里的库拷到该路径：

```bash
sudo cp -a /opt/ros-aarch64-sysroot/usr/lib/aarch64-linux-gnu/libpython3.10.so* \
           /usr/lib/aarch64-linux-gnu/
```

> 这不算优雅，但有效。更干净的做法是在 toolchain 文件里设置 `CMAKE_SYSROOT` 并让 CMake 完全走 sysroot 路径。本次采用拷贝是因为时间成本更低。

## 八、完整的 toolchain 文件

```cmake
# aarch64-toolchain-sysroot.cmake
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR aarch64)
set(CMAKE_SYSTEM_VERSION 1)

set(SYSROOT "/opt/ros-aarch64-sysroot")

set(CMAKE_C_COMPILER   /usr/bin/aarch64-linux-gnu-gcc)
set(CMAKE_CXX_COMPILER /usr/bin/aarch64-linux-gnu-g++)
set(CMAKE_SYSROOT "${SYSROOT}")

set(CMAKE_FIND_ROOT_PATH "${SYSROOT}" "/usr/aarch64-linux-gnu")
set(CMAKE_PREFIX_PATH "${SYSROOT}/opt/ros/humble")

# 关键：程序在宿主找，库/头文件只在目标找
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_PACKAGE ONLY)
```

**使用方法**：
```bash
export PYTHONPATH=$SYSROOT/opt/ros/humble/lib/python3.10/site-packages:$PYTHONPATH
export AMENT_PREFIX_PATH=$SYSROOT/opt/ros/humble

cmake .. -DCMAKE_TOOLCHAIN_FILE=aarch64-toolchain-sysroot.cmake
make
```

## 九、验证方法（三步）

### 1. 检查 ELF 架构

```bash
file cross_ros_test
# ELF 64-bit LSB pie executable, ARM aarch64

readelf -h cross_ros_test | grep -E 'Class|Machine'
# Class:   ELF64
# Machine: AArch64
```

### 2. 检查依赖库

```bash
readelf -d cross_ros_test | grep NEEDED
# librclcpp.so
# libstd_msgs__rosidl_typesupport_cpp.so
# librcl.so
# librmw.so
# ...
```

**这是关键**：依赖的是**真实的 ROS 库**，不是空壳。

### 3. QEMU 执行验证

```bash
export LD_LIBRARY_PATH=$SYSROOT/opt/ros/humble/lib:$SYSROOT/usr/lib/aarch64-linux-gnu
./cross_ros_test
# [INFO] [cross_node]: === Built for aarch64 ===
# [INFO] [cross_node]: pointer=8 bytes, c++=201703
```

## 十、CI 集成方案

### 在 GitHub Actions / Jenkins 里

```yaml
cross_build:
  image: ros2-ci:humble-base
  script:
    - apt install -y gcc-aarch64-linux-gnu g++-aarch64-linux-gnu qemu-user-static
    - bash docker/build_sysroot.sh          # 建 sysroot
    - export PYTHONPATH=/opt/ros-aarch64-sysroot/opt/ros/humble/lib/python3.10/site-packages:$PYTHONPATH
    - export AMENT_PREFIX_PATH=/opt/ros-aarch64-sysroot/opt/ros/humble
    - colcon build --cmake-args -DCMAKE_TOOLCHAIN_FILE=aarch64-toolchain-sysroot.cmake
  artifacts:
    paths: ["**/build/**/*.so", "**/install/**"]
```

### 关键点

| 项 | 说明 |
|---|---|
| **sysroot 要缓存** | 120MB，重建一次要 10 分钟，缓存它 |
| **PYTHONPATH 必须设** | 否则 ament 模板脚本失败 |
| **AMENT_PREFIX_PATH 必须设** | 否则 typesupport 找不到 |
| **QEMU 仅用于验证** | 别在 CI 里跑 ARM 仿真，太慢 |

## 十一、目标平台认知（无需硬件）

| 平台 | 芯片 | 系统 | Ubuntu | 关键坑 |
|---|---|---|---|---|
| **Jetson Orin Nano** | ARM64 | JetPack 6.x | 22.04 | CUDA 版本锁死；容器需 nvidia-container 特配 |
| **Jetson Xavier NX** | ARM64 | JetPack 5.x | 20.04 | 只能跑 ROS 2 Foxy，不是 Humble |
| **RK3588** | ARM64 | 各家 BSP | 20.04/22.04 | 内核差异大；GPU 驱动闭源 |
| **树莓派 4B** | ARM64 | RPi OS / Ubuntu | 22.04 | 官方 ROS 支持但不完整 |

**面试要点**：能说清"Jetson Orin Nano 是 JetPack 6 + Ubuntu 22.04，能跑 ROS 2 Humble"就够，不需要真机。
