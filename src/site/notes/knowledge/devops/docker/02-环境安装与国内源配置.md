# Docker 环境安装与国内源配置

> 目标：在一台干净的 Linux 机器上装好 Docker、配好国内镜像源、验证能用。
> 一句话主线：**发行版仓库装出来的通常是旧版，要么升官方源，要么认命用旧版；国内源不配，拉镜像基本拉不动。**

---

## 〇、先确认要装哪个版本

| 装法 | 版本 | 适用 |
|:--|:--|:--|
| 发行版仓库（`apt install docker.io`）| 旧（Ubuntu 22.04 是 20.10）| 快速试用，不追新特性 |
| **Docker 官方源** | **最新稳定版** | 生产、需要 BuildKit 新特性 |
| 官方一键脚本 `get.docker.com` | 最新稳定版 | 图省事，但不适合受控环境 |
| 发行版提供 `docker-ce` 包 | 较新 | 部分企业镜像源 |

> **判断标准**：如果你要用 `docker compose`（v2 插件）、BuildKit 新特性、或者多阶段构建的 cache mount，**必须用官方源**——发行版仓库的版本太旧，缺这些东西。

## 一、Ubuntu / Debian：官方源安装（推荐）

### 1.1 卸载旧版

```bash
# 先清掉可能存在的旧版和冲突包
sudo apt-get remove -y docker docker-engine docker.io containerd runc 2>/dev/null
sudo apt-get purge -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin 2>/dev/null
```

> **注意**：`purge` 会删 `/var/lib/docker`，如果机器上已有容器数据，先备份。

### 1.2 装依赖 + 加 GPG key

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL --retry 3 --max-time 60 https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor --yes -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
```

### 1.3 加软件源

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
```

### 1.4 装 Docker + Compose 插件

```bash
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
                        docker-buildx-plugin docker-compose-plugin

# 验证
docker --version
docker compose version      # v2，注意是子命令不是连字符
```

> 🚨 **关键区别**：`docker-compose`（连字符）= v1，Python 实现，**已停止维护**；`docker compose`（空格）= v2，Go 实现，插件形式。
> **v1.29.2 有 `KeyError: 'ContainerConfig'` 的严重 bug——会删容器但不建新的。** 一律用 v2。

### 1.5 非 root 用户免 sudo

```bash
sudo groupadd docker 2>/dev/null
sudo usermod -aG docker $USER

# 需要重新登录（或 newgrp docker）才生效
newgrp docker

# 验证
docker ps
```

## 二、CentOS / RHEL / 国产发行版

```bash
# 装依赖
sudo yum install -y yum-utils device-mapper-persistent-data lvm2

# 加源（国内用阿里云镜像）
sudo yum-config-manager --add-repo \
  https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

# 装
sudo yum install -y docker-ce docker-ce-cli containerd.io \
                    docker-buildx-plugin docker-compose-plugin

sudo systemctl enable --now docker
docker --version
```

> 国产发行版（OpenCloudOS / 麒麟 / 统信）通常兼容 CentOS 源。如果 `$releasever` 解析失败，把 repo 文件里的 `$releasever` 手动替换成 `9` 或 `8`。

## 三、国内镜像源配置（必做）

### 3.1 为什么必做

```
docker pull hello-world → 卡住 → 报错
```

**根因**：
- Docker 官方 registry（`registry-1.docker.io`）在国内访问不稳
- 拉镜像的流程是：先请求 `auth.docker.io` 拿 token → 再请求 registry 拉层
- **很多"镜像加速器"只代理 registry，不代理 auth.docker.io** → 认证阶段必然失败

### 3.2 配置 registry-mirrors

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://dockerproxy.net",
    "https://mirror.ccs.tencentyun.com"
  ],
  "insecure-registries": [],
  "features": {
    "buildkit": false
  }
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker

# 验证
docker info | grep -A 5 "Registry Mirrors"
```

> **`buildkit: false` 的原因**：Docker 29 的 buildkitd 会话健康检查有 bug，长时间构建（>30 分钟）会在 `exporting layers` 阶段"假死"，同时 GC 把已构建的层全回收掉。大镜像构建一律关掉 BuildKit，或单次用 `DOCKER_BUILDKIT=0 docker build`。

### 3.3 可用镜像源速查

| 源 | 可用性 | 备注 |
|:--|:--|:--|
| `mirror.ccs.tencentyun.com` | ✅ 腾讯云内网 | 只在腾讯云机器上有效 |
| `docker.1ms.run` | ✅ 社区维护 | 通用性较好 |
| `docker.xuanyuan.me` | ✅ 社区维护 | — |
| `dockerproxy.net` | ⚠️ 时好时坏 | — |
| `docker.mirrors.ustc.edu.cn` | ❌ 已停 | 中科大已关闭公共服务 |
| `hub-mirror.c.163.com` | ❌ 已停 | 网易已关闭 |

> 镜像源是消耗品，**失效很快**。配多个让 Docker 自动 failover，别只配一个。

### 3.4 私有仓库认证

```bash
# 登录（会写进 ~/.docker/config.json）
docker login registry.cn-hangzhou.aliyuncs.com -u <用户名>

# 注意：密码用「仓库独立密码」，不是阿里云账号密码
```

## 四、验证安装

```bash
# 1. 版本
docker --version
docker compose version

# 2. 服务状态
systemctl status docker --no-pager

# 3. 跑个容器
docker run --rm hello-world

# 4. GPU（如果有卡）
nvidia-smi && docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi

# 5. 磁盘占用
docker system df
```

## 五、Portainer（Web 图形管理）

```bash
# 持久化卷
docker volume create portainer_data

# 启动（9443 = HTTPS 管理端口，8000 = Edge agent）
docker run -d \
  --name portainer \
  --restart=unless-stopped \
  -p 8000:8000 \
  -p 9443:9443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portainer_data:/data \
  portainer/portainer-ce:latest
```

访问 `https://<IP>:9443`，首次进入设管理员密码。

> 🔴 **安全提醒**：`/var/run/docker.sock` 挂进容器 = 把 root 权限交出去。**Portainer 只能在内网或加 TLS + 认证后对外**，绝不要裸奔在公网。

## 六、数据目录迁移

默认数据在 `/var/lib/docker`，系统盘小的时候必须迁走。

```bash
# 1. 停服务
sudo systemctl stop docker

# 2. 迁移（用 rsync 保留权限）
sudo rsync -aP /var/lib/docker/ /data/docker/

# 3. 改配置
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "data-root": "/data/docker",
  "registry-mirrors": ["https://docker.1ms.run"]
}
EOF

# 4. 重启并验证
sudo systemctl daemon-reload
sudo systemctl start docker
docker info | grep "Docker Root Dir"

# 5. 确认没问题后再删旧的
# sudo rm -rf /var/lib/docker
```

> ⚠️ 顺序很重要：**先 rsync 再改配置**。直接改配置然后重启，Docker 会以为目录是空的，你的镜像和容器全"消失"（其实还在旧目录）。

## 七、常见报错排查

| 报错 | 原因 | 解法 |
|:--|:--|:--|
| `permission denied ... docker.sock` | 用户不在 docker 组 | `usermod -aG docker $USER` + 重新登录 |
| `Cannot connect to the Docker daemon` | 服务没起 | `systemctl start docker` |
| `pull access denied / timeout` | 镜像源没配或全失效 | 换源，多配几个 |
| `Error response from daemon: Get ... dial tcp ... i/o timeout` | 到 registry 网络不通 | 配 registry-mirrors |
| `KeyError: 'ContainerConfig'` | 用了 docker-compose v1 | 换 `docker compose`（v2）|
| `Unknown runtime specified nvidia` | daemon.json 没配 runtimes | 见 NVIDIA 篇 |
| `exporting layers` 卡死 | BuildKit bug | `DOCKER_BUILDKIT=0` |
| `no space left on device` | 系统盘满 | 迁 data-root 或 `docker system prune` |

### 清理空间

```bash
# 看占用
docker system df -v

# 清未使用的镜像/容器/网络（不动 volume）
docker system prune -a

# 连 volume 一起清（危险，会删数据）
docker system prune -a --volumes

# 只清悬空镜像
docker image prune
```

## 八、生产环境加固清单

| 项 | 做法 |
|:--|:--|
| 不用 root 跑容器 | Dockerfile 里 `USER nonroot` |
| 限制资源 | `--memory` `--cpus` `--pids-limit` |
| 只读根文件系统 | `--read-only --tmpfs /tmp` |
| 禁特权 | 不用 `--privileged`，按需 `--cap-add` |
| 日志限额 | daemon.json 配 `log-opts: max-size=100m, max-file=3` |
| 关掉默认 bridge 的容器互联 | `--icc=false`（老版本）或自定义网络 |
| 定期扫镜像 | `trivy image <镜像>` |

**日志限额配置示例**（不做这条，日志能把磁盘撑爆）：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
```

## 九、一句话总结

> **装 Docker 只有两个关键决策：用官方源还是发行版源（要新特性就官方源），配不配国内镜像源（不配基本废）。**
> 剩下的坑集中在三处：`docker compose` v1 的 `ContainerConfig` bug、BuildKit 长构建假死、data-root 迁移的顺序。
