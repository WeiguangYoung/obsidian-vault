# 安全扫描 · 工具服务 · Fuzz 测试 实现方案

> 汽车嵌入式 CI/CD 流水线中三类关键服务的详细实现，以及 Jenkins Pipeline 接入方式。

---

## 一、总体流程

```
代码提交 → Jenkins Pipeline 触发
    ├── 阶段1：安全扫描（7项并行）
    ├── 阶段2：Fuzz 测试（并行执行）
    ├── 阶段3：工具服务（打 tag / 通知 / XSAN 同步 / Nmap）
    └── 阶段4：结果汇总 → 邮件通知
```

## 二、安全扫描（14 台 Worker，7 项 ×2）

### 2.1 敏感信息扫描

**功能：** 扫描代码仓库中的硬编码密码、API Key、Token、私钥、证书等敏感信息。

**实现方案：**

```
工具：Gitleaks + 自定义正则规则集
输入：Git 仓库（指定分支/commit range）
输出：JSON 报告 → SFS Turbo /reports/secrets/
```

**自定义规则（汽车嵌入式场景）：**
- ECU 调试密码（常见格式：`debug_pwd=xxx`）
- CAN 总线密钥
- 车载网络凭证（WiFi SSID/PSK）
- OTA 签名私钥
- 供应商 FTP/SFTP 密码

**Docker 化：**

```dockerfile
FROM golang:1.22-alpine AS build
RUN go install github.com/gitleaks/gitleaks/v8@latest

FROM alpine:3.20
COPY --from=build /go/bin/gitleaks /usr/local/bin/
COPY rules/automotive.toml /etc/gitleaks/
COPY entrypoint.sh /
RUN chmod +x /entrypoint.sh
ENTRYPOINT ["/entrypoint.sh"]
```

**entrypoint.sh：**

```bash
#!/bin/sh
REPO_DIR=${1:-/workspace}
BRANCH=${2:-HEAD}
OUTPUT=/reports/secrets/gitleaks-$(date +%Y%m%d%H%M%S).json

gitleaks detect \
  --source "$REPO_DIR" \
  --config /etc/gitleaks/automotive.toml \
  --report-format json \
  --report-path "$OUTPUT" \
  --verbose

# 解析结果，有泄漏返回 exit 1
# gitleaks --report-format json 输出是数组 [...]
LEAKS=$(jq 'length' "$OUTPUT" 2>/dev/null || echo 0)
if [ "$LEAKS" -gt 0 ]; then
  echo "❌ 发现 $LEAKS 条敏感信息泄漏"
  exit 1
fi
echo "✅ 未发现敏感信息"
exit 0
```

**检查项：**
| 检查项 | 规则 |
|:------|:------|
| NOPASSWD 滥用 | 禁止 `ALL=(ALL) NOPASSWD:ALL` |
| 通配符过多 | 禁止 `*` 在命令路径中使用 |
| env_reset | 必须启用 |
| Defaults 安全选项 | 检查 `env_reset`、`mail_badpass`、`secure_path` |
| 免密命令白名单 | 列出所有 NOPASSWD 项供审核 |

### 2.3 加密算法检测

**功能：** 扫描二进制/C 代码中使用的加密算法，检测弱算法。

**实现方案：**

```
工具：自定义 regex + checksec + 二进制分析
输入：源码目录 + 编译产物（.elf / .bin）
输出：加密算法使用清单 → SFS Turbo
```

**检测范围：**

| 类型 | 检测内容 | 工具 |
|:----|:------|:------|
| 源码级 | `#include <openssl/md5.h>`、DES、RC4 等 | grep + 正则 |
| 二进制级 | 静态分析 ELF/二进制中的加密符号 | strings + 符号表 |
| 编译选项 | checksec 检查 PIE/RELRO/Stack Canary | checksec |
| 弱随机数 | `rand()`、`srand()` 调用 | cppcheck / grep |

**Docker 化脚本：**

```bash
#!/bin/bash
SOURCE_DIR=$1
BINARY_DIR=$2
OUTPUT=/reports/crypto/report-$(date +%Y%m%d%H%M%S).json

echo "{" > $OUTPUT
echo '"weak_algorithms":' >> $OUTPUT

# 源码级检测
grep -rIn -E "MD5_Init|DES_|RC4_|SHA1_Init" $SOURCE_DIR --include="*.c" --include="*.h" \
  | jq -R -s 'split("\n") | map(select(length>0))' >> $OUTPUT

echo ', "missing_mitigations":' >> $OUTPUT
# checksec 检查
for f in $BINARY_DIR/*.elf; do
  checksec --file=$f --format=json
done | jq -s '.' >> $OUTPUT

echo "}" >> $OUTPUT
```

### 2.5 开放端口扫描

**功能：** 扫描构建产物/目标设备中开放的端口和服务。

**实现方案：**

```
工具：Nmap
目标：构建产物中的网络配置文件 + 实际目标 IP 列表
输出：端口扫描报告 → SFS Turbo
```

**扫描策略：**

```bash
#!/bin/bash
TARGET=$1
OUTPUT=/reports/ports/nmap-$(date +%Y%m%d%H%M%S).xml

nmap -sV -sC -p- \
  --script=vuln \
  -oX "$OUTPUT" \
  "$TARGET"

# 导出为 Jenkins 可读的 JSON
nmap-parse-output "$OUTPUT" json > "${OUTPUT%.xml}.json"
```

**针对汽车嵌入式的特殊端口：**

| 端口 | 关注点 |
|:---:|:------|
| 23/tcp | Telnet（不应存在） |
| 21/tcp | FTP（若存在需加密） |
| 502/tcp | Modbus（工业总线安全） |
| 20000/udp | DDS 发现协议 |
| 11898/tcp | SOME/IP 协议 |

### 2.6 二进制安全扫描

**功能：** ELF / 二进制文件危险函数检测、符号分析、安全属性。

**实现方案：**

```
工具：checksec + radare2 + 自定义 python
输入：编译产物（.elf / .so / .bin）
输出：安全分析报告 → SFS Turbo
```

**检测项：**

| 检测项 | 工具 | 说明 |
|:------|:-----|:------|
| 危险函数 | objdump -T | `strcpy`, `sprintf`, `gets`, `scanf`, `system` |
| 安全编译选项 | checksec | NX/Canary/RELRO/PIE/Fortify |
| 符号泄露 | nm/readelf | 不应导出内部符号 |
| SUID 二进制 | find -perm | 检查不当 SUID |
| 硬编码路径 | strings | `/tmp/`, `/etc/shadow` 等 |
| RWX 段 | readelf -l | 不应有可写可执行段 |

```bash
#!/bin/bash
BINARY=$1
OUTPUT=/reports/binary/report-$(basename $BINARY)-$(date +%Y%m%d%H%M%S).json

cat > "$OUTPUT" << EOF
{
  "file": "$(basename $BINARY)",
  "checksec": $(checksec --file=$BINARY --format=json),
  "dangerous_functions": $(objdump -T $BINARY 2>/dev/null | grep -E 'strcpy|sprintf|gets|system|scanf' | awk '{print $NF}' | jq -R -s 'split("\n") | map(select(length>0))'),
  "rwx_segments": $(readelf -lW $BINARY 2>/dev/null | grep 'RWE' | jq -R -s 'split("\n") | map(select(length>0))'),
  "hardcoded_strings": $(strings $BINARY | grep -E '/tmp/|password|secret|/etc/' | head -20 | jq -R -s 'split("\n") | map(select(length>0))')
}
EOF
```

### 2.7 病毒扫描

**功能：** 扫描编译产物、依赖库、第三方组件中的已知恶意软件。

**实现方案：**

```
工具：ClamAV
输入：编译产物目录 + 第三方库路径
输出：病毒扫描报告 → SFS Turbo
```

**Docker 化：**

```dockerfile
FROM clamav/clamav:1.3
COPY scan.sh /
RUN chmod +x /scan.sh
ENTRYPOINT ["/scan.sh"]
```

```bash
#!/bin/sh
SCAN_DIR=${1:-/workspace}
OUTPUT=/reports/virus/clamav-$(date +%Y%m%d%H%M%S).txt

# 更新病毒库
freshclam --no-dns

# 扫描
clamscan -r --bell -i \
  --max-filesize=100M \
  --max-scansize=100M \
  "$SCAN_DIR" > "$OUTPUT" 2>&1

# 有病毒返回 exit 1
grep -q "Infected files: 0" "$OUTPUT" || exit 1
```

## 三、工具服务（8 台 Worker）

### 3.1 自动打 tag

**功能：** 构建成功后自动生成 Git tag、Release Note、changelog。

**实现方案：**

```
工具：conventional-changelog + git
触发：构建通过后
```

```bash
#!/bin/bash
REPO_DIR=$1

cd "$REPO_DIR"
# 根据 commit message 自动推断版本号
NEW_VERSION=$(npx conventional-recommended-bump -p angular 2>/dev/null || echo "patch")

# 生成 changelog
npx conventional-changelog -p angular -i CHANGELOG.md -s -r 0

# 打 tag
git config user.email "cicd@automotive.internal"
git config user.name "CI/CD Bot"
git tag -a "v${NEW_VERSION}" -m "Release v${NEW_VERSION} [skip ci]"
git push origin "v${NEW_VERSION}"
git push origin HEAD:main

echo "{\"version\":\"v${NEW_VERSION}\",\"time\":\"$(date -Iseconds)\"}"
```

### 3.3 XSAN

**功能：** XSAN 是汽车行业的跨节点文件同步/共享存储系统，提供多机文件同步与高可用访问。

**实现方案：**

```
工具：XSAN 客户端（汽车行业专用分布式同步工具）
用途：构建产物同步到共享存储、跨站点分发
```

```bash
#!/bin/bash
SOURCE=${1:-/workspace/build}
DEST=${2:-/xsan/releases/}

# 调用 XSAN 同步客户端，将构建产物同步到共享存储
xsync -avz --progress --checksum "$SOURCE/" "$DEST/"
echo "{\"source\":\"$SOURCE\",\"dest\":\"$DEST\",\"status\":\"ok\",\"time\":\"$(date -Iseconds)\"}"
```

### 3.4 Nmap（网络扫描工具服务）

**功能：** 不同于安全扫描中的端口扫描（针对构建产物），这里是作为**网络发现和资产扫描服务**，定期扫描内网存活主机和拓扑。

**实现方案：**

```
工具：Nmap + ndiff
模式：定期巡检（CronJob）
输出：网络拓扑变化报告 → SFS Turbo
```

```bash
#!/bin/bash
PREV_SCAN=/data/nmap/previous.xml
CURR_SCAN=/data/nmap/current-$(date +%Y%m%d).xml

nmap -sn 192.168.0.0/16 -oX "$CURR_SCAN"

if [ -f "$PREV_SCAN" ]; then
  ndiff "$PREV_SCAN" "$CURR_SCAN" > /data/nmap/diff-$(date +%Y%m%d).txt
fi

mv "$CURR_SCAN" "$PREV_SCAN"
```

## 四、Fuzz 测试（8 台 Worker）

### 4.1 dtfuzz（6 台）

**功能：** 针对汽车通信协议的模糊测试（DDS / SOME/IP / CAN / UDS 等）。

**实现架构：**

```
工具：dtfuzz（汽车行业专用协议模糊测试器，基于 libFuzzer/AFL++ 封装）
输入：协议模型文件 (.json/.yaml)、种子语料
输出：Crash 样本、覆盖率报告、变异日志
```

**运行模型：**

```yaml
# dtfuzz-config.yaml
protocol: DDS
interface: veth_fuzz0
target_ip: 172.20.0.100
port: 7400
seed_dir: /corpus/dds/
timeout: 10800  # 3小时
max_crashes: 10
cov_report: true
asan_enabled: true
```

**Docker 化：**

```dockerfile
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y \
  build-essential clang libasan6 \
  python3 python3-pip netcat-openbsd
COPY dtfuzz /usr/local/bin/
COPY entrypoint.sh /
RUN chmod +x /entrypoint.sh
ENTRYPOINT ["/entrypoint.sh"]
```

**入口脚本：**

```bash
#!/bin/bash
CONFIG=${1:-/config/dtfuzz-config.yaml}
OUTPUT=/reports/fuzz/dtfuzz-$(date +%Y%m%d%H%M%S)
mkdir -p "$OUTPUT"

timeout 3h dtfuzz \
  --config "$CONFIG" \
  --output "$OUTPUT" \
  --crash-dir "$OUTPUT/crashes" \
  --coverage "$OUTPUT/coverage"

# 统计
echo "{\"crashes\":$(ls $OUTPUT/crashes/ 2>/dev/null | wc -l),\"execs\":\"$(grep execs $OUTPUT/stats.log | tail -1)\"}"
```

### 4.2 c-spider（2 台）

**功能：** C/C++ 覆盖率引导的模糊测试（基于 AFL++ 封装）。

**实现架构：**

```
工具：c-spider（汽车行业专用 C/C++ 覆盖率引导模糊测试器，AFL++ 封装）
模式：覆盖率引导变异
输入：被测二进制（插桩编译）+ 初始种子
输出：Crash、覆盖率、变异路径
```

**工作原理：**

```
                     ┌─────────────────┐
  初始种子 ──────────→│ 变异引擎        │
  (合法输入)          │ havoc/splice    │
                     └──────┬──────────┘
                            ↓
                     ┌─────────────────┐
                     │ 被测二进制      │
                     │ (asan+coverage) │
                     └──────┬──────────┘
                            ↓
              ┌─────────────┴─────────────┐
              ↓                           ↓
         Crash！ → 保存输入            新覆盖 → 加入种子队列
```

**编译要求（被测目标）：**

```bash
# 用 AFL++ 插桩编译
CC=afl-clang-fast CXX=afl-clang-fast++ cmake ..
AFL_USE_ASAN=1 make -j$(nproc)
```

**运行：**

```bash
#!/bin/bash
TARGET_BIN=$1
SEED_DIR=${2:-/corpus/c-spider}
OUTPUT=/reports/fuzz/cspider-$(date +%Y%m%d%H%M%S)

c-spider \
  -i "$SEED_DIR" \
  -o "$OUTPUT" \
  -m none \
  -t 5000+ \
  -- "$TARGET_BIN" @@

echo "{\"output\":\"$OUTPUT\",\"crashes\":\"$(ls $OUTPUT/crashes/ 2>/dev/null | wc -l)\"}"
```

## 五、Jenkins 接入方案

### 5.1 总体 Pipeline 架构

```
Jenkins (裸机) ── Kubernetes Plugin ──→ CCE 集群
  │                                        │
  │  动态创建 Pod                           ├── ns: security-scan
  │  nodeSelector 绑定                      ├── ns: fuzz-test
  │  toleration 穿透污点                     └── ns: tools
```

### 5.2 Jenkins Kubernetes Plugin 配置

```groovy
// Jenkinsfile - 主流水线
pipeline {
  agent none

  parameters {
    string(name: 'REPO_URL', description: '代码仓库')
    string(name: 'BRANCH', defaultValue: 'develop', description: '分支')
    string(name: 'BINARY_PATH', description: '编译产物路径')
  }

  environment {
    SFS_TURBO = '/sfs-turbo'
    REPORTS = "${SFS_TURBO}/reports/${BUILD_NUMBER}"
  }

  stages {

    // ===== 阶段1: 安全扫描（7项并行） =====
    stage('安全扫描') {
      parallel {
        stage('敏感信息扫描') {
          agent {
            kubernetes {
              label 'gitleaks-pod'
              yaml """
                spec:
                  nodeSelector:
                    workload: security-scan
                  tolerations:
                  - key: workload
                    operator: Equal
                    value: security-scan
                    effect: NoSchedule
                  containers:
                  - name: gitleaks
                    image: swr.cn-east-3.myhuaweicloud.com/automotive/gitleaks:latest
                    command: ["/bin/sh", "-c"]
                    args: ["gitleaks detect --source /workspace --report-format json --report-path /reports/gitleaks.json"]
                    volumeMounts:
                    - {name: workspace, mountPath: /workspace}
                    - {name: reports, mountPath: /reports}
                  volumes:
                  - {name: workspace, persistentVolumeClaim: {claimName: workspace-pvc}}
                  - {name: reports, persistentVolumeClaim: {claimName: sfs-turbo-reports}}
              """
            }
          }
          steps {
            echo "Gitleaks scan started"
          }
        }

        stage('sudo配置检查') {
          agent { label 'security-scan' }
          steps {
            container('sudo-check') {
              sh "sudo-check /etc/sudoers ${REPORTS}/sudo.json"
            }
          }
        }

        stage('加密算法检测') {
          agent { label 'security-scan' }
          steps {
            container('crypto-check') {
              sh "crypto-check ${WORKSPACE} ${params.BINARY_PATH} ${REPORTS}/crypto.json"
            }
          }
        }

        stage('资料安全扫描') {
          agent { label 'security-scan' }
          steps {
            container('doc-scan') {
              sh "doc-scan ${WORKSPACE}/docs ${REPORTS}/docs.json"
            }
          }
        }

        stage('开放端口扫描') {
          agent { label 'security-scan' }
          steps {
            container('port-scan') {
              sh "port-scan ${TARGET_IP} ${REPORTS}/ports/"
            }
          }
        }

        stage('二进制安全扫描') {
          agent { label 'security-scan' }
          steps {
            container('binary-scan') {
              sh """
                for f in ${params.BINARY_PATH}/*.elf; do
                  binary-scan \$f ${REPORTS}/binary/
                done
              """
            }
          }
        }

        stage('病毒扫描') {
          agent { label 'security-scan' }
          steps {
            container('clamav') {
              sh "clamscan -r --bell -i ${WORKSPACE} > ${REPORTS}/clamav.txt"
            }
          }
        }
      }
    }

    // ===== 阶段2: Fuzz测试 =====
    stage('Fuzz测试') {
      parallel {
        stage('dtfuzz') {
          agent { label 'fuzz-test' }
          steps {
            container('dtfuzz') {
              sh "dtfuzz --config /config/dds.yaml --output ${REPORTS}/dtfuzz/"
            }
          }
        }

        stage('c-spider') {
          agent { label 'fuzz-test' }
          steps {
            container('c-spider') {
              sh "c-spider -i /corpus/ -o ${REPORTS}/c-spider/ -- ${params.BINARY_PATH}/target.elf @@"
            }
          }
        }
      }
    }

    // ===== 阶段3: 结果汇总 =====
    stage('结果汇总') {
      agent { label 'tools' }
      steps {
        container('report-gen') {
          sh """
            python3 /scripts/generate-report.py \
              --reports-dir ${REPORTS} \
              --output ${REPORTS}/summary.html
          """
        }
      }
    }

    // ===== 阶段4: 打Tag & 通知 =====
    stage('打Tag') {
      when { expression { currentBuild.result == 'SUCCESS' } }
      agent { label 'tools' }
      steps {
        container('auto-tag') {
          sh "auto-tag ${WORKSPACE}"
        }
      }
    }

  }

  post {
    always {
      container('mail') {
        sh "notify ${currentBuild.result} ${REPORTS}/summary.html"
      }
    }
    failure {
      container('mail') {
        sh "notify-failure '${currentBuild.result}' '${env.BUILD_URL}'"
      }
    }
  }
}
```

### 5.3 Pod Template 配置

```yaml
# Jenkins → Manage → Clouds → Kubernetes → Pod Templates
# label 必须与 Jenkinsfile 中 agent { label 'xxx' } 一致

- name: security-scan  # 对应 Jenkinsfile agent { label 'security-scan' }

  yaml: |
    spec:
      nodeSelector:
        workload: security-scan
      tolerations:
      - key: workload
        operator: Equal
        value: security-scan
        effect: NoSchedule
      containers:
      - name: jnlp
        image: jenkins/inbound-agent:latest

- name: fuzz-test
  label: fuzz-test
  namespace: fuzz-test
  yaml: |
    spec:
      nodeSelector:
```

## 六、镜像与部署

所有工具 Docker 化，推送到华为云 SWR：

```bash
# 构建示例
docker build -t swr.cn-east-3.myhuaweicloud.com/automotive/gitleaks:latest .
docker push swr.cn-east-3.myhuaweicloud.com/automotive/gitleaks:latest

# K8s 部署（非 Jenkins 场景）
kubectl -n security-scan apply -f - <<EOF
apiVersion: batch/v1
kind: Job
metadata:
  name: gitleaks-scan
spec:
  template:
    spec:
      nodeSelector:
        workload: security-scan
      tolerations:
      - key: workload
        operator: Equal
        value: security-scan
        effect: NoSchedule
      containers:
      - name: gitleaks
        image: swr.cn-east-3.myhuaweicloud.com/automotive/gitleaks:latest
        command: ["/bin/sh", "-c"]
        args: ["gitleaks detect --source /workspace --report-format json --report-path /reports/gitleaks.json"]
        volumeMounts:
        - name: workspace
          mountPath: /workspace
        - name: reports
          mountPath: /reports
      volumes:
      - name: workspace
        persistentVolumeClaim:
          claimName: workspace-pvc
      - name: reports
        persistentVolumeClaim:
          claimName: sfs-turbo-reports
      restartPolicy: Never
EOF
```
