## 一、汽车 vs 机器人：关键差异与复用策略

两个行业的 CI/CD 骨架高度相似（都是嵌入式 + 交叉编译 + 硬件测试），差异集中在**产物形态**、**合规强度**、**测试手段**三处：

| 维度 | 汽车 | 机器人 |
|:----|:----|:----|
| **通信** | CAN/LIN/车载以太网，信号导向 + SOME/IP | DDS 主导，服务/话题导向 |
| **构建** | CMake/Bazel + AUTOSAR 生成器 | colcon + ament_cmake |
| **产物** | .hex/.bin/S19 + 刷写包 | Docker 镜像 + .deb + 模型权重 |
| **升级** | OTA（SOTA/FOTA、双分区回滚、验签） | 边缘 OTA、容器滚动更新 |
| **合规** | ASPICE、ISO 26262、ISO 21434（硬性取证） | 多为功能/安全标准（如 ISO 10218 机械安全） |
| **测试** | HIL/SIL、CANoe 总线仿真 | SIL（Gazebo/Isaac）、rosbag 回放、HIL |
| **实时性** | 强实时、确定性（TSN） | 软实时为主，感知链路允许抖动 |

**可复用的通用能力（不用重复学）：**

1. **构建基础设施** —— Docker 化工具链、ccache、Ninja、产物归档
2. **质量门禁** —— 静态分析、单元测试、覆盖率、SBOM
3. **制品与版本** —— 语义化版本、制品库、可追溯性
4. **可观测性** —— 日志/指标/告警体系
5. **签名与验签** —— 镜像签名链路（见 CMake 实战文档的 post-build 签名）

**需要按行业补的差异能力：**

- 汽车：总线诊断工具链、ASPICE 流程文档、功能安全分析（FMEA/FTA）
- 机器人：仿真环境搭建、QoS 调优、多机编排、模型权重版本管理
