# 06 · 打包安装篇（installer）

> 路径：`06-installer/deb/`
> 目标：把构建产物打成可分发、可安装的系统包（`.deb`）。

## 二、CMakeLists.txt 全文

```cmake
cmake_minimum_required(VERSION 3.5)
project(cmake_examples_deb)

# 设置版本号
set(deb_example_VERSION_MAJOR 0)
set(deb_example_VERSION_MINOR 2)
set(deb_example_VERSION_PATCH 2)
set(deb_example_VERSION
    "${deb_example_VERSION_MAJOR}.${deb_example_VERSION_MINOR}.${deb_example_VERSION_PATCH}")

############################################################
# 构建部分
############################################################

add_library(cmake_examples_deb SHARED src/Hello.cpp)

target_include_directories(cmake_examples_deb
    PUBLIC ${PROJECT_SOURCE_DIR}/include
)

add_executable(cmake_examples_deb_bin src/main.cpp)

target_link_libraries(cmake_examples_deb_bin
    PUBLIC cmake_examples_deb
)

############################################################
# 安装部分
############################################################

# 可执行文件
install(TARGETS cmake_examples_deb_bin
    DESTINATION bin)

# 动态库
install(TARGETS cmake_examples_deb
    LIBRARY DESTINATION lib)

# 配置文件
install(FILES cmake-examples.conf
    DESTINATION etc)

############################################################
# 打 DEB 包
############################################################

set(CPACK_GENERATOR "DEB")

# 维护者信息（DEB 必需，缺失会打包失败）
set(CPACK_DEBIAN_PACKAGE_MAINTAINER "Thom Troy")

set(CPACK_PACKAGE_VERSION ${deb_example_VERSION})

include(CPack)
```

## 三、CPack 工作原理

```
CMakeLists.txt
     │
     │ configure
     ▼
build/CPackConfig.cmake      ← include(CPack) 生成
     │
     │ cpack / make package
     ▼
cmake_examples_deb-0.2.2-Linux.deb
```

`include(CPack)` 会在构建目录生成 `CPackConfig.cmake`，并挂上两个 target：

| target | 作用 |
|:--|:--|
| `package` | 生成安装包 |
| `package_source` | 生成源码包（`.tar.gz` 等） |

`install()` 规则同时被两条路径消费：

- `make install` → 装到 `CMAKE_INSTALL_PREFIX`
- `make package` → 按同样的目录结构打进包里

> **关键认知：CPack 不重新定义文件布局，它直接复用 `install()` 规则。** 所以「能正确 `make install`」是「能正确打包」的前提。

## 四、构建与打包

```bash
mkdir build && cd build
cmake ..
make
cpack                    # 或 make package
```

产物：

```
build/
├── cmake_examples_deb-0.2.2-Linux.deb
├── cmake_examples_deb_bin
└── libcmake_examples_deb.so
```

### 检查包内容

```bash
dpkg -c cmake_examples_deb-0.2.2-Linux.deb
```

输出大致如下：

```
./usr/bin/cmake_examples_deb_bin
./usr/lib/libcmake_examples_deb.so
./usr/etc/cmake-examples.conf
```

### 安装 / 卸载

```bash
sudo dpkg -i cmake_examples_deb-0.2.2-Linux.deb
sudo dpkg -r cmake-examples-deb      # 或 apt remove
```

## 五、CPack 常用变量

### 5.1 通用变量

```cmake
set(CPACK_PACKAGE_NAME          "cmake-examples")       # 包名（默认 = PROJECT_NAME）
set(CPACK_PACKAGE_VERSION       "0.2.2")                # 版本
set(CPACK_PACKAGE_DESCRIPTION   "CMake example package")# 描述
set(CPACK_PACKAGE_CONTACT       "dev@example.com")      # 联系方式
set(CPACK_PACKAGE_VENDOR        "Example Inc.")         # 供应商
set(CPACK_RESOURCE_FILE_LICENSE "${CMAKE_SOURCE_DIR}/LICENSE")
set(CPACK_PACKAGE_INSTALL_DIRECTORY "cmake-examples")   # Windows 安装目录
set(CPACK_PACKAGE_FILE_NAME
    "${CPACK_PACKAGE_NAME}-${CPACK_PACKAGE_VERSION}-${CMAKE_SYSTEM_NAME}")
```

> 现代 CMake（3.12+）可以用 `project(... VERSION 1.2.3)` 自动填充 `CPACK_PACKAGE_VERSION`，不必手写三段版本号。

### 5.2 DEB 专有变量

```cmake
set(CPACK_GENERATOR "DEB")

# 必需：维护者
set(CPACK_DEBIAN_PACKAGE_MAINTAINER "Your Name <you@example.com>")

# 推荐：架构与依赖
set(CPACK_DEBIAN_PACKAGE_ARCHITECTURE "amd64")
set(CPACK_DEBIAN_PACKAGE_DEPENDS "libc6 (>= 2.27), libstdc++6")

# 可选：分区、优先级、包段
set(CPACK_DEBIAN_PACKAGE_SECTION   "devel")
set(CPACK_DEBIAN_PACKAGE_PRIORITY  "optional")
set(CPACK_DEBIAN_FILE_NAME DEB-DEFAULT)   # 标准命名
```

### 5.3 多生成器

```cmake
set(CPACK_GENERATOR "DEB;RPM;TGZ")
```

一次 `cpack` 产出三份，前提是系统装有 `dpkg-deb` / `rpmbuild`。

| 生成器 | 产物 | 依赖工具 |
|:--|:--|:--|
| `DEB` | `.deb` | `dpkg-deb` |
| `RPM` | `.rpm` | `rpmbuild` |
| `TGZ` / `TXZ` | 压缩包 | — |
| `NSIS` | Windows 安装程序 | NSIS |
| `WIX` | `.msi` | WiX |
| `IFW` | Qt Installer | Qt |

## 六、进阶：组件化打包

把库、工具、文档拆成独立包：

```cmake
install(TARGETS mylib
    LIBRARY DESTINATION lib
    COMPONENT libraries)

install(TARGETS mytool
    RUNTIME DESTINATION bin
    COMPONENT applications)

install(DIRECTORY doc/
    DESTINATION share/doc
    COMPONENT documentation)

set(CPACK_DEB_COMPONENT_INSTALL ON)
set(CPACK_COMPONENTS_ALL libraries applications documentation)
include(CPack)
```

产物变成 `mylib.deb` / `mytool.deb` / `mydoc.deb` 三个包，部署时可以按需安装。

## 七、进阶：安装后脚本

```cmake
# 安装后执行的脚本
set(CPACK_DEBIAN_PACKAGE_CONTROL_EXTRA
    "${CMAKE_SOURCE_DIR}/debian/postinst;"
    "${CMAKE_SOURCE_DIR}/debian/prerm")
```

| 脚本 | 触发时机 |
|:--|:--|
| `preinst` | 安装前 |
| `postinst` | 安装后（`dpkg -i` 完成时） |
| `prerm` | 卸载前 |
| `postrm` | 卸载后 |

典型用途：`postinst` 里 `ldconfig`、创建用户、初始化配置文件。

## 八、嵌入式场景怎么用

嵌入式固件**不需要装到系统目录**，所以 `install()` 在嵌入式项目里通常被换成 `POST_BUILD` 拷贝：

```cmake
add_custom_command(TARGET app POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O binary $<TARGET_FILE:app> ${CMAKE_BINARY_DIR}/app.bin
    COMMAND ${CMAKE_OBJCOPY} -O ihex   $<TARGET_FILE:app> ${CMAKE_BINARY_DIR}/app.hex
    COMMAND ${CMAKE_SIZE} $<TARGET_FILE:app> > ${CMAKE_BINARY_DIR}/app.size
    COMMENT "Generating bin/hex/size"
)
```

| 场景 | 用什么 |
|:--|:--|
| 产品固件 | `POST_BUILD` → `.bin` / `.hex` |
| 发布给客户的 SDK | `install()` + CPack 打 `.deb` / `.tar.gz` |
| 开发机工具链 | `install()` + 打包 |
| 车载 Linux 应用 | CPack 打 `.deb`，走 OTA 分发 |

> 所以：**「嵌入式不用 CPack」是个误解**。固件本身不用，但配套的 SDK、配置工具、宿主端调试工具都要打包。

## 九、常见坑

| 现象 | 原因 | 解决 |
|:--|:--|:--|
| `cpack` 报 maintainer 为空 | DEB 必需 `CPACK_DEBIAN_PACKAGE_MAINTAINER` | 补上 |
| 包里路径是 `./usr/...` 而非 `/usr/...` | 正常现象，解包后才是绝对路径 | 无需处理 |
| `dpkg -i` 报依赖缺失 | 没声明 `CPACK_DEBIAN_PACKAGE_DEPENDS` | 补依赖 |
| 包名带大写 | DEB 包名要求小写 | 设 `CPACK_PACKAGE_NAME` 为小写 |
| 打出的包缺文件 | `install()` 里漏了 | `dpkg -c` 核对 |
| 改了 install 规则但包没变 | 没重新 `cmake` | 重新配置再 `cpack` |
| 库装到 `lib` 但系统找不到 | 没跑 `ldconfig` | `postinst` 里加 |
