# 📘 STM32F407 手册与核心板详解

> 三件事：**查手册该翻哪本**、**芯路城 STM32F407VGT6-Mini 怎么接怎么烧**、**SWD 不通时怎么排**。
> 参数来自官方原理图、RM0090 与实板实测。

---

## 一、四本手册怎么分工

| 文档 | 编号 | 管什么 | 什么时候翻 |
|:--|:--|:--|:--|
| **数据手册** | DS8626 | 引脚定义、AF 映射、电气参数、封装、订购代码 | 画原理图、算功耗、选型 |
| **参考手册** | RM0090 | 外设寄存器逐位定义、时钟树、Flash 接口、选项字节 | 写驱动、配寄存器 |
| **编程手册** | PM0214 | Cortex-M4F 内核、NVIC、SCB/VTOR、MPU | 中断优先级、Bootloader |
| **勘误表** | ES0182 | 硅片已知 bug 与规避方法 | 量产前必过一遍 |

补充：**应用笔记 AN**（具体场景做法）、**UM1725**（HAL API 字典，但行为仍由 RM0090 定义）。

> 记住三条边界：**数据手册管物理边界，参考手册管外设寄存器，编程手册管内核**。
> 手册里没写的，厂商不保证；写「典型值」的不能当设计裕量。

**几条实用原则**

- 先看首页 Doc ID 和 Rev，旧版描述的行为可能已修订
- `typ / min / max` 分清楚，裕量按 worst case 取
- 寄存器属性缩写要认：`rc_w0` 读清或写 0 清、`rc_w1` 写 1 清、`rs` 读置位。**搞错清除方式会让标志永远清不掉**
- 先看功能框图再看寄存器，数据流向比逐位读快得多
- 中文译版更新滞后，关键参数以英文原版为准

**高频查阅路径**

| 问题 | 翻哪本 | 位置 |
|:--|:--|:--|
| 这个 pin 能不能这么接 | 数据手册 | 引脚定义表、AF 映射表 |
| 外设配好了但不动 | 参考手册 | RCC 章（80% 是没使能外设时钟）|
| 主频跑不到 168 MHz | 数据手册 + RM | 电压-频率对应表 + Flash 等待周期 |
| Bootloader 跳 App 失败 | **编程手册** | SCB / `VTOR`（RM0090 里没有）|
| 通信偶发丢数据 | 参考手册 + 勘误表 | 标志清除条件 + Errata |
| 访问某地址 HardFault | 参考手册 | 第 2 章存储器映射图 |
| 读保护 / 选项字节 | 参考手册 | 3.x 选项字节表 + FLASH_OPTCR |

## 二、板卡概况

| 项 | 值 |
|:--|:--|
| 型号 | **芯路城 STM32F407VGT6-Mini**（立创开源）|
| 主控 | **STM32F407VGT6**，LQFP100 |
| Flash / SRAM | 实读 **1024 KB** / 192 KB |
| 主频 | 168 MHz |
| 供电 | Type-C 5V → **SPX1117M3-3.3**（LDO，非开关电源）→ 3.3V |
| 设备 ID | `0x413`（CubeProgrammer 库 `STM32_Prog_DB_0x413.xml`）|

> VG = 1 MB Flash / 192 KB SRAM。实读 `0x1FFF7A22` 也是 1024 KB，与型号一致。
> 别被网上 VE（512 KB）的例程限制住。

## 三、引脚

**板载外设**

| 功能 | 引脚 | 说明 |
|:--|:--|:--|
| 用户 LED **D2** | **PA1** | 3V3→R5 1K→PA1，**低电平点亮** |
| 电源 LED **D1** | — | 常亮，不可控 |
| 用户按键 **S1** | **PA0** | 串 1K，按下接地 |
| 复位 **S2** | NRST | **未引出排针** |
| BOOT0 | pin 94 | 10K 下拉，**无按键**，只能跳线拉高 |
| USB D− / D+ | **PA11 / PA12** | 经 0Ω 到 Type-C |
| 串口 | **PA9 / PA10** | USART1 TX/RX |

> ⚠️ **LED 是 PA1，不是 PC0。** 网上大量 F407 例程默认 PC0，套用会「程序在跑但灯不亮」。

**SWD 下载口 P1（5PIN 短排针）** —— 丝印是功能名，不是引脚名

| P1 | 信号 | 丝印 | 接 ST-Link |
|:--:|:--|:--|:--|
| 1 | BOOT0 | `B70` | 不接 |
| 2 | 3V3 | `3V3` | 不接（Type-C 已供电）|
| 3 | GND | `GND` | **GND** |
| 4 | SWDIO (PA13) | `SWDIO` | DIO |
| 5 | SWSCLK (PA14) | `SWCLK` | CLK |

**串口在 P3 排针**：脚 **19 = PA10 (RX)**，脚 **20 = PA9 (TX)**，两者相邻一格。

## 四、时钟

```c
// HSE 8 MHz 无源晶振（PH0/PH1）→ 168 MHz
PLLM = 8;              // 8 MHz / 8  = 1 MHz
PLLN = 336;            // × 336 = 336 MHz (VCO)
PLLP = RCC_PLLP_DIV2;  // / 2 = 168 MHz → SYSCLK
PLLQ = 7;              // 48 MHz（USB 必须用 7，用 4 会枚举失败）
```

> **`HSE_VALUE` 必须是真的 8000000。** 见 5.1。

## 五、踩过的坑

### 5.1 `HSE_VALUE` 覆盖不生效 → 串口全是乱码

工程 `stm32f4xx_hal_conf.h` 里写的 `#define HSE_VALUE 8000000U` 被框架默认的 25 MHz 挡住了（`#if !defined` 不成立）。结果固件按 525 MHz 算波特率，实际 168 MHz：

```
症状：115200 乱码，降到 38400 反而正常
验算：115200 × 168/525 = 36864 ≈ 38400
```

**修法：命令行强制定义，别指望头文件**

```ini
; platformio.ini
build_flags = -D HSE_VALUE=8000000
```

**验证：搜二进制确认真编进去了**

```bash
arm-none-eabi-objcopy -O binary firmware.elf f.bin
python3 -c "import struct;d=open('f.bin','rb').read();print('8M OK' if struct.pack('<I',8000000) in d else 'MISSING')"
```

> **通用规律**：串口乱码时逐档试波特率，若某个"非预期"波特率能解出正确内容，就是时钟算错，不是接线问题。

### 5.2 `st-flash` 1.6.0 会抹掉 F4 的固件

报 `Failed to unlock flash!` 之后**仍会发出擦除命令**。烧 F4 一律用 OpenOCD、`dfu-util` 或 CubeProgrammer。

### 5.3 `dump_image` 后一定要 `reset run`

只 `shutdown` 会把芯片留在 debug halt：固件不跑、USB 不枚举，很容易误判成「烧坏了」。

### 5.4 选项字节的字节偏移极易读错（我犯过）

选项字节是**半字定义、小端存储**，RDP 在**高字节**（偏移 +1），不是低字节。详见第八节。
读错一个字节，会把 `USER` 当成 `RDP`，进而编出一整套错误诊断。

## 六、烧录：三条通道

| 通道 | 依赖 | 要 BOOT0 跳线 | 能改选项字节 | 备注 |
|:--|:--|:--:|:--:|:--|
| **SWD** | ST-Link | ❌ 不用 | ✅ | 当前不可用（见第七节）|
| **DFU** (USB) | Type-C | ✅ 要 | ✅（工具要对）| 救砖首选 |
| **UART bootloader** | CH343 → PA9/PA10 | ✅ 要 | ✅ | 最稳，不依赖 USB 枚举 |

BOOT0 跳线三步（无按键，只能手动）：

```
1. 杜邦线 P1 脚1 (B70) → 脚2 (3V3)
2. 按一下 S2 复位
3. 拔掉跳线（否则 app 不跑）
```

### 6.1 SWD / OpenOCD

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
        -c "init; program firmware.bin 0x08000000 verify; reset run; shutdown"
```

读备份（读完务必 `reset run`）：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
        -c "init; dump_image backup.bin 0x08000000 0x100000; reset run; shutdown"
```

### 6.2 DFU

```bash
dfu-util -a 0 -s 0x08000000:leave -D firmware.bin
```

### 6.3 UART bootloader

```bash
stm32flash -w firmware.bin -v -g 0x08000000 /dev/ttyUSB0
# -w 写入  -v 校验  -g 烧完从 flash 启动
```

### 6.4 STM32CubeProgrammer（stcp）

已装到 `~/bin/stcp`，版本 **2.24.0**，**原生运行，不用 Docker**。

**为什么要特殊装**：新版要求 `glibc 2.34` / `GLIBCXX 3.4.29`，本机 Ubuntu 20.04 只有 `2.31` / `3.4.28`，直接跑会报：

```
/lib/x86_64-linux-gnu/libc.so.6: version `GLIBC_2.34' not found
```

**做法**：把 jammy(22.04) 的运行时树解到独立目录，用它的 loader 启动，**系统 glibc 一点不动**。

```
~/.local/stcp-runtime/root/     22 MB，glibc 2.35 + libstdc++ + libusb/glib 等
~/bin/stcp                      包装脚本
```

```bash
# 包装脚本核心（~/bin/stcp）
P=/usr/local/STMicroelectronics/STM32Cube/STM32CubeProgrammer
R=$HOME/.local/stcp-runtime/root
exec "$R/lib/x86_64-linux-gnu/ld-linux-x86-64.so.2" \
  --library-path "$R/lib/x86_64-linux-gnu:$R/usr/lib/x86_64-linux-gnu:$P/lib" \
  "$P/bin/STM32_Programmer_CLI" "$@"
```

**常用命令**

```bash
stcp --version                      # 2.24.0
stcp -l                             # 列出可用接口（ST-Link / UART）
stcp -c port=SWD freq=480           # 走 SWD 连芯片
stcp -c port=USB1 -ob displ         # 显示选项字节（带字段名）
stcp -c port=USB1 -e all            # 全片擦除
stcp -c port=USB1 -ob WRP1=0xFFF    # 解除写保护（12 位全 1 = 不保护）
stcp -c port=USB1 -ob RDP=0xAA      # 恢复读保护 Level 0
stcp -c port=USB1 -ob unlockchip    # 选项字节异常时解锁
stcp -c port=USB1 -d app.bin 0x08000000   # 烧写
```

**参数来源**：`--help` 原文 + `Data_Base/STM32_Prog_DB_0x413.xml`（WRP0：BitOffset `0x10`，BitWidth `0xC`，值 `0x0`=保护 / `0x1`=不保护）。

## 七、SWD 不通：结论与排查

### 7.1 现状

| 项 | 状态 | 证据 |
|:--|:--|:--|
| 芯片 | ✅ 健康 | Flash 有有效向量表（SP `0x20005010`、Reset `0x08000289`）|
| 固件 | ✅ 完好 | 12:08 备份 1 MB，非 0xFF 字节 116,455 |
| 供电 | ✅ 正常 | 板载 LED 亮、DFU 能枚举 |
| **SWD** | ❌ **不可用** | `chipid: 0x0000`；官方工具 `Unable to get core ID` |
| DFU | ✅ 可用 | BOOT0 拉高即出现 `0483:df11` |
| 原固件备份 | ✅ | `~/backups/f407/orig_20261127.bin` |

### 7.2 判断口诀

```
chipid 有值，但读 Flash 被拒   →  查 RDP（读保护）
chipid = 0x0000               →  查物理层（接线/适配器/走线）
```

**我们是后者。** RDP 保护只会「限制访问」，不会让 DP 握手都失败。

### 7.3 四条独立实现全部失败

| 工具 | 通用层 | 结果 |
|:--|:--|:--|
| OpenOCD 0.10 | HLA / stlink 库 | `init mode failed` |
| OpenOCD 0.12 | 自带 DAP | `jtag status contains invalid mode value` |
| pyocd | pyocd 自带 | `No device connected` |
| **CubeProgrammer 2.24（ST 官方）** | ST 官方 ST-LINK 栈 | **`Unable to get core ID`** |

**官方参考实现都在 DP 层失败 → 软件配置、时钟速度、RDP 全部可以排除。** 问题在 ST-Link 到芯片之间。

### 7.4 已排除项（都是实测，不是推断）

| 怀疑点 | 实测 | 结论 |
|:--|:--|:--|
| RDP 读保护 | RDP 字段实为 `0xAA`（Level 0）| ❌ 不是原因（见第八节）|
| 固件禁用了 SWD 脚 | 跑在 ROM bootloader 时测，仍失败 | ❌ ROM 不会禁 SWD |
| 速度/时序容差 | 试到 50 kHz（慢 30 倍）仍失败 | ❌ 不是速度 |
| 杜邦线断芯 | 换过线，症状不变 | ❌ 不是线材 |
| 芯片损坏 | DFU 擦/写/跑/串口全正常 | ❌ 芯片健康 |
| 全片擦除后残留 | mass erase 后空白片测，仍失败 | ❌ 不是残留 |
| 板子没电 | 见 7.5 | ⚠️ 曾有误判 |

### 7.5 关键陷阱：3.32V 不代表板子有电

我一度把 `Target voltage: 3.32V` 当成「板子供电正常」的证据。**错的。**

```
12:08 通电    3.329452
13:17         3.346939
14:28         3.323327
16:10 未通电  3.324949   ← 板子没电，照样 3.3V
16:14 通电    3.326572
```

**原因**：ST-Link 板载自己的 3.3V LDO（USB 5V 供电），TVCC 引脚给的是它自己的输出。
OpenOCD / CubeProgrammer 读的「Target voltage」量的是这根线，**不是目标板电源**。

> 判断板子有没有电，只能用万用表量板子 3V3 脚，或看板载电源 LED。

### 7.6 怎么定死是哪个部件（2×2 交叉）

| | 这块 F407 | 另一块 STM32 板 |
|:--|:--|:--|
| **这个 ST-Link** | ❌ 已测失败 | **B：未测** |
| **另一个调试器** | **C：未测** | 对照组 |

- **B 成功** → ST-Link 没问题，问题在这块板
- **C 成功** → 板子没问题，问题是 ST-Link
- B、C 都失败 → 都有问题，或方法本身有系统性错误

**没有 B 或 C，就无法定死。** 可用的「另一个调试器」：Nucleo/Discovery 板载 ST-Link（最省钱）、DAP-Link、J-Link。

### 7.7 没有第二套硬件时：万用表三组测点

**测点 A：目标板引脚电平**（板子通电，DCV 20V 档，黑笔压 GND）

| 测点 | 正常值 | 异常含义 |
|:--|:--:|:--|
| P1 脚4（SWDIO / PA13） | **≈3.3V** | 0V → 未接通 / 插错格 / 虚焊 |
| P1 脚5（SWCLK / PA14） | **≈0V** | 3.3V → 两根线接反 |
| P1 脚3（GND） | 0V | 与 3V3 之间应 3.3V |

原理：STM32 复位后 **PA13 内部上拉、PA14 内部下拉**。这个特征电压同时证明「引脚映射对 + 芯片活着 + 排针焊通」。

**测点 B：ST-Link 空载**（不接板子）

| 测点 | 正常 | 异常 |
|:--|:--:|:--|
| SWDIO | ≈3.3V | 0V → **适配器损坏** |

**测点 C：通断**（断电，蜂鸣档）

| 起点 | 终点 | 应通 |
|:--|:--|:--:|
| P1 脚4 | MCU pin 72（PA13） | ✅ |
| P1 脚5 | MCU pin 76（PA14） | ✅ |
| P1 脚3 | GND | ✅ |

原理图上这两根网络**没有串联电阻**，应直通。
表笔太粗会碰相邻针（针距 2.54 mm），建议缝衣针绑表笔，或斜 45° 只点针尖。

### 7.8 一个可疑点

```
ST-Link SN : AE5A5BB50000000000078880
ST-Link FW : V2J28M18
```

原厂 ST-Link V2.1 序列号是唯一 ID；后段全 0 是**山寨方案**（常见 CS32F103 + 改写固件）的特征。
山寨 ST-Link 在 F4 上有已知 SWD 时序兼容问题——**这是当前最大嫌疑，但未经验证，只是假设**。

## 八、选项字节与 RDP

### 8.1 地址与字段（RM0090 表 10 / 表 11 / 3.8.7 节）

```
0x1FFFC000 - 0x1FFFC00F   选项字节区，16 字节
```

| 地址 | 内容 |
|:--|:--|
| `0x1FFFC000` 半字 [15:8] | **RDP**（读保护）→ 即 **byte1** |
| `0x1FFFC000` 半字 [7:0] | **USER**（用户选项）→ 即 **byte0** |
| `0x1FFFC002` | ~USER |
| `0x1FFFC003` | ~RDP |
| `0x1FFFC008` | 扇区 0-11 写保护 nWRP |

> **小端存储下 RDP 在高字节。RDP 绝对地址 = `0x1FFFC001`。**
> 这一条是踩过的坑（5.4）：读成 byte0 就会把 USER 当 RDP。

**RDP 取值**

| 值 | 级别 | 含义 |
|:--:|:--:|:--|
| `0xAA` | Level 0 | 无保护 |
| `0xCC` | Level 2 | 芯片保护（禁调试、禁 RAM 启动，**不可逆**）|
| 其它 | Level 1 | 读保护（调试功能受限，仍能读 IDCODE）|

**运行时可读的寄存器**（需 SWD 或在固件里读）

```
FLASH_OPTCR   0x40023C14   位15:8 = RDP   复位值 0x0FFFAAED
```

### 8.2 实测数据与本板真相

```
读取: ff aa 00 55  ff aa 00 55  ...
      ↑  ↑  ↑  ↑
      │  │  │  └─ 0x1FFFC003  ~RDP  = 0x55
      │  │  └──── 0x1FFFC002  ~USER = 0x00
      │  └─────── 0x1FFFC001  RDP   = 0xAA   ← Level 0，无保护
      └────────── 0x1FFFC000  USER  = 0xFF
```

**RDP 从头到尾都是 `0xAA`（Level 0），从未开启读保护。**

证据链（三条独立）：

1. **三次 DFU 读取**，byte1 恒为 `0xAA`
2. **反码自洽**：`0xAA ^ 0x55 = 0xFF` ✅
3. **12:08 经 SWD 成功读出整片 1 MB**——Level 1 会拦 Flash 读出，能读就说明是 Level 0

### 8.3 我改坏的是 USER 字节

```
原始: ff aa 00 55   USER=0xFF  RDP=0xAA
写入: bb aa 44 55   USER=0xBB  RDP=0xAA   ← 只有 USER 变了
```

`USER: 0xFF → 0xBB` 的实际影响：

| 位 | 含义 | 变化 |
|:--:|:--|:--|
| bit6 | nRST_STOP | `1` → `0`：进 Stop 模式现在会产生复位 |
| bit3:2 | BOR_LEV | `11`(关闭) → `10`(VBOR1，2.1~2.4V) |

两个都是有效配置，**不会变砖**，但 BOR 阈值抬高后低压时更易复位。建议恢复成 `0xFF`。

### 8.4 教训

> **不要用 `dfu-util` 写选项字节。** 它把 16 字节当普通数据下发，两次都是「写一半 + 报错」。
> 正确工具：`stcp -ob`（原生支持，带字段解析）或 `stm32flash -k`。

## 九、串口方案：每次都要跳线吗

### 9.1 结论

| 接线程度 | 每次烧录 | 自动化 |
|:--|:--|:--:|
| 只接 TX/RX/GND（现状）| 跳 BOOT0 + 按 S2 + 拔线 | ❌ |
| 加接 DTR→BOOT0、RTS→NRST | 一条命令 | ✅ |
| 应用层软件跳转 | 一条命令（app 健康时）| ✅ 但 app 坏了就失效 |

**默认答案是：要。** bootloader 只看复位瞬间的 BOOT0 电平，这块板没有按键，只能手跳。

### 9.2 接线（CH343 → F407）

```
CH343          STM32 (P3 排针)
RXD    ←────  脚20  PA9   (板子 TX)
TXD    ────→  脚19  PA10  (板子 RX)
GND    ─────  GND
DTR    ────→  P1 脚1 B70      （可选，自动复位）
RTS    ────→  S2 的 NRST 焊盘  （可选，自动复位）
```

- **交叉接**：模块 RX 接板子 TX
- **不要接 VCC/3V3**：板子已由 Type-C 供电
- CH343 若有 5V/3.3V 跳线，**拨到 3.3V**

### 9.3 三种免手方案

| | 手动跳线 | DTR/RTS 自动 | 应用层跳转 |
|:--|:--:|:--:|:--:|
| 每次动手 | 3 步 | 0 | 0 |
| 需焊接 | 无 | **2 根** | 无 |
| app 坏了能救 | ✅ | ✅ | ❌ |
| 适合 | 偶发烧写 | **长期主力** | 快速迭代 |

**DTR/RTS 自动**：`stm32flash` 原生支持 `-i GPIO_string`（仅 Linux），格式 `[entry_seq][:exit_seq]`，`sequence = [-]n[,sequence]`，`n` 可以是 GPIO 号或 `rts`/`dtr`。

```bash
stm32flash -i <序列> -w app.bin -v -g 0x08000000 /dev/ttyUSB0
```

> ⚠️ **NRST 没引到排针**，只在芯片 pin 14 和 S2 按键上，RTS 这根必须焊 S2 焊盘。
> 具体 `-i` 序列语法本机 man 写得简略，**首次使用需实测确认**。

**应用层跳转**（免焊接，但 app 跑飞失效）：

```c
#define BOOTLOADER_ADDR  0x1FFF0000

void jump_to_bootloader(void)
{
    uint32_t sp = *(volatile uint32_t *)BOOTLOADER_ADDR;
    uint32_t pc = *(volatile uint32_t *)(BOOTLOADER_ADDR + 4);
    __disable_irq();
    SysTick->CTRL = 0;
    HAL_RCC_DeInit();
    HAL_DeInit();
    __set_MSP(sp);
    ((void (*)(void))pc)();
}
```

## 十、接下来要做的事

按优先级，前两步不需要买任何东西。

### ① 万用表测三组点（7.7 节）

```
P1 脚4 (SWDIO)  期望 ≈3.3V
P1 脚5 (SWCLK)  期望 ≈0V
P1 脚3 (GND)    对 3V3 应 3.3V
```

外加 ST-Link 空载 SWDIO（应 ≈3.3V）+ 三根通断。**这一步能排除一大半可能。**

### ② 恢复 USER 字节并做官方核验（需进 DFU）

```
B70 → 3V3，按 S2，拔线
```

```bash
stcp -c port=USB1 -ob displ        # 官方解析，交叉验证 RDP=0xAA
stcp -c port=USB1 -ob USER=0xFF    # 把 USER 从 0xBB 恢复
stcp -c port=USB1 -ob displ        # 读回确认
```

### ③ 交叉验证（若有第二块板/调试器）

换调试器测这块板，或拿这块 ST-Link 测别的板 —— 唯一能「定死」的方法。

### ④ 建立串口烧录流程

接 CH343 到 PA9/PA10，验证：

```bash
stm32flash -w firmware.bin -v -g 0x08000000 /dev/ttyUSB0
```

### ⑤ 长期：换正品 ST-Link 或 DAP-Link

恢复 SWD，拿回调试能力，也就不用每次跳线了。

### 明确不该再做的

- ❌ 继续调 OpenOCD 速度（50 kHz 都试过）
- ❌ 继续换杜邦线（已换过）
- ❌ 用 `dfu-util` 写选项字节（写坏两次）
- ❌ 反复「再试一次」而不加新变量
- ❌ 再纠结 RDP —— 它是 `0xAA`，和 SWD 无关

## 十一、上手清单

1. LED = **PA1**，按键 = **PA0**，别照抄 PC0/PC1 例程
2. `build_flags` 加 `-D HSE_VALUE=8000000`，USB 工程 `PLLQ=7`
3. 烧录前先备份，读完补 `reset run`
4. 进 DFU 要跳线，没有 BOOT0 按键
5. NRST 未引出，connect-under-reset 无效
6. SPX1117 是 LDO，带屏时注意发热
7. **选项字节 RDP 在 byte1（`0x1FFFC001`），不是 byte0**
8. SWD 报 `chipid=0` 时先查物理层，不要先怀疑 RDP
9. ST-Link 报的 `Target voltage` 不是目标板电源，别当供电证据
10. 写选项字节用 `stcp -ob`，别用 `dfu-util`

## 十二、一句话总结

> **芯片好、固件好、供电好，坏的是 SWD 这条物理链路。**
> RDP 一直是 Level 0，不是原因；四条独立实现（含 ST 官方）都在 DP 握手失败。
> 定死原因只能靠 2×2 交叉或万用表测点。
> 在此之前，串口 + `stm32flash` 是可靠通道，DFU 只作救砖，`stcp` 管选项字节。
