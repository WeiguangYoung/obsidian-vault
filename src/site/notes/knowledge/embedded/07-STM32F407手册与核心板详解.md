## 一、什么是芯片手册

芯片手册（Chip Documentation）是**芯片厂商发布的、描述该芯片能力边界与使用方法的官方技术文档集合**。它的本质是**规格合同**：

- 手册里写的参数，厂商必须保证（在标称条件下）；
- 手册里没写的，厂商不保证，出了问题算设计方的；
- 手册里写"典型值"的地方是统计结果，**不能当设计裕量用**。

所以手册不是教程。它不教你"怎么用 CAN 做个项目"，只告诉你"CAN 控制器有 28 个寄存器，每一位是什么含义"。**教程讲意图，手册讲事实。**

STM32F407 的文档量级：

| 文档 | 大致页数 |
|:--|--:|
| 数据手册（DS8626 / DM00037051） | 200+ |
| 参考手册（RM0090） | 1700+ |
| 编程手册（PM0214） | 250+ |
| 勘误表（ES0182） | 40+ |

## 三、数据手册核心内容（DS8626）

数据手册回答"**这颗芯片在物理世界里的边界**"。

### 3.1 特性概览

- 内核：ARM Cortex-M4F，最高 **168 MHz**，单精度 FPU + DSP 指令
- 存储：**512 KB ~ 1 MB Flash**，**192 KB SRAM**（128 KB + 64 KB CCM）
- 供电：**1.8 V ~ 3.6 V**
- 封装：LQFP64 / LQFP100 / LQFP144 / BGA100 / WLCSP90
- 外设：3×12-bit ADC、2×DAC、17 定时器、3×I2C、6×USART、3×SPI、2×CAN、USB OTG FS/HS、Ethernet MAC、SDIO、FSMC

> "最高 168 MHz"有条件——通常要 VDD ≥ 2.1 V 且 Flash 等待周期配对。降压实测跑不到 168 MHz 时，先查**电压-频率对应表**，不是芯片坏了。

### 3.2 引脚定义与复用功能

数据手册翻得最多的部分，也是硬件出错的重灾区：

- **引脚分布图**：按封装给顶视图，标注 pin 1 位置
- **引脚定义表**：编号、名称、类型、复用功能、复位后默认状态、附加功能（ADC 通道、TIM 通道）
- **复用功能映射表（AF mapping）**：哪一路 USART_TX 能映射到哪几个 pin。STM32F407 的 AF 编号 0~15，例如 `PA9` 作 `USART1_TX` 是 **AF7**

查错一行，引脚就死了。

### 3.3 电气特性

| 类别 | 典型内容 |
|:--|:--|
| 绝对最大额定值 | VDD 最大 4.0 V、单引脚注入电流 ±25 mA、总注入 ±150 mA |
| 工作条件 | VDD 1.8~3.6 V；温度等级 6 = -40~85 ℃，7 = -40~105 ℃ |
| 电流消耗 | Run mA/MHz，Sleep/Stop/Standby 各模式典型值 |
| I/O 特性 | VIL/VIH、VOL/VOH、上下拉范围、引脚电容 |
| 模拟特性 | ADC 精度（INL/DNL/ENOB）、VREF 范围、DAC 建立时间 |
| 时钟特性 | HSI/HSE 精度、PLL 抖动、晶振推荐参数 |
| 时序特性 | Flash 编程时间、复位脉宽、启动时间 |

**用法**：算功耗预算、选 LDO、判断电平匹配、确定晶振负载电容，全在这一章。做低功耗产品，Stop 模式的 μA 级数字和唤醒时间必须从这里取。

### 3.4 封装、热特性、订购信息

- 封装机械图（尺寸、焊距、推荐 footprint）
- 热阻 θJA / θJC，估算结温
- **订购代码解析**：`STM32F407VGT6` = F407 + `V`(LQFP100) + `G`(1 MB Flash) + `T`(LQFP) + `6`(-40~85 ℃)

> 温度等级和封装字母是采购换料最容易搞错的地方，换料时对一遍这张表，比信供应商口头承诺可靠。

## 四、参考手册核心内容（RM0090）

参考手册回答"**这个外设的寄存器怎么配，配了会发生什么**"，是驱动开发的唯一权威依据。

### 4.1 前几章：地基

| 章 | 内容 | 为什么重要 |
|:--|:--|:--|
| 1 | 文档约定 | 读懂 `rw/r/W1C/rc_w0` 这些寄存器属性缩写 |
| 2 | 存储器与总线架构 | AHB/APB 分域、地址空间、位带 |
| 3 | 嵌入式 Flash 接口 | 等待周期 vs 主频、扇区擦除、选项字节 |

**第 2 章的存储器映射图**是排错利器：访问非法地址触发 HardFault 时，先对照看地址落在哪个区。

### 4.2 时钟与电源（第 5、6、7 章）

- **PWR**：Sleep / Stop / Standby 三种低功耗模式的进入条件、唤醒源、模式下的时钟与 SRAM 保持
- **RCC**：时钟树（HSI/HSE/PLL → SYSCLK → AHB/APB 分频）、每个外设的时钟使能位、CSS 时钟安全系统

> 新手最常见的问题"外设配好了但不动"，80% 是 RCC 里没使能该外设时钟。

### 4.3 GPIO（第 8 章）

四种输入模式（浮空/上拉/下拉/模拟）、四种输出模式（推挽/开漏 + 上下拉）、复用与模拟模式；`MODER` / `OTYPER` / `OSPEEDR` / `PUPDR` / `IDR` / `ODR` / `BSRR` / `AFR[2]` 八个寄存器。

**BSRR 的原子性**：置位/复位一次写完成，比读改写 ODR 安全（中断里也不怕）。

### 4.4 通信外设（第 24~30 章）

以 USART（第 26 章）为例，典型结构：功能框图 → 波特率计算（`USARTDIV = fCK / (16 × baud)`）→ 寄存器逐位说明 → 中断/DMA 映射 → 错误标志清除。

**状态标志清除方式是踩坑高发区**：有的读 SR 再读 DR 才清，有的写 0 清，有的写 1 清。手册每个标志后面都标了清除条件，别凭印象写。

### 4.5 定时器（第 14~17 章）

| 类型 | 实例 | 特点 |
|:--|:--|:--|
| 高级控制 | TIM1 / TIM8 | 互补输出、死区、刹车输入，给电机/电源 |
| 通用 | TIM2~5、TIM9~14 | 输入捕获、输出比较、PWM、编码器接口 |
| 基本 | TIM6 / TIM7 | 只有计数和更新事件，给 DAC 触发/时基 |

### 4.6 其它重点章

DMA（流/通道映射表、FIFO、双缓冲）｜ADC（规则/注入组、采样时间与源阻抗、多重模式）｜bxCAN（过滤器组位宽、邮箱、BTR 位定时）｜FMC（外部 SRAM/NOR/SDRAM 时序）｜ETH（DMA 描述符、MII/RMII）｜DBG（调试时冻结看门狗的 `DBGMCU`）

## 五、编程手册核心内容（PM0214）

编程手册讲 **CPU 内核**，不是 ST 的外设。ARM 也出一份架构手册，但 ST 这份更贴实际——它把内核寄存器和 STM32 的具体地址绑定了。

- **内核架构**：R0~R15、xPSR、PRIMASK/BASEPRI/FAULTMASK、CONTROL、栈对齐、特权/非特权模式
- **指令集**：Thumb-2 编码与语义、条件执行、位操作指令（`BFI`/`BFC`/`RBIT`）
- **FPU**：S0~S31、`FPCCR`/`FPSCR`、**惰性压栈**机制
- **NVIC**：优先级分组（抢占/子优先级）、`NVIC_ISER` 等地址、**优先级数值越小越高**
- **SCB 系统控制块**：`VTOR` 向量表偏移（Bootloader 必看）、`AIRCR` 软复位、`SHPRx` 异常优先级
- **MPU**：区域配置、属性、访问权限（跑 RTOS 或做安全隔离时才用）
- **异常模型**：进入/返回的压栈内容、尾链优化、延迟到达

> 写 Bootloader 跳到 App 时必须改 `SCB->VTOR`——这条在 RM0090 里找不到，只在 PM0214 里。这就是"两本手册分工"的典型例子。

## 六、勘误表与应用笔记

### 6.1 勘误表（ES0182）

列出**硅片层面已确认的缺陷**及规避方案，按模块分（内核/系统、Flash、ADC、通信外设等）。问题分两类：**有规避方法** 和 **无解（只能避免使用该功能）**。

**处理原则**：量产前必须逐条过，判断你的用法是否踩中。

### 6.2 应用笔记（AN 系列）

常用主题：时钟/晶振设计与 PCB 布局、ADC 精度提升、USB/Ethernet 硬件检查表、Flash 模拟 EEPROM、低功耗设计。

价值在于**把手册参数翻译成工程做法**，但**不具备规格约束力**——冲突时以数据手册/参考手册为准。

### 6.3 库文档（UM1725）

用 HAL 时它是 API 字典。但**HAL 只是把寄存器操作封装了一层，行为仍由 RM0090 定义**。HAL 出问题时最终还是要回参考手册看寄存器。

## 八、读手册的方法

1. **先看版本号和修订历史**。首页有 Doc ID 和 Rev，勘误表也有版本。旧版本描述的行为可能已被修订。
2. **看清限定条件**。所有参数都带前提（VDD、温度、时钟频率），脱离条件引用参数是最常见的错误。
3. **区分 typ / min / max**。设计裕量按 worst case 取，不能用 typ。
4. **看懂寄存器属性缩写**：`rw` / `r` / `w` / `rc_w0`（读清或写 0 清）/ `rc_w1`（写 1 清）/ `rs`（读置位）。搞错清除方式会导致标志永远清不掉。
5. **优先看框图再看寄存器**。功能框图告诉你数据流向和触发关系，比逐位读寄存器快得多。
6. **中文译版仅作参考**。ST 部分文档有中文版，但**更新滞后且可能翻译偏差**，关键参数以英文原版为准。
7. **手册 + 官方例程对照读**。Cube 包的 `Examples/` 是最好的"标准答案"。
8. **把勘误表加入 checklist**。不是读一遍就完，每次改硬件/改关键配置时回查。

## 九、核心板与开发板选型（一句话版）

**核心板是元器件，开发板是工具。**

- **核心板**：只留 MCU 跑起来必需的元件（MCU、晶振、复位、LDO、BOOT 选择、排针），便宜、小，适合**嵌入产品、批量、插到自研底板**
- **开发板**：核心板 + USB 转串口 + 按键 LED + 各种接口 + 四周排针，插线即用，适合**学习、验证、竞赛**
- **选型只需问一句**：我有 ST-Link 吗？没有 → 买开发板（省心）；有 → 核心板更划算（调试器是可复用资产，板子是一次性的）

芯片完全相同，差的是**调试通路和外设完整度**，不是性能。

## 十、实例：芯路城 STM32F407VET6-Mini 核心板

参数来自官方原理图 `STM32F407VX_M核心板-原理图-2026.4.pdf` 与实板实测。

### 10.1 板卡概况

| 项目 | 参数 |
|:--|:--|
| 板卡型号 | **STM32F407VET6-Mini**（芯路城 / 立创开源）|
| 主控 | STM32F407VET6，LQFP100 |
| Flash / SRAM | **实测 1024 KB** / 192 KB（读 `0x1FFF7A22`）|
| 主频 | 168 MHz |
| 供电 | Type-C 5V → SPX1117M3-3.3 LDO → 3.3V |
| 引出 | 两侧 2.54 mm 长排针 + P1/P2/P3/P4 功能排针 |

> 官网标注 **VET6-Mini**，并注明「STM32F407VGT6 和 STM32F407VET6 资料通用」。实板 Flash 读到 1024 KB，与 VG 规格一致——**别按 512 KB 规划容量**，以 `0x1FFF7A22` 实读为准。

### 10.2 电源

```
Type-C VBUS (5V) ──→ SPX1117M3-3.3 ──→ 3.3V ──→ STM32 + 外设
                     (SOT-223 LDO)       │
                                   10 µF + 100 nF 滤波
```

- **LDO 是 SPX1117M3-3.3**（不是开关电源，效率低、发热明显）
- 模拟电源 `VDDA` 经磁珠从 3.3V 隔离，`VREF+` 与 `VDDA` 同网
- 纽扣电池座 → `VBAT`，不装电池则 RTC 掉电不保持
- Type-C 的 `CC1/CC2` 各串 5.1 kΩ 下拉（UFP 规范）；`DP/DN` 经 **0 Ω 电阻**接 **PA12/PA11**

> 供电只走一路：Type-C 插着时不要再从排针灌 5V，板上无防倒灌。

### 10.3 时钟

| 时钟 | 器件 | 引脚 |
|:--|:--|:--|
| HSE | **8 MHz 无源晶振 Y2** | OSC_IN / OSC_OUT（PH0 / PH1）|
| LSE | 32.768 kHz（如装）| PC14 / PC15 |

**PLL 配置（168 MHz 满速）**：

```c
PLLM = 8;              // 8 MHz / 8  = 1 MHz
PLLN = 336;            // 1 MHz × 336 = 336 MHz (VCO)
PLLP = RCC_PLLP_DIV2;  // 336 / 2 = 168 MHz → SYSCLK
PLLQ = 7;              // 48 MHz（USB 必须用 7，用 4 会枚举失败）
```

> 工程里的 `stm32f4xx_hal_conf.h` 必须把 `HSE_VALUE` 改成 **8000000**。老版 HAL 默认 25 MHz，改漏了会导致串口波特率全错、延时不准。

### 10.4 引脚分配

**板载外设**：

| 功能 | 引脚 | 说明 |
|:--|:--|:--|
| 用户 LED **D2** | **PA1** | 3V3 → R5 1K → PA1，**低电平点亮**（灌电流）|
| 电源 LED **D1** | — | 3V3 → R1 1K → GND，常亮不可控 |
| 用户按键 **S1** | **PA0** | 串 R2 1K，按下接地 |
| 复位按键 **S2** | NRST | 配 C5 到地；**NRST 未引出排针** |
| BOOT0 | pin 94 | R7 10K 下拉，**无按键，只能靠排针跳线拉高** |
| USB D− / D+ | **PA11 / PA12** | 经 0 Ω 到 Type-C |
| HSE | PH0 / PH1 | 8 MHz 晶振 |

> **LED 引脚是 PA1。** 网上大量 F407 例程默认驱动 PC0，直接套用会「程序在跑但灯不亮」——先确认原理图上 LED 挂的是哪个脚。

**SD 卡（MiniSD 座 SD1，走 SDIO）**：

| 座子脚 | 信号 | | 座子脚 | 信号 |
|:--|:--|:--|:--|:--|
| 1 | SDIO_D2 | | 5 | SDIO_CLK |
| 2 | SDIO_D3 | | 6 | GND |
| 3 | SDIO_CMD | | 7 | SDIO_D0 |
| 4 | 3V3 | | 8 | SDIO_D1 |

**SPI Flash W25QXX**：`F_CS`、`SI`(MOSI)、`SO`(MISO)、`SCLK`、`WP`、`HOLD`

**TFT 显示屏接口 P2（8P，SPI1）**：

| 脚 | 信号 | 脚 | 信号 |
|:--:|:--|:--:|:--|
| 1 | 3V3 | 5 | PB12 |
| 2 | GND | 6 | PB14 |
| 3 | PB15 | 7 | PC5 |
| 4 | PB13 | 8 | PB1 |

**其它排针**：`P3` 为 24P IO 扩展口（5V、PD8/PD10/PD12/PD14、PC6/PC8/PC10、PA8/PA10/PA12 等），`P4` 为 22×2P 全引脚引出，具体见原理图。

### 10.5 SWD 下载接口 P1（5PIN，短排针）

丝印写的是**功能名，不是引脚名**：

| P1 | 信号 | 丝印 | 接 ST-Link |
|:--:|:--|:--|:--|
| 1 | BOOT0 | `B70`（印字被截断）| 不接 |
| 2 | 3V3 | `3V3` | 不接（Type-C 已供电）|
| 3 | GND | `GND` | **GND** |
| 4 | SWDIO (PA13) | `SWDIO` | **DIO / SWDIO** |
| 5 | SWSCLK (PA14) | `SWCLK` | **CLK / SWCLK** |

> ⚠️ 本板**没有把 NRST 引到任何排针上**（只在芯片 pin 14 与按键 S2 上）。所以 `connect_assert_srst` / connect-under-reset 无效——要用就得飞线到 S2 的 NRST 焊盘，通常不如直接走 DFU。

### 10.6 烧录

**方式一：SWD（推荐，需要接线）**

```bash
openocd -f interface/stlink-v2-1.cfg -f target/stm32f4x.cfg \
        -c "init; program firmware.bin 0x08000000 verify; reset run; shutdown"
```

**方式二：DFU（不依赖 SWD，空片/跑飞也能救）**

```bash
# 1. 杜邦线把 P1 的 B70(BOOT0) 短接到 3V3
# 2. 按一下 S2 复位
# 3. 拔掉那根跳线
lsusb | grep df11        # 应出现 0483:df11
dfu-util -a 0 -s 0x08000000:leave -D firmware.bin
```

`-s ...:leave` 表示烧完自动跳转运行，不用再手动复位。

**方式三：板载 USB 原生 DFU** —— Type-C 直连 PA11/PA12，同上，只要 BOOT0 拉高即可。

> **别用 `st-flash` 1.6.0 烧 F4。** 它对 F4 解锁流程有 bug：报 `Failed to unlock flash!` 之后**仍会发出擦除命令**，直接抹掉固件。用 OpenOCD 或 `dfu-util`。

### 10.7 上手注意点

1. **LED 在 PA1，按键在 PA0**，别照抄网上默认 PC0/PC1 的例程
2. **NRST 没引出**，SWD 连不上时无法用复位同步，走 DFU 更快
3. **BOOT0 没有按键**，进 DFU 必须用杜邦线短接 B70 到 3V3 再按 S2
4. **`HSE_VALUE` 必须是 8 MHz**，USB 工程 `PLLQ=7`
   - ⚠️ **只在工程 `stm32f4xx_hal_conf.h` 里改常常不生效**，框架的 25 MHz 会先占位。
     最保险：`platformio.ini` 的 `build_flags` 加 `-D HSE_VALUE=8000000`
   - **验证方法**：把 `.elf` 转 `.bin` 后搜常量——`8MHz(0x7A1200)` 应在、`25MHz(0x17D7840)` 应无：
     ```bash
     arm-none-eabi-objcopy -O binary firmware.elf f.bin
     python3 -c "import struct;d=open('f.bin','rb').read();print('8M' if struct.pack('<I',8000000) in d else 'MISSING')"
     ```
   - **症状识别**：串口输出乱码，但降到 `38400` 反而正常 → 时钟算错的典型指纹
     （固件按 525 MHz 算波特率，实际 168 MHz，115200 实际输出 36864 baud）
5. **SPX1117 是 LDO**，5V 降 3.3V 时压差大，带屏时注意发热
6. **烧录前先备份**：`openocd -c "dump_image backup.bin 0x08000000 0x100000"`，读完记得 `reset run`
7. **`dump_image` 后一定要 `reset run`**，否则芯片停在 debug halt，固件不跑、USB 不枚举，容易误判为「烧坏了」


### 10.8 串口实测：接 CH340 与「乱码 = 时钟错」

#### 接线

板子 **USART1 在 P3 排针**（2×13，26 脚），PA9/PA10 相邻一格：

| P3 脚号 | 信号 | 方向 |
|:--:|:--|:--|
| **20**（右列）| **PA9** = USART1_TX | 板 → CH340 **RXD** |
| **19**（左列）| **PA10** = USART1_RX | 板 ← CH340 **TXD** |

```
CH340        STM32 (P3)
RXD    ←──   PA9   (脚 20，板子发)
TXD    ──→   PA10  (脚 19，板子收)
GND    ────  GND
```

- **交叉接**：模块的 RX 接板子的 TX，模块的 TX 接板子的 RX，接反就收不到
- **不要接 VCC / 3V3**：板子已由 Type-C 供电，两路电源会打架
- CH340 模块若带 5V/3.3V 跳线，**务必拨到 3.3V**，5V 电平长期打 RX 脚会损 IO

主机侧（本机实测）：

```bash
lsusb | grep 1a86        # 1a86:7523 = CH340
ls /dev/ttyUSB0
sudo usermod -aG dialout $USER   # 打不开串口时补这一步，重登录生效
```

#### 坑：115200 全是乱码，降到 38400 反而正常

**现象**：串口助手 115200 收到一堆乱码（`\x00\x1c\x1c\x00...`），换几个波特率，只有 **38400** 能解出正确中文。

**逐档试出来的结果**（用 `stty` + `cat` 直接抓原始字节，统计可打印字符比例）：

| 波特率 | 可打印占比 | 判定 |
|:--|:--:|:--|
| 115200 | 0% | 乱码 |
| **38400** | **32%（中文可辨）** | ✅ 真实波特率 |
| 57600 / 19200 / 9600 | 7%/23%/21% | 乱码 |
| 230400 / 460800 | 0% | 乱码 |

**根因**：固件里 `HSE_VALUE` 编进去的是 **25 MHz**（框架默认），而板上晶振是 **8 MHz**。

```c
// 工程 include/stm32f4xx_hal_conf.h 里明明写着：
#if !defined (HSE_VALUE)
  #define HSE_VALUE  8000000U     // ← 这条根本没生效
#endif
```

验证方法——直接搜固件二进制：

```bash
arm-none-eabi-objcopy -O binary firmware.elf f.bin
python3 -c "
import struct
d=open('f.bin','rb').read()
for v,n in [(8000000,'8MHz'),(25000000,'25MHz')]:
    print(n, '出现' if struct.pack('<I',v) in d else '未出现')
"
```

结果：

```
8MHz  ( 8000000) : ❌ 未出现
25MHz (25000000) : ✅ 出现 @0x15C8
```

**验算完全吻合**：

```
固件以为 SYSCLK = 25/8 × 336/2 = 525 MHz
实际    SYSCLK =  8/8 × 336/2 = 168 MHz
按 115200 配置 → 实际输出 115200 × 168/525 = 36864 baud
实测能解出内容 → 38400 baud
```

`36864 ≈ 38400`，误差 1.4%，正在波特率容差内——所以不是完全收不到，而是**每个字节都被采样错位**。

**修法**：命令行强制定义，别指望头文件覆盖：

```ini
; platformio.ini
build_flags =
    -D USE_HAL_DRIVER
    -D STM32F407xx
    -D HSE_VALUE=8000000      ; ← 必须加这行
    -Wl,-u,_printf_float
```

重编译后再搜二进制，`8MHz` 出现、`25MHz` 消失，烧录后 115200 立刻正常。

#### 通用结论

> **串口乱码时，先逐档试波特率。** 如果某个"非预期"波特率（如 38400）能解出正确内容，
> 那就不是接线问题，而是**时钟频率算错**——真实波特率 = 配置波特率 × 实际主频 / 代码以为的主频。
> 这个比例往往正好等于晶振实际值与你代码里 `HSE_VALUE` 的比值。

配套排查顺序：

1. 串口助手设 8N1、无流控
2. 逐档扫波特率，找能解出中文的那一档
3. 算比例 → 反推 `HSE_VALUE` 是否写错
4. `objcopy` 成 bin，搜常量确认编译结果
5. 改用 `-D HSE_VALUE=xxx` 命令行定义，重新编译烧录

#### 实测输出（修复后，115200）

```
十进制格式：  128
十六进制格式：80
小数格式：    9.123456
```

每 500ms 循环一轮，中文、整数、十六进制、浮点全部正确——**USART1 + PA9/PA10 + CH340 + 115200 整链路验证通过**。
