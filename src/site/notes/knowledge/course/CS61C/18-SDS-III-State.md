# CS61C FA26 · L18 SDS III: State

> UC Berkeley · Great Ideas in Computer Architecture
> 授课：Dan Garcia · 课件 18-SDS III: State（46 页）

---

## 一、起点问题：做一个累加器

### 1.1 需求

```c
S = 0;                      // S0
for (int i = 0; i < n; i++)
    S = S + X[i];
```

**三个必须满足的要求：**

| # | 要求 |
|---|---|
| ① | **把和 S 复位成 0** |
| ② | **每个周期施加一个 X[i]，共 n 个周期** |
| ③ | **第 i 步的 S 是 X[1]…X[i] 的和（真正的 S_i）** |

### 1.2 ❌ 第一次尝试：只加反馈

```
        ┌──────────┐
   X ──►│          │
        │  Adder   ├──► S_i
   S ──►│          │
        └──────────┘
             ▲ 反馈（feedback）
             └──────────┘
```

> **❌ 不行！**

**两个致命问题：**

| 问题 | 说明 |
|---|---|
| **① 无法复位** | **没有任何办法把 S 归零** |
| **② 无法控制时序** | **没有任何办法控制「下一次迭代何时发生」** |

> **结论：需要「控制信息流动」的机制 → 这就是状态元件的动机。**

## 二、两类电路的对比

> **SDS 由两种基本电路构成（L16 已初见）：**

| 类型 | 特征 | 状态 |
|---|---|---|
| **① Combinational Logic** | 输出仅是输入的函数，无记忆、无副作用 | L16–L17 ✅ |
| **② State Elements** | **能存储信息的电路**，例：寄存器 | **本讲** |

> **目标不变：用 SDS 实现 RISC-V 处理器。**

---

## 三、状态元件的作用

### 3.1 它们做什么

> **状态元件是「存储信息」的电路。**

| 能力 | 说明 |
|---|---|
| **长时间保存值** | 保存「不确定多久」 |
| 例子 | **寄存器堆（RISC-V 的 x0–x31）**、**内存（缓存、主存）**、**SR 锁存器** |
| **控制信息流动** | **「拦住」涌向组合逻辑输入的信息，让它们有序通过** |
| **限制整体性能** | **常常是 SDS 性能的瓶颈** |

> ⭐ **最后一句话很重要：状态元件往往决定整个系统的速度上限。**

## 四、寄存器

### 4.1 定义

> **寄存器是一种「在一段时间内存储信息」的特殊电路。**

| 项 | 说明 |
|---|---|
| **位宽** | `n = 32`（典型）|
| **特殊输入** | **`LOAD` —— 触发信号** |
| **触发时** | **采样输入 → 传到输出** |
| **其他所有时候** | **忽略输入** |

### 4.2 时钟：同步系统的节拍

> **同步 = 由中央时钟协调所有操作，它是系统的「心跳」。**

> **要控制信息流动，就「用时钟驱动状态元件」—— 即用时钟信号控制更新触发。**

| 量 | 典型值 |
|---|---|
| **时钟周期 T** | `1 ns = 10⁻⁹ s` |
| **时钟频率 f** | `1/T ≈ 1 GHz = 每秒十亿周期` |

### 4.3 边沿触发寄存器

> **本讲讨论「上升沿触发（rising edge-triggered）」状态元件，又称「正边沿（positive edge）」。**

| 项 | 说明 |
|---|---|
| **触发条件** | **`LOAD` 从 0 变 1** |
| **`LOAD` 是谁** | **就是系统时钟信号 `CLK`** |
| **每个时钟周期** | **载入输入值** |
| **载入需要时间** | **CLK-to-Q 延迟** |

> **（课外：下降沿寄存器、非时钟触发等，本课不讨论。）**

> ⚠️ **寄存器是物理系统，所以输出更新有延迟 —— 这就是 CLK-to-Q 延迟。**

### 4.4 寄存器内部

> **常规寄存器设计：**

| 信号 | 含义 |
|---|---|
| **D** | **Data（输入）** |
| **Q** | **Output（输出）** |
| **CLK** | **时钟信号** |

> **一个 n 位宽寄存器 = n 个触发器（flip-flop）的并排集合。**

| 术语 | 说明 |
|---|---|
| **Flip-Flop（FF）** | **1 位寄存器** |
| | 得名于「输出在 0 和 1 之间 flip and flop（翻来覆去）」 |
| **三角形符号** | **表示「时钟驱动的状态元件」** |

## 五、⭐ 触发器时序：三个约束

### 5.1 基本行为

> **在 CLK 的上升沿，每个 FF 抓取输入 d，内部保存，再传到输出 q。**

### 5.2 三个时序参数

| 参数 | 定义 | 类比（自拍）|
|---|---|---|
| **Setup time（建立时间）** | **输入必须在时钟上升沿「之前」稳定多久** | **按下快门前别动** |
| **Hold time（保持时间）** | **输入必须在上升沿「之后」稳定多久** | **快门关了再动** |
| **CLK-to-Q delay** | **从上升沿到输出真正变化要多久** | **从拍到看到照片的延迟** |

### 5.3 ⭐ 核心规定

> **所有寄存器时序约束，都是「相对时钟上升沿」的。**

```
            ┌─────┐
CLK   ──────┘     └─────
         │
         │◄─setup─┤◄─hold─┤
         │                   │
      上升沿               
                              
d  ───稳──────稳──────?──────
                   
q  ────────稳──────稳────────
           └─CLK-to-Q─┘
```

> **⚠️ 输入数据必须在「setup + hold」整个窗口内保持稳定！**

## 六、回到累加器：正确解法

### 6.1 ✅ 加入寄存器 + reset

```
         ┌───────┐     ┌──────────┐
  reset ─┤       │     │          │
         │  REG  ├────►│  Adder   ├──► S_i
  CLK ──►│       │  S  │          │
         └───────┘  i-1└──────────┘
              ▲            │
              └─── Xi ─────┘
```

**两个改进：**

| 改进 | 说明 |
|---|---|
| **① 新寄存器输入：`reset`** | **强制全零**，优先级高于 S_i 输入 |
| **② `S_{i-1}` 保存「第 i-1 次迭代的结果」** | **`S_i` 既是寄存器的输入，也是电路的输出** |

### 6.2 数值示例

| 时刻 | `S_{i-1}` | `X_i` | `S_i` |
|---|---|---|---|
| **i = 4** | 6 | 2 | **8** |
| **i = 5** | 8 | 3 | **11** |

### 6.3 ⚠️ 「暂时错」是正常的

> **`S_i` 在那个周期里会「暂时是错的」，但寄存器总是在时钟上升沿抓到正确的值。**

> **原因：组合逻辑是「连续传播」的，而寄存器只在边沿采样。**
> **中间过程的抖动不影响最终结果 —— 这正是同步设计的威力。**

## 七、同步系统的通用模型

> **一个同步系统 = 「组合逻辑块（CL block）」被「寄存器」隔开。**

| 规则 | 说明 |
|---|---|
| **寄存器可以背靠背** | 无中间组合逻辑 |
| **组合逻辑块可以背靠背** | 无中间寄存器 |
| **反馈可选** | 累加器需要，纯流水线不需要 |
| **时钟只连寄存器的时钟输入** | **不连组合逻辑！** |

> **寄存器作为时钟驱动元件，控制着组合逻辑块之间的信息流动。**

## 八、⭐ 电路时序约束

### 8.1 目标：高带宽电路

| 概念 | 说明 |
|---|---|
| **目标** | **每秒产生尽可能多的输出** |
| **手段** | 时钟跑得更快 → 状态元件变化更快 |
| **风险** | **跑太快的电路会输出不稳定（unstable）** |

> **目标：确定电路的「最高时钟频率」（等价于「最短时钟周期」）。**

### 8.2 最短时钟周期 = 关键路径

> **最短时钟周期 = 关键路径上的延迟。**

| 术语 | 定义 |
|---|---|
| **Critical Path（关键路径）** | **输入到输出之间「最坏情况（最大）延迟」的那条路径** |

**公式：**

```
Max Delay = Delay of Critical Path
          = CLK-to-Q Delay  +  CL Delay  +  Setup Time
```

> **时钟再快一点，电路就不稳定了！**

**所以：**

```
min_period = CLK-to-Q + worst-case CL delay + setup
max_frequency = 1 / min_period
```

### 8.3 ⭐ 第二个约束：Hold Time 违例

> **这是一个「反方向」的问题 —— 电路跑得「太快」也会坏！**

**条件：**

```
若  CLK-to-Q + 最快情况组合延迟  <  Hold Time
```

> **那么数据「冲得太快」—— 新数据赶在旧数据被「稳住」之前就到达了 → 保持时间不足 → 违例！**

**必须满足：**

```
CLK-to-Q + best-case combinational delay  ≥  hold time
```

**修复方法：**

> **在「最快路径」上故意加延迟 —— 例如串两个反相器（two inverters）。**

### 8.4 两个约束的对照

| 约束 | 公式 | 违反后果 | 修复 |
|---|---|---|---|
| **Setup（周期下限）** | `CLK-to-Q + worst CL + setup ≤ T` | 时钟太快 | 降低频率 / 切流水线 |
| **Hold（周期无关）** | `CLK-to-Q + best CL ≥ hold` | 路径太快 | **加延迟（串反相器）** |

> ⭐ **关键洞察：**
> **Setup 违例可以通过「降频」修复；**
> **Hold 违例「降频没用」，必须改电路！**

## 九、有限状态机（FSM）

### 9.1 核心定理

> **用「组合逻辑 + 寄存器」，任何 FSM 都能在硬件中实现。**

**方法：**

| 部件 | 作用 |
|---|---|
| **寄存器** | **记住「当前处于哪个状态」** |
| | 每个状态用唯一的 bit pattern 表示 |
| **组合逻辑** | **把「输入 + 当前状态（PS）」映射成「下一状态（NS）+ 输出」** |

### 9.2 例子：检测「连续 3 个 1」

> **FSM 目标：检测输入流中是否出现「连续的三个 1」。**

**状态设计：**

| 状态 | 含义 |
|---|---|
| `00` | 还没见到 1 |
| `01` | 见到 1 个 1 |
| `10` | 见到 2 个 1 |
| （`11` 不需要，因为一见到就直接输出 1）|

**状态转移表：**

| PS | input | NS | output |
|---|---|---|---|
| 00 | 0 | 00 | 0 |
| 00 | 1 | 01 | 0 |
| 01 | 0 | 00 | 0 |
| 01 | 1 | 10 | 0 |
| 10 | 0 | 00 | 0 |
| 10 | 1 | 00 | **1** |

> **每一行 = 一条边（transition）。**

### 9.3 硬件实现结构

```
              ┌─────────────┐
   input ────►│             │
              │  组合逻辑   ├──► output
   PS ───────►│  (NS & out) │
              └──────┬──────┘
                     │ NS
                ┌────▼────┐
                │  寄存器  │
                │  (状态)  │
                └────┬────┘
                     │
                     └──► PS（反馈）
```

> **组合逻辑算「下一状态 + 输出」，寄存器存「当前状态」。**
> **这就是「状态」在硬件里的物理形态。**

## 十、⭐ 流水线（Pipelining 的动机）

### 10.1 非流水线版本

```
输入 ──►[ Adder ]──►[ Shifter ]──► 输出
         └──── 一个时钟周期内完成 ────┘
```

> **时钟周期被「Adder + Shifter 的传播延迟」限制。**

### 10.2 流水线版本：中间插寄存器

```
输入 ──►[ Adder ]──►[REG]──►[ Shifter ]──► 输出
```

| 指标 | 变化 |
|---|---|
| **吞吐量（throughput）** | ✅ **更高 —— 每秒输出更多** |
| **延迟（latency）** | ⚠️ **更高 —— 单个结果出来更慢** |

> **「Shifter 在算当前结果的同时，Adder 已经在算下一个输入了。」**

### 10.3 课程原话

> **「我们现在只是「埋下种子」—— 寄存器能提高吞吐量，即使它增加了延迟。**
> **这就造出了一条流水线（pipeline）。几周后我们会回到这个话题。」**

> **这就是 L23–L25 的主题预告。**

## 十一、🎯 练习：最高时钟频率

### 11.1 题目

> **这个电路的最高时钟频率是多少？**

**给定：**

| 参数 | 值 |
|---|---|
| **CLK-to-Q delay** | **1 ns** |
| **Setup time** | **1 ns** |
| **Hold time** | **1 ns** |
| **AND 门延迟** | **1 ns** |

> **（假设所有未连接的输入都来自某个寄存器。）**

**选项：**

| 选项 | 频率 |
|---|---|
| A | 5 GHz |
| B | 200 MHz |
| C | 500 MHz |
| D | 1/7 GHz |
| E | **1/6 GHz** |
| F | 其他 |

### 11.2 解题方法

**Step 1：找出关键路径**

> **从「某个寄存器的输出」出发，经过尽可能多的组合逻辑，到达「某个寄存器的输入」。**

**Step 2：数延迟**

```
关键路径 = CLK-to-Q + (关键路径上所有门的延迟之和) + Setup
         = 1 ns + N × 1 ns + 1 ns
         = (N + 2) ns
```

**Step 3：算频率**

```
min_period = (N + 2) ns
max_freq   = 1 / ((N + 2) ns) = 1/(N+2) GHz
```

**若关键路径上有 4 个 AND 门：**

```
min_period = 1 + 4 + 1 = 6 ns
max_freq   = 1/6 GHz ≈ 167 MHz
```

> **答案 E：`1/6 GHz`。**

### 11.3 ⚠️ 常见错误

| 错误 | 说明 |
|---|---|
| **算进了 Hold time** | **Hold 不参与周期计算！** |
| **只算组合逻辑** | 漏掉 CLK-to-Q 和 Setup |
| **数错门的个数** | 要数「最长路径」不是「总门数」 |

## 十二、我的笔记与理解

### 12.1 为什么「反馈」不够，必须要寄存器

```
纯反馈：S = S + X
```

> **问题不是「逻辑错」，而是「时间上没有边界」。**
> **反馈回路会立刻形成「组合逻辑环路」—— 信号无限循环，永远不稳定。**

**寄存器做的事：**

> **在反馈回路上「插一个闸门」，让信号「一个周期前进一格」。**
> **这把「连续时间」离散化了 —— 这正是「同步」的本质。**

### 12.2 Setup 与 Hold 的对称性

```
        上升沿
          │
──────────┼──────────
   setup  │  hold
  ◄───────┤◄───────►
          │
   数据必须在这段窗口稳定
```

| 约束 | 关注 | 违反原因 |
|---|---|---|
| **Setup** | **数据来得太晚** | 路径太慢 / 时钟太快 |
| **Hold** | **数据来得太早** | 路径太快 |

> **「太慢」和「太快」都是 bug。**
> **这是硬件设计和软件设计最大的思维差异之一。**

### 12.3 CLK-to-Q 为什么不可省略

> **很多人第一次算频率时会忘记它。**

```
物理因果链：
上升沿 → FF 内部电路响应 → 输出变化
         └── 需要时间 ──┘
```

> **FF 不是「瞬时机」—— 输出不可能在边沿「同一瞬间」变。**
> **所以任何跨寄存器的路径，都必须从「输出真正变了」开始算。**

### 12.4 关键路径 ≠ 最长的那条画线

> **关键路径是「延迟最大」的路径，不是「门最多」的路径。**

> **如果不同门延迟不同（如 AND=1ns、加法器=3ns），
> 就要按「实际延迟」累加，而不是数门数。**

**本课简化假设「所有门都 1 ns」，是为了让练习可算。**

### 12.5 累加器「暂时错」的深层含义

> **`S_i` 在一个周期的中间时刻可能是错的。**

**这没问题，因为：**

| 事实 | 后果 |
|---|---|
| **寄存器只在边沿采样** | 中间值被忽略 |
| **时钟周期 ≥ 关键路径延迟** | 边沿到来时值已经稳定 |

> **这是同步设计「容错」的来源：**
> **只要在「采样时刻」正确即可，中间过程可以「乱」。**

### 12.6 FSM 在硬件里的「两段式」

```
状态寄存器（时序）  +  下一状态逻辑（组合）
     ↑ 存 PS              ↑ 算 NS
```

> **这个「寄存器 + 组合逻辑」的配对，就是所有控制逻辑的原型。**
> **L21 的「控制器」就是它的直接应用。**

### 12.7 流水线的本质：用延迟换吞吐

| 指标 | 非流水线 | 流水线 |
|---|---|---|
| **吞吐量** | 1 / (Adder+Shifter) | **1 / max(Adder, Shifter)** |
| **延迟** | Adder + Shifter | **加了寄存器开销** |
| **时钟频率** | 慢 | **快** |

> **关键洞察：切流水线不减少「工作总量」，只减少「每段的工作量」。**
> **所以最快的段决定频率 —— 这就是为什么流水线要「切得均匀」。**

### 12.8 与后续的衔接

| 讲次 | 关系 |
|---|---|
| **L19** | ALU：组合逻辑的集大成 |
| **L20–22** | Datapath + 控制器：FSM 的实战 |
| **L23–25** | 流水线：本讲预告的正式展开 |
| **L26–29** | 缓存：状态元件的另一种应用 |
