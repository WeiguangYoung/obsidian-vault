## 三、Load：`lw`

### 3.1 语义

```asm
lw rd, imm(rs1)
```

| 元件 | 动作 |
|---|---|
| **DMEM** | **在地址 `addr` 读一个字** |
| **RegFile** | **`Reg[rs1]` 读；`Reg[rd]` 写** |
| **PC** | `PC = PC + 4` |

**地址计算：**

```
addr = R[rs1] + 符号扩展后的 imm
```

**编码（I-Type，opcode=LOAD=0000011，funct3=010）：**
```
31        20 19    15 14   12 11    7 6      0
imm[11:0]     rs1    010     rd    0000011
```

### 3.2 需要新增的硬件

| 新增 | 作用 |
|---|---|
| **DMEM 接入** | `addr` ← ALU 输出 |
| **`mem` 数据线** | DMEM 的 `rdata` 输出 |
| **`WBSel`（写回选择）** | **选择写回 RegFile 的值** |
| **`MemRW`** | 设为 **`Read`** |

### 3.3 ⭐ WBSel：新增的 MUX

> **写回 RegFile 的值有两个来源：**

| WBSel | 来源 | 用于 |
|---|---|---|
| **0** | **`mem`（DMEM 读出的值）** | **load** ✅ |
| **1** | **`alu`（ALU 结果）** | **add / sub / addi** |

> **L21 后面会扩展到 3 输入（加 PC+4 给 jal/jalr）和 4 输入（给 lui）。**

### 3.4 ⭐ load 用满了全部五个阶段

```
① IF   取指令
② ID   读 R[rs1]
③ EX   ALU 算 addr = R[rs1] + imm
④ MEM  按 addr 读 DMEM
⑤ WB   把 mem 写回 rd
```

> ⭐ **「Load 是唯一一条用满全部五个阶段的指令」** ——
> **这也是单周期 CPU 周期长度的决定者（L22 会算）。**

### 3.5 控制信号

| 信号 | 值 |
|---|---|
| **ImmSel** | **I** |
| **BSel** | **1**（用 imm）|
| **ALUSel** | **Add** |
| **MemRW** | **Read(0)** |
| **RegWEn** | **1** |
| **WBSel** | **0**（选 mem）|

### 3.6 lb / lh / lbu / lhu（参考，Proj3）

| 指令 | funct3 |
|---|---|
| **lb** | 000 |
| **lh** | 001 |
| **lw** | 010 |
| **lbu** | 100 |
| **lhu** | 101 |

> **实现方式（三条）：**
> 1. **从内存读 32 位字**
> 2. **加额外逻辑取出正确的字节/半字**
> 3. **符号扩展或零扩展到 32 位，再写进 RegFile**
>
> **「可以用 MUX + 少量门实现。」**

## 四、Store：`sw`

### 4.1 语义

```asm
sw rs2, imm(rs1)
```

| 元件 | 动作 |
|---|---|
| **DMEM** | **把 `R[rs2]` 写到地址 `addr` 的字** |
| **RegFile** | **`R[rs1]`（基址）、`R[rs2]`（要存的值）都是读** |
| **PC** | `PC = PC + 4` |

**编码（S-Type，opcode=STORE=0100011，funct3=010）：**
```
31        25 24    20 19    15 14   12 11       7 6      0
imm[11:5]    rs2     rs1    010    imm[4:0]   0100011
```

### 4.2 需要新增的硬件

| 新增 | 作用 |
|---|---|
| **`dataW` ← `R[rs2]`** | **DMEM 的写数据直接来自 rs2** |
| **`MemRW = Write`** | 启动写 |
| **`ImmSel = S`** | 用 S 型立即数 |

### 4.3 ⭐ 关键：不写 RegFile

| 信号 | 值 | 原因 |
|---|---|---|
| **`RegWEn`** | **0** | **store 不产生结果** |
| **`WBSel`** | **`*`（don't care）** | **因为 `RegWEn=0`，写回路径无关** |

> ⭐ **「`RegWEn=0` 意味着不回写 RegFile，所以 `WBSel` 的值是 don't care（*）。」**

> **这是硬件设计的常见现象：某个信号在特定指令下「无所谓」，标 `*` 即可，控制逻辑可以随便给。**

### 4.4 控制信号

| 信号 | 值 |
|---|---|
| **ImmSel** | **S** |
| **BSel** | **1**（用 imm）|
| **ALUSel** | **Add** |
| **MemRW** | **Write(1)** |
| **RegWEn** | **0** |
| **WBSel** | **\*** |

## 五、B-Type：分支

### 5.1 语义

```asm
beq rs1, rs2, Label
```

| 元件 | 动作 |
|---|---|
| **RegFile** | **只读 `R[rs1]`、`R[rs2]`（用于比较）** |
| **PC** | **若分支成立：`PC = PC + imm`** |
| | **否则：`PC = PC + 4`** |

**编码（B-Type，opcode=BRANCH=1100011）：**
```
31            25 24    20 19    15 14   12 11           7 6      0
imm[12|10:5]    rs2     rs1   funct3  imm[4:1|11]   1100011
```

### 5.2 ⚠️ 核心矛盾：ALU 只能做一件事

> **分支需要同时做两件事：**
> 1. **比较 `R[rs1]` 和 `R[rs2]`**
> 2. **算 `PC + imm`**

> ⚠️ **「同一时钟周期内只有一个 ALU 可访问。需要更多硬件！！」**

### 5.3 解法：新增两个块

| 新块 | 作用 |
|---|---|
| **Branch Comp.（分支比较器）** | **比较 `R[rs1]` 和 `R[rs2]`，输出 `BrEq`、`BrLT`** |
| **PC 输入的 `+4` 加法器（已存在）** | **`pc+4`** |
| **ALU 改用来算 `PC + imm`** | **`ASel=1` 选 PC，`BSel=1` 选 imm** |
| **PCSel（新增 MUX）** | **选 `pc+4` 还是 `alu`** |

### 5.4 ⭐ Branch Comp. 的接口

| 项 | 说明 |
|---|---|
| **输入 A** | `R[rs1]`（datapath 的 A 总线）|
| **输入 B** | `R[rs2]`（datapath 的 B 总线）|
| **输入 BrUn** | **「Branch Unsigned」控制位** |
| **输出 BrEq** | **`1` 若 `A == B`** |
| **输出 BrLT** | **`1` 若 `A < B`** |
| | **`BrUn=1` 时无符号比较，否则有符号** |

### 5.5 ⭐ 分支判定的逻辑

> **控制逻辑用 `BrLT`/`BrEq` 决定 `PCSel`：**

| 指令 | 条件 | PCSel |
|---|---|---|
| **`beq`** | `BrEq = 1` | **taken** |
| **`bne`** | `BrEq = 0` | **taken** |
| **`blt`** | **`BrLT=1` 且 `BrEq=0`** | **taken** |
| **`bge`** | **`BrLT=0`（即 `not(A<B)` → `A≥B`）** | **taken** |
| **`bltu`** | `BrUn=1` 时的 `BrLT=1` 且 `BrEq=0` | taken |
| **`bgeu`** | `BrUn=1` 时的 `BrLT=0` | taken |

> ⭐ **`bge` 的实现技巧：`A ≥ B` 等价于 `¬(A < B)` ——**
> **「如果 `BrLT=0`，就 taken」。不需要单独的比较器。**

### 5.6 ⭐ `BrUn` 怎么算出来的

> **最简示例：**

```
BrUn = inst[13] · Branch
```

**为什么？**

> **`inst[13]` 是 `funct3` 的 bit[1]。**

| 指令 | funct3 | `inst[13]` | 无符号？ |
|---|---|---|---|
| **blt** | 100 | **0** | 有符号 |
| **bge** | 101 | **0** | 有符号 |
| **bltu** | **110** | **1** | **无符号** ✅ |
| **bgeu** | **111** | **1** | **无符号** ✅ |

> **`funct3` 的 bit[1] 恰好就是「有符号/无符号」开关。**

> ⭐ **这和 L13 学过的「load 的 funct3 bit[2]」是同一类设计：**编码位被设计成能直接当控制信号用。

### 5.7 控制信号

| 信号 | 值 |
|---|---|
| **ImmSel** | **B** |
| **ASel** | **1**（选 PC）|
| **BSel** | **1**（选 imm）|
| **ALUSel** | **Add** |
| **RegWEn** | **0**（分支不写寄存器）|
| **MemRW** | **Read** |
| **WBSel** | **\*** |

> ⚠️ **注意：`MemRW=Read` 只是「不做写」，不是真的要读内存 —— 反正 `RegWEn=0`，读了也不用。**

## 六、⭐ 立即数生成块（Imm Gen）

### 6.1 设计目标

> **一个块，支持 I / S / B / J / U 五种格式。**

**用 `ImmSel` 选择格式。**

### 6.2 五种格式的立即数位分布

| 格式 | 立即数的位在指令的哪里 |
|---|---|
| **I** | `imm[11:0]` = `inst[31:20]` |
| **S** | `imm[11:5]` = `inst[31:25]`；`imm[4:0]` = `inst[11:7]` |
| **B** | `imm[12]`=`inst[31]`；`imm[10:5]`=`inst[30:25]`；`imm[4:1]`=`inst[11:8]`；`imm[11]`=`inst[7]` |
| **J** | `imm[20]`=`inst[31]`；`imm[10:1]`=`inst[30:21]`；`imm[11]`=`inst[20]`；`imm[19:12]`=`inst[19:12]` |
| **U** | `imm[31:12]` = `inst[31:12]` |

### 6.3 ⭐ 统一的结构

> **注意到一个共通规律：**

```
最高位（符号位）= 永远是 inst[31]
低 12 位        = 由 MUX 从不同位置挑
高 20 位        = 全部填符号位（符号扩展）
```

**所以：**

| 部件 | 作用 |
|---|---|
| **一个 12 位的 MUX** | **`ImmSel` 控制，从指令的不同位段拼出 `imm[11:0]`** |
| **符号扩展** | **`imm[31:12]` 全接 `inst[31]`** |

### 6.4 逐位的 MUX

> **`imm[11]` 的选择：**

| ImmSel | 来源 |
|---|---|
| **I** | `inst[31]` |
| **S** | `inst[31]` |
| **B** | **`inst[7]`** ⚠️ 唯一特别 |
| **J** | **`inst[20]`** ⚠️ 唯一特别 |
| **U** | — |

> **`imm[10:5]` 的选择：**

| ImmSel | 来源 |
|---|---|
| I | `inst[30:25]` |
| S | `inst[30:25]` |
| B | `inst[30:25]` |
| **J** | **`inst[30:25]`** ← ⚠️ 但目标是 `imm[10:5]`，实际是 `inst[30:21]` 的一部分 |

> **`imm[4:0]` 的选择：**

| ImmSel | 来源 |
|---|---|
| I | `inst[24:20]`（**注意：I 型这里是 rd 位！**）|
| S | `inst[11:7]` |
| B | **`inst[11:8] + 0`（`imm[0]` 恒为 0）** |
| J | `inst[24:20]` |

> ⚠️ **I 型的 `imm[4:0]` 来自 `inst[24:20]`（即 rd 字段位置）—— 这就是为什么 I 型"立即数 12 位正好占 rs2 的位置"。**

### 6.5 ⭐ 三条捷径观察

| 观察 | 说明 |
|---|---|
| **① `inst[31]` 永远是符号位** | 所有格式立即数的最高位 |
| **② `imm[0]` 恒为 0（B/J 型）** | 半字对齐，不用存 |
| **③ 大部分位段位置重叠** | I/S/B 的 `imm[10:5]` 都来自 `inst[30:25]` |

> **正因为这些「重叠」，Imm Gen 才不需要 5 个独立的 MUX —— 一个多路 MUX 就够。**

## 七、J-Type：`jal`

### 7.1 语义

```asm
jal rd, Label

PC = PC + imm        (无条件 PC 相对跳转)
rd = PC + 4          (保存返回地址)
```

| 元件 | 动作 |
|---|---|
| **PC** | `PC = PC + imm` |
| **RegFile** | **`rd = PC + 4`（保存返回地址）** |

**编码（J-Type，opcode=1101111）：**
```
31                      12 11    7 6      0
imm[20|10:5|4:1|11|19:12]   rd   1101111
```

### 7.2 需要的改动

| 改动 | 说明 |
|---|---|
| **`WBSel` 从 2 输入扩成 3 输入** | **新增 `pc+4` 作为第三路** |
| **ImmSel 支持 J** | **20 位半字 → 字节偏移** |
| **`ASel=1`、`BSel=1`** | **ALU 算 `PC + imm`** |
| **`PCSel = taken(1)`** | **无条件跳转** |

**WBSel 三路：**

| WBSel | 来源 |
|---|---|
| **0** | **`mem`** |
| **1** | **`alu`** |
| **2** | **`pc+4`** ✅ 新增 |

### 7.3 控制信号

| 信号 | 值 |
|---|---|
| **ImmSel** | **J** |
| **ASel** | **1**（选 PC）|
| **BSel** | **1**（选 imm）|
| **ALUSel** | **Add** |
| **RegWEn** | **1** |
| **MemRW** | **Read** |
| **WBSel** | **2**（选 pc+4）|
| **PCSel** | **taken(1)** |

> ⚠️ **「对 JAL 来说，分支信号是 don't care（\*）。」**

## 八、`jalr`

### 8.1 语义

```asm
jalr rd, rs1, imm

PC = R[rs1] + imm      (绝对寻址)
R[rd] = PC + 4
```

**编码（I-Type，opcode=JALR=1100111）：**
```
31        20 19    15 14   12 11    7 6      0
imm[11:0]     rs1    000     rd    1100111
```

### 8.2 需要的改动

| 改动 | 说明 |
|---|---|
| **`ASel=0`** | **ALU 的 A 输入改用 `R[rs1]` 而不是 PC** |
| **`ImmSel=I`** | **12 位立即数** |
| **`BSel=1`** | 选 imm |
| **`PCSel=taken`** | 跳转 |
| **`WBSel=2`** | 写 `pc+4` |

### 8.3 ⭐ 关键观察

> **「Control 的 `ImmSel` 是基于「指令格式」，而不是「指令」。迄今为止：I、S、B、J。」**

> **这条规则很重要：`addi`、`lw`、`jalr` 的 `ImmSel` 全都是 `I` ——**
> **因为它们的「格式」相同，立即数生成方式一样。**

## 九、U-Type：`lui` / `auipc`

### 9.1 两条指令

| 指令 | 语义 |
|---|---|
| **`lui rd, imm`** | **`R[rd] = imm`**（imm 是高 20 位，低 12 位补 0）|
| **`auipc rd, imm`** | **`R[rd] = PC + imm`** |

**编码（U-Type，opcode：lui=`0110111`，auipc=`0010111`）：**
```
31              12 11    7 6      0
imm[31:12]         rd    opcode
```

### 9.2 两条指令的差异

| 指令 | ALUSel | ASel | 结果 |
|---|---|---|---|
| **`lui`** | **`B`** | `*` | **`alu = imm`（直接透传 B）** |
| **`auipc`** | **`Add`** | **`1`（PC）** | **`alu = PC + imm`** |

> ⭐ **`lui` 用一个「直通」的 ALU 操作 `B` ——**
> **ALU 不做任何运算，直接把 B 输入送到输出。**

| 信号 | lui | auipc |
|---|---|---|
| **ImmSel** | **U** | **U** |
| **ASel** | **\*** | **1** |
| **BSel** | **1** | **1** |
| **ALUSel** | **B** | **Add** |
| **RegWEn** | **1** | **1** |
| **MemRW** | **Read** | **Read** |
| **WBSel** | **1**（ALU）| **1**（ALU）|
| **PCSel** | **not taken(0)** | **not taken(0)** |

## 十一、我的笔记与理解

### 11.1 「选择信号来自指令格式，不是指令」

> **这句 L21 的原话极重要：**

```
ImmSel 由「格式」决定：
  I 格式 → addi, lw, jalr
  S 格式 → sw
  B 格式 → beq, bne, blt, bge, bltu, bgeu
  J 格式 → jal
  U 格式 → lui, auipc
```

> ⭐ **所以控制逻辑只需看 `opcode`（2 bit 差别）就能定 `ImmSel` ——**
> **不需要分辨具体是哪条指令。**

### 11.2 Branch Comp. 为什么必须独立

> **关键约束：「同一周期内只能访问一个 ALU」。**

**如果复用 ALU 做比较：**

```
时刻 1：ALU 比较 A、B  → 得到 BrEq/BrLT
时刻 2：ALU 算 PC+imm  → 得到目标地址
```

> **两个时刻不能塞进一个周期（否则周期变两倍长）。**

> ⭐ **解法：加一个专用的、极简单的比较器（只做 == 和 <）。**
> **这比「把 ALU 做两遍」便宜得多。**

### 11.3 `BrUn = inst[13] · Branch` 的精妙

> **一个与门，就把「无符号/有符号」开关做出来了。**

```
inst[13] = funct3 的 bit[1]
Branch   = opcode 是 1100011
```

> ⭐ **这是 RISC-V 编码设计的「前瞻性」：**
> **把「语义相关的位」放在固定位置，让控制逻辑能「用最少的门」解码。**

> **对比 MIPS：`slt`/`sltu` 也要类似处理，但 RISC-V 更规整。**

### 11.4 don't care（\*）的价值

> **控制表里大量 `*`。这不是偷懒，是优化。**

| 场景 | `*` 的价值 |
|---|---|
| **sw 的 WBSel** | `RegWEn=0`，写回路径根本没启用 → 随便给节省解码逻辑 |
| **beq 的 BrUn** | 相等比较不涉及大小 → 无所谓 |
| **jal 的 BrEq/BrLT** | 跳转无条件 → 分支判定无关 |

> ⭐ **「don't care 越多的指令，控制逻辑越简单。」**
> **这也是为什么 L22 能用 ROM 实现控制 —— 很多位根本不用算。**

### 11.5 `lui` 用 ALUSel=B 的巧妙

> **`lui` 需要 `R[rd] = imm`，不做任何运算。**

**朴素做法：**
```
WBSel 加第四路：imm 直通 → RegFile
```

**本课做法：**
```
ALUSel = B   →  ALU 输出 = B 输入 = imm
```

> **复用已有路径（ALU 输出 → WBSel=ALU → RegFile），**
> **只给 ALU 加一个「直通」操作，省了一条数据线。**

> ⭐ **这就是「用 ALU 操作码扩展」代替「加数据通路」的典型权衡。**

### 11.6 `bge` = `not(blt)` 的技巧

> **`A ≥ B` 等价于 `¬(A < B)`。**

| 指令 | PCSel = taken 的条件 |
|---|---|
| **blt** | `BrLT = 1` **且** `BrEq = 0` |
| **bge** | **`BrLT = 0`** |

> ⭐ **`bge` 不需要「大于等于比较器」—— 只要「小于比较器取反」即可。**

> **同样：`bgeu` = `not(bltu)`，只是 `BrUn=1`。**

### 11.7 立即数生成的「一个 MUX 搞定」

> **五种格式看起来完全不同，但用三条观察就能统一：**

```
观察 1: inst[31] 永远是符号位
观察 2: imm[0] 恒为 0（B/J）
观察 3: 大部分位段在原位重叠
```

**结果：**

| 部件 | 数量 |
|---|---|
| **12 位宽的 MUX（ImmSel 控制）** | **1 个** |
| **符号扩展连线** | **1 组** |

> ⭐ **不需要 5 个独立的立即数生成器。**

> **这也解释了 L14 讲的「bit swirling」为什么那样设计 ——**
> **正是为了让「一个 MUX 能覆盖所有格式」。**

### 11.8 与 L14 的呼应

| L14 讲的 | L21 的用途 |
|---|---|
| **B 型 `imm[0]` 恒为 0** | **Imm Gen 的 `imm[0]` 直接接 0** |
| **J 型 `imm[19:12]` 在原位** | **Imm Gen 里这一段「直通」** |
| **`inst[31]` 是符号位** | **所有格式的符号扩展源** |
| **立即数位「旋转」** | **为了让 MUX 的选择逻辑规整** |

> ⭐ **L14 当时说「硬件成本考虑」—— L21 给出了具体答案：**
> **bit swirling 让「一个多路 MUX」就能覆盖 I/S/B/J/U 五种格式。**
