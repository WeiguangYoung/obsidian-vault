## 一、机器语言与存储程序计算机

### 1.1 历史大事件：Stored-Program Computer

> **存储程序计算机（又称「冯·诺依曼」计算机）** 得名于广泛流传的技术报告。
> 基于 1944 年 EDVAC 的讨论（Eckert、Mauchly）；图灵和 Zuse 更早预见到。

**核心突破：**

- **指令被表示为比特模式（即数字）**
- **因此整个程序可以像数据一样被存进内存、读写**
- ** reprogramming 从「重新接线（几天）」变成「读入新程序（几秒）」**

### 1.2 快速 CS 史

| 机器 | 年份 | 特征 |
|---|---|---|
| **EDSAC**（Cambridge） | 1949 | 第一台通用存储程序电子计算机<br>17 位字（35 位双字）、二进制补码<br>内存：**512 字**；乘法：**6 ms**；**支持子程序** |
| **IBM 701** | 1952 | IBM 首台商用科学计算机<br>36 位符号-幅值字<br>内存：**2048 字**（真空管）<br>乘法：**0.5 ms**<br>两个程序员可见寄存器：**累加器**、**乘商寄存器** |

> **对比今天的乘法是纳秒级 —— 快了一千万倍。**

### 1.3 存储程序计算机的四个核心概念

| 概念 | 说明 |
|---|---|
| **① 一切都有内存地址** | 指令和数据字都有 |
| **② 分支和跳转用指令内存地址** | PC 指向当前指令 |
| **③ PC 本质上是指向内存的指针** | Intel 称其为 IP（Instruction Pointer）|
| **④ 程序以二进制形式分发** | 即汇编后的机器码，绑定特定指令集 |

## 二、RV32I 的六个指令格式

### 2.1 核心设计

> **RV32I 指令：32 位宽，6 种格式。**

| 特点 | 说明 |
|---|---|
| **固定长度** | 所有指令都是 **32 位**，和寄存器、内存字一样 |
| **统一** | RV32、RV64、RV128 都用 32 位指令 |
| **六种格式** | 32 位字被切成字段，每个字段告诉处理器一件事 |

**六种格式：**

```
R-Type  寄存器-寄存器（算术）
I-Type  寄存器-立即数（算术、load、jalr）
S-Type  存储（store）
B-Type  分支（branch）
U-Type  高位立即数（lui、auipc）
J-Type  跳转（jal）
```

### 2.2 例子

```asm
add x18, x19, x10
        ↓
00000000101010011000100100110011   ← 机器码
```

> **计算机只懂比特。**

## 三、R-Type 指令格式

### 3.1 布局

```
 31        25 24    20 19    15 14    12 11      7 6        0
┌───────────┬────────┬────────┬────────┬──────────┬──────────┐
│  funct7   │  rs2   │  rs1   │ funct3 │    rd    │  opcode  │
│   7 bit   │ 5 bit  │ 5 bit  │ 3 bit  │  5 bit   │  7 bit   │
└───────────┴────────┴────────┴────────┴──────────┴──────────┘
```

**适用于：所有寄存器-寄存器算术指令**（`add`、`sub`、`xor`、`sll` 等）

### 3.2 三个寄存器字段

| 字段 | 位置 | 含义 |
|---|---|---|
| **`rs2`** | bits 24:20 | **源寄存器 2**（第二个操作数）|
| **`rs1`** | bits 19:15 | **源寄存器 1**（第一个操作数）|
| **`rd`** | bits 11:7 | **目的寄存器**（存结果）|

> **每个都是 5 位无符号整数 `[0, 31]`，对应寄存器编号 x0-x31。**

**例子：`a0` → `x10` → `0b01010`**

### 3.3 三个控制字段

| 字段 | 位数 | 作用 |
|---|---|---|
| **`opcode`** | 7 | **用哪种指令格式**（R-type 固定 `0110011`）|
| **`funct3`** | 3 | R 格式内**具体做什么操作** |
| **`funct7`** | 7 | 进一步区分 |

> **「为什么不用一个 17 位的字段来简化？」** —— 课程留了这个问题，答案是**硬件解码更简单**。

### 3.4 编码例子：`add x18 x19 x10`

**第 1 步：查 opcode / funct3 / funct7**

```
opcode = 0110011   （R-Type）
funct3 = 000       （add）
funct7 = 0000000   （add）
```

**第 2 步：翻译寄存器**

```
rd  = x18 = 10010
rs1 = x19 = 10011
rs2 = x10 = 01010
```

**第 3 步：拼接**

```
funct7  rs2   rs1   funct3 rd    opcode
0000000 01010 10011 000    10010 0110011
```

### 3.5 R-Type 全部 10 条指令

| 指令 | funct7 | funct3 | 说明 |
|---|---|---|---|
| **add** | 0000000 | 000 | |
| **sub** | **0100000** | 000 | 与 add 同 funct3，靠 funct7 区分 |
| **and** | 0000000 | 111 | |
| **or** | 0000000 | 110 | |
| **xor** | 0000000 | 100 | |
| **sll** | 0000000 | 001 | |
| **srl** | 0000000 | 101 | |
| **sra** | 0100000 | 101 | 与 srl 同 funct3，靠 funct7 区分 |
| **slt** | 0000000 | 010 | set less than |
| **sltu** | 0000000 | 011 | set less than unsigned |

**统计：**

- **opcode：只有 1 个**（`0110011`）
- **funct3：8 个不同值**
- **funct7：2 个不同值**（`0000000` 和 `0100000`）

> **10 条指令用 8 个 funct3 × 2 个 funct7 组合出来 —— 这是「编码压缩」，用少量位区分大量操作。**

### 3.6 `sub` 和 `sra` 的巧妙之处

```
add: funct7=0000000, funct3=000
sub: funct7=0100000, funct3=000
```

> **只差 funct7 的最高位**（0 vs 1）。
>
> 硬件实现上，**`sub` 就是「对 rs2 取补码再 add」** ——
> **这一位直接控制「要不要反转 rs2 并加 1」。**

## 四、I-Type 指令格式

### 4.1 布局

```
 31            20 19    15 14    12 11      7 6        0
┌────────────────┬────────┬────────┬──────────┬──────────┐
│   imm[11:0]    │  rs1   │ funct3 │    rd    │  opcode  │
│    12 bit      │ 5 bit  │ 3 bit  │  5 bit   │  7 bit   │
└────────────────┴────────┴────────┴──────────┴──────────┘
```

**适用于：**

- **寄存器-立即数算术**（`addi`、`xori` 等）
- **Load 指令**（`lw`、`lb`、`lbu`...）
- **`jalr`**

### 4.2 立即数字段

> **立即数（Immediates）是在指令里直接写明的整数。**

| 项 | 说明 |
|---|---|
| **宽度** | **12 位** |
| **范围** | **`[-2048, +2047]`**（有符号补码）|
| **使用时** | **CPU 先符号扩展到 32 位**再参与运算 |

> **「超过 12 位的立即数怎么办？」** —— 见 U-Type（L14）。

### 4.3 为什么不用 R-Type 加立即数

**假设把 `rs2` 换成立即数：**

> **5 位只能表示 32 个立即数值** —— **但立即数常常大得多！**

**所以必须单独设计 I-Type，给立即数 12 位。**

### 4.4 编码例子：`addi x15 x1 -50`

**立即数 -50 的补码：**

```
+50 = 0b 0…0110010
取反 = 0b 1…1001101
加 1 = 0b 1…1001110
12 位截取 = 1111 1100 1110
```

**字段：**

```
imm[11:0]   rs1    funct3  rd     opcode
111111001110 00001 000     01111  0010011
```

| 字段 | 值 |
|---|---|
| opcode | `0010011`（I-Type 算术）|
| funct3 | `000`（add）|
| rs1 | `00001`（x1）|
| rd | `01111`（x15）|

### 4.5 I-Type 的 opcode 分支

| 用途 | opcode |
|---|---|
| **算术**（addi 等） | `0010011` |
| **Load**（lw 等） | `0000011` |
| **jalr** | `1100111` |
| **其他**（ecall/ebreak） | `1110011` |

### 4.6 funct3 在 I-Type 与 R-Type 的一致性

> **I-Type 算术指令的 funct3 与对应 R-Type 完全相同：**

| 指令 | funct3 | 对应 R-Type |
|---|---|---|
| `addi` | 000 | `add` |
| `andi` | 111 | `and` |
| `ori` | 110 | `or` |
| `xori` | 100 | `xor` |
| `slli` | 001 | `sll` |
| `srli` | 101 | `srl` |
| `srai` | 101 | `sra` |

> ⚠️ **没有 `subi`** —— 因为用 `addi` 加负数就行。

### 4.7 I※-Type：移位立即数的特殊情况

> **移位指令的立即数只需要 5 位！**

**为什么？**

> **`imm[4:0]`：最大移位 32 位** ——
> **再大就会把所有数据都移出寄存器了。**

**结构：**

```
 31     25 24    20 19    15 14    12 11      7 6      0
┌──────────┬────────┬────────┬────────┬────────┬───────┐
│ imm[11:5]│ imm[4:0]│  rs1  │ funct3 │   rd   │opcode │
│  (funct7)│ (shift) │       │        │        │       │
└──────────┴────────┴────────┴────────┴────────┴───────┘
```

> **`imm[11:5]` 实际充当了 R-Type 里 `funct7` 的角色** ——
> **用来区分 `slli`（0000000）和 `srai`（0100000）。**

### 4.8 Load 也用 I-Type（关键洞察）

```asm
loadop rd, imm(rs1)
```

| 字段 | 对应 | 说明 |
|---|---|---|
| **`imm[11:0]`** | **offset（偏移）** | 加到基址形成内存地址 |
| **`rs1`** | **base（基址）** | load 的基地址 |
| **`rd`** | **destination** | 从内存读取到的值 |

**核心公式：**

```
Load address = (Base Register) + (Immediate Offset)
```

> **「为什么 Load 用 I-Type？」**
> **因为「计算内存地址」本质就是一个「加法立即数」操作！**
> **顺带说：`sw` 用 S-Type，是因为它要存的是寄存器（rs2），不是读进寄存器。**

### 4.9 S-Type 的种子：为什么 `sw` 不同

```
lw rd, imm(rs1)      ← 需要：rd（目的地）+ rs1（基址）+ imm
sw rs2, imm(rs1)     ← 需要：rs2（数据）+ rs1（基址）+ imm
```

> **`lw` 的「目的地」是寄存器，`sw` 的「目的地」是内存！**
> **所以 `sw` 需要 `rs2` 而不是 `rd` —— 字段布局必须不同。**

### 4.10 Load 编码例子：`lw x14 8(x2)`

```
imm[11:0]   rs1    funct3  rd     opcode
000000001000 00010 010     01110  0000011
```

| 字段 | 值 | 说明 |
|---|---|---|
| imm | `+8` | offset |
| rs1 | `00010` | x2（sp，base）|
| funct3 | `010` | lw |
| rd | `01110` | x14 |
| opcode | `0000011` | I-Type load |

### 4.11 Load / jalr 的 funct3 表

| 指令 | funct3 | opcode |
|---|---|---|
| **lb** | 000 | 0000011 |
| **lbh** | 100 | 0000011 |
| **lh** | 001 | 0000011 |
| **lhu** | 101 | 0000011 |
| **lw** | 010 | 0000011 |
| **jalr** | 000 | 1100111 |

> **funct3 的设计规律：bit[2:0] 编码「数据大小 + 有无符号」**
> ```
> 000 = 1 字节，有符号
> 100 = 1 字节，无符号
> 001 = 2 字节，有符号
> 101 = 2 字节，无符号
> 010 = 4 字节
> ```
> **最高位 = 1 表示「无符号」！**

## 五、S-Type 指令格式

### 5.1 布局（立即数被拆成两段！）

```
 31        25 24    20 19    15 14    12 11      7 6      0
┌───────────┬────────┬────────┬──────────┬────────┬───────┐
│ imm[11:5] │  rs2   │  rs1   │  funct3  │imm[4:0]│opcode │
│   7 bit   │ 5 bit  │ 5 bit  │  3 bit   │ 5 bit  │ 7 bit │
└───────────┴────────┴────────┴──────────┴────────┴───────┘
```

**适用于：`sw`、`sh`、`sb`（store 指令）**

### 5.2 为什么拆开立即数

> **「RISC-V ISA 设计优先保持寄存器字段在相同位置。」**

**对比三种格式的寄存器位置：**

```
R-Type:  rs2[24:20]   rs1[19:15]   funct3[14:12]   rd[11:7]
I-Type:  imm[31:20]   rs1[19:15]   funct3[14:12]   rd[11:7]
S-Type:  imm[31:25]   rs2[24:20]  rs1[19:15]   funct3[14:12]   imm[4:0]
                     ↑ 相同位置！  ↑ 相同位置！  ↑ 相同位置！
```

> **关键：`rs1`、`rs2`、`funct3` 在所有格式里位置固定。**
> **这样硬件**不用先判断格式**就能读寄存器。**
>
> **代价：立即数被劈成两半。**

### 5.3 Store 不需要扩展

> **Store 只写入指定字节，所以没有符号/零扩展的问题。**

**funct3 与 Load 相同：**

| 指令 | funct3 |
|---|---|
| `sb` | 000 |
| `sh` | 001 |
| `sw` | 010 |

### 5.4 编码例子：`sw x14 36(x2)`

**立即数 36 = `0b000000100100`（12 位）**

拆成：
- `imm[11:5]` = `0000001`（高 7 位）
- `imm[4:0]` = `00100`（低 5 位）

**字段：**

```
imm[11:5]  rs2    rs1    funct3  imm[4:0]  opcode
0000001    01110  00010  010     00100     0100011
```

| 字段 | 值 |
|---|---|
| rs2 | `01110`（x14，source）|
| rs1 | `00010`（x2，base）|
| funct3 | `010`（sw）|
| opcode | `0100011` |

## 六、反汇编练习

### 6.1 题目

把 `0x01B3 42B3` 翻译成 RISC-V 指令。

### 6.2 解答步骤

**第 1 步：转二进制**

```
0x01B3 42B3
= 0000 0001 1011 0011 0100 0010 1011 0011
```

**第 2 步：看 opcode（最低 7 位）**

```
… 0011 0011   →  opcode = 0110011 = R-Type
```

**第 3 步：切字段**

```
31      25 24    20 19    15 14    12 11    7 6      0
0000000     11011  00110  100     00101  0110011
funct7      rs2    rs1    funct3  rd     opcode
```

| 字段 | 二进制 | 十进制 | 含义 |
|---|---|---|---|
| funct7 | 0000000 | 0 | |
| rs2 | 11011 | 27 | **s11**（x27）|
| rs1 | 00110 | 6 | **t1**（x6）|
| funct3 | 100 | 4 | **xor** |
| rd | 00101 | 5 | **t0**（x5）|

**答案：`xor t0, t1, s11`** ✅

### 6.3 反汇编流程总结

```
十六进制 → 二进制 → 取 opcode → 定格式 → 切字段 → 查表定指令 → 翻译寄存器号
```

## 七、编码练习

### 7.1 题目

把 `add x4 x3 x2` 编码成十六进制。

### 7.2 解答

**查表：**

```
opcode = 0110011
funct3 = 000
funct7 = 0000000
```

**寄存器：**

```
rd  = x4  = 00100  (4)
rs1 = x3  = 00011  (3)
rs2 = x2  = 00010  (2)
```

**拼接：**

```
0000000 00010 00011 000 00100 0110011
funct7  rs2   rs1   f3  rd    opcode
```

**转十六进制（每 4 位一组）：**

```
0000 0000 0010 0001 1000 0010 1011 0011
 0    0    2    1    8    2    B    3
```

**答案：`0x0021 82B3`** ✅

### 7.3 常见错误

> **不要忘记 opcode 低位顺序！**
> **也可能把 `rd` 和 `rs1` 位置搞混** ——
> **记住：rd 在 bits 11:7，紧邻 funct3 之后。**

## 八、本讲总结（课程原话）

- **简化对 RISC-V 有效：指令与数据字同大小（32 位），因此用同一块内存。**
  - **计算机程序就是这些 32 位数字的序列。**
- **RISC-V 机器语言指令格式：**

```
R-Type:  funct7 | rs2 | rs1 | funct3 | rd    | opcode
I-Type:  imm[11:0]    | rs1 | funct3 | rd    | opcode
S-Type:  imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode
```

## 九、我的笔记与理解

### 9.1 本讲的三大设计智慧

| 设计 | 直觉上 | 实际原因 |
|---|---|---|
| **固定 32 位长度** | 浪费空间 | **取指令简单**（pc 永远 +4）|
| **字段位置固定** | 立即数被劈开很怪 | **硬件不用先解码就能读寄存器** |
| **opcode + funct3 + funct7 三级** | 复杂 | **少量位编码大量操作** |

### 9.2 「字段对齐」是 S-Type 劈开立即数的唯一原因

```
       31      25 24      20 19      15 14      12 11      7
R-Type: funct7    rs2       rs1       funct3     rd
I-Type: imm[11:0] ———       rs1       funct3     rd
S-Type: imm[11:5]  rs2      rs1       funct3     imm[4:0]
```

**看 `rs1`（bits 19:15）和 `funct3`（bits 14:12）—— 三种格式完全一致。**

> **这意味着：**
> - 硬件可以直接从 bit 19:15 读出 `rs1`，**不需要先判断格式**
> - 寄存器读和格式解码**可以并行**
>
> **代价**：立即数被劈成两半，解码时要重新拼接。

### 9.3 funct3 的最高位是「无符号标志」

```
000  lb    (1 字节，有符号)
100  lbu   (1 字节，无符号)
001  lh    (2 字节，有符号)
101  lhu   (2 字节，无符号)
010  lw    (4 字节)
```

> **规律：bit[2] = 1 表示「无符号」。**
>
> **这是一个隐含的设计模式** ——
> **L02 讲的无符号/有符号区分，在 funct3 编码里留下了痕迹。**

### 9.4 opcode 的低 2 位永远是 11

```
R-Type: 0110011
I-Type: 0010011 / 0000011 / 1100111 / 1110011
S-Type: 0100011
B-Type: 1100011
J-Type: 1101111
```

> **所有指令 opcode 的 bit[1:0] 都是 `11`。**
>
> **原因**：RISC-V 压缩扩展（C 扩展）的 16 位指令，低 2 位是 `00`/`01`/`10`。
> **用 `11` 区分「32 位指令」，让硬件一眼就能看出长度。**

### 9.5 `sub` 用 funct7 区分的深意

```
add: funct7 = 0000000, funct3 = 000
sub: funct7 = 0100000, funct3 = 000
```

**硬件层面：**

```
ALU 操作 = add(a, b) 或 add(a, ~b + 1)
                             ↑
                        funct7[5] 控制
```

> **`funct7[5] = 1` 就是「反转 rs2 并加 1」。**
> **加法器硬件只需多一个 mux，就能同时实现 add 和 sub。**

### 9.6 立即数范围的实际影响

**I-Type 12 位有符号：**

```
[-2048, +2047]
```

**这意味着：**

- `lw x1, 2047(x2)` ✅ 可以
- `lw x1, 2048(x2)` ❌ **超出范围**
- 访问更远的数组元素 → **必须先把基址调整**

> **这就是为什么循环里用「指针递增」而不是「大偏移」**（L11 讲的优化）。

### 9.7 与后续的衔接

| 讲次 | 关系 |
|---|---|
