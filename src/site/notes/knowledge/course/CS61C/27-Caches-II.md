# CS61C FA26 · L27 Caches II

## 一、⭐ 直接映射缓存（Direct-Mapped Cache）

### 1.1 定义

> **「在直接映射缓存中，每个内存地址都只关联到缓存的「一个可能块」。」**

**推论：**

| 结论 | 说明 |
|---|---|
| **只需查「一个位置」** | **如果数据在缓存里，只可能在这一个地方** |
| **块（block）是传输单位** | **缓存↔内存之间以块为单位搬运** |

---

### 1.2 最小例子：4 字节缓存、块大小 1 字节

```
内存          缓存
0x0 ──┐
0x1  │
0x2  │
0x3  │
0x4 ──┼──►  索引 0
0x5  │
0x6  │
0x7  │
0x8 ──┼──►  索引 1
0x9  │
0xA  │
0xB  │
0xC ──┼──►  索引 2
0xD  │
0xE  │
0xF  │
       └──►  索引 3
```

> **缓存位置 0 可以被「内存地址 0, 4, 8, C...」的数据占据。**

**规律：**

```
缓存索引 = 内存地址 mod 4
```

| 缓存位置 | 可容纳的内存地址 |
|---|---|
| **0** | **0, 4, 8, C** |
| **1** | **1, 5, 9, D** |
| **2** | **2, 6, A, E** |
| **3** | **3, 7, B, F** |

> **4 个块 → 任何「4 的倍数」的内存地址都映射到块 0。**

---

### 1.3 块大小 > 1 字节：8 字节缓存、块大小 2 字节

```
内存             缓存（4 个块，每块 2 字节）
0x0 ┐            索引 0: [0x0, 0x1]
0x1 ┘
0x2 ┐            索引 1: [0x2, 0x3]
0x3 ┘
0x4 ┐            索引 2: [0x4, 0x5]
0x5 ┘
0x6 ┐            索引 3: [0x6, 0x7]
0x7 ┘
0x8 ┐            → 又映射到索引 0（覆盖）
0x9 ┘
...
```

> **「当我们请求一个字节时，控制器找到正确的块，然后「把整块都载入」！」**

### 1.4 ⚠️ 三个必须回答的问题

| 问题 | 难度 |
|---|---|
| **① 它怎么知道「哪个块是对的」？** | **需要 Tag** |
| **② 我们怎么「选中块里的那个字节」？** | **需要 Offset** |
| **③ 它怎么知道「这个块原本来自哪个内存地址」？** | **需要 Tag（再强调）** |

> ⭐ **「在行李提取处你会怎么做？」** ——
> **看行李牌（tag）确认是你的行李！**

---

### 1.5 ⭐ 加入 Tag

```
索引  Tag   数据
 0    0x08  [0x08, 0x09]
 1    0x02  [0x02, 0x03]
 2    0x14  [0x14, 0x15]
 3    0x1E  [0x1E, 0x1F]
```

**三个关键问题（课件原话）：**

| 问题 | 答案 |
|---|---|
| **① Tag 里该放什么？** | **「剩余的地址位」** |
| **② 需要「完整地址」吗？** | **不需要 —— 索引和偏移已经隐含了，去掉可省内存** |
| **③ 为什么「不按缓存编号计数」？** | **「用「和块大小相同的宽度」来画内存更方便」** |

> ⭐ **「这些 tag 有什么共同点？」—— 它们都是「块号」，即「去掉低位的地址」。**

## 二、⭐⭐ TIO：三字段划分

### 2.1 核心答案

> **「把内存地址分成三个字段：」**

```
ttttttttttttttttt  iiiiiiiiii  oooo
      Tag            Index      Offset
   （用来检查          （选择      （块内的
   是否有正确块）      哪个块）    字节偏移）
```

### 2.2 三个字段的定义

> **「所有字段都按「无符号整数」读取。」**

| 字段 | 名称 | 作用 |
|---|---|---|
| **Index** | **索引** | **指定「缓存的哪一行/哪一块」** |
| **Offset** | **偏移** | **找到正确块后，指定「块内哪个字节」** |
| **Tag** | **标签** | **偏移和索引确定后剩下的位 —— 用来区分「所有映射到同一位置的内存地址」** |

### 2.3 ⭐ TIO 记忆法（Uncle Dan 版）

```
AREA（缓存大小，B）= 2^(H+W) = 2^H × 2^W
                    = HEIGHT（块数）× WIDTH（每块字节数）
```

```
           Tag    Index    Offset
                 └─ H ─┘   └─ W ─┘
                 HEIGHT    WIDTH
    └────── AREA ──────┘
```

| 参数 | 含义 | 由什么决定 |
|---|---|---|
| **WIDTH（W）** | **每块字节数** | **块大小 → offset 位数** |
| **HEIGHT（H）** | **块数** | **缓存总大小 / 块大小 → index 位数** |
| **Tag** | **剩余位** | **地址位数 − W − H** |

> ⭐ **「TIO = Tag-Index-Offset，顺序就是地址从高到低。」**

## 三、⭐ 完整例题：8 B 缓存、2 B 块、32 位地址

### 3.1 题目

> **「假设有一个 8 B 数据的直接映射缓存，块大小 2 字节。**
> **如果是 32 位架构（RV32），求 tag、index、offset 的位数。」**

### 3.2 Step 1：Offset

> **「需要指定块内正确的字节。块含 2 字节 = 2¹ 字节 → 需要 1 位。」**

```
Offset = 1 bit
```

### 3.3 Step 2：Index

> **「需要指定缓存中正确的块。」**

```
缓存含 8 B = 2³ 字节
块含 2 B = 2¹ 字节
块数/缓存 = 2³ / 2¹ = 2² 块
→ 需要 2 位
```

```
Index = 2 bits
```

### 3.4 Step 3：Tag

> **「用剩下的位作为 tag。」**

```
tag 长度 = 地址长度 − offset − index
        = 32 − 1 − 2
        = 29 bits
```

> **「所以 tag 是内存地址「最左边 29 位」。」**
> **「Tag 可以理解为「缓存编号（cache number）」。」**

### 3.5 ⭐ 答案汇总

| 字段 | 位宽 | 位置（32 位地址中）|
|---|---|---|
| **Tag** | **29** | **bit[31:3]** |
| **Index** | **2** | **bit[2:1]** |
| **Offset** | **1** | **bit[0]** |

```
31                    3 2   1 0
┌──────────────────────┬─────┬───┐
│        Tag (29)      │Idx 2│Off│
└──────────────────────┴─────┴───┘
```

### 3.6 ⭐ 为什么不用「完整 32 位地址」做 tag

> **两个理由（课件原话）：**

| 理由 | 说明 |
|---|---|
| **① 块内所有字节需要「相同的地址」** | **低 offset 位在块内是「常量」，不区分信息** |
| **② index 对「块内每个地址」都相同** | **因此「tag 检查时是冗余的」，省掉可节省内存** |

> ⭐ **「tag 只需存「区分同一索引下不同块」的信息 —— 也就是「块号的高位」。」**

## 四、⭐ 有无缓存的完整访问流程

### 4.1 无缓存

```asm
lw t0, 0(t1)      # t1 = 1022₁₀，Memory[1022] = 99
```

| 步骤 | 动作 |
|---|---|
| **1** | **处理器向内存发出地址 1022₁₀** |
| **2** | **内存读取地址 1022₁₀ 处的字（99）** |
| **3** | **内存把 99 送回处理器** |
| **4** | **处理器把 99 装入 t0** |

**总共 4 步。**

### 4.2 ⭐ 有缓存（类似于哈希）

| 步骤 | 动作 |
|---|---|
| **1** | **处理器向「缓存」发出地址 1022₁₀** |
| **2** | **缓存检查「是否有 1022₁₀ 数据的副本」** |
| **2a** | **✅ 命中（Hit）：缓存读出 99，送给处理器** |
| **2b** | **❌ 未命中（Miss）：缓存把地址 1022 发给内存** |
| | **Ⅰ. 内存读取 1022₁₀ 处的 99** |
| | **Ⅱ. 内存把 99 送给缓存** |
| ** | **Ⅲ. 缓存用新的 99「替换」旧内容** |
| | **Ⅳ. 缓存把 99 送给处理器** |
| **3** | **处理器把 99 装入 t0** |

> ⭐ **「缓存总是「副本（copy）」—— 这一点在替换时很重要。」**

## 六、⭐ 缓存术语（三种情况）

### 6.1 读内存时可能发生三件事

| 情况 | 名称 | 说明 |
|---|---|---|
| **①** | **Cache hit（命中）** | **缓存块有效且含正确地址 → 直接读想要的字** |
| **②** | **Cache miss（未命中）** | **对应块里什么都没有 → 从内存取** |
| **③** | **Cache miss, block replacement（未命中+替换）** | **对应块里是「错误数据」→ 丢弃，从内存取** |

> ⭐ **「缓存总是副本（cache always copy）」——**
> **所以丢弃缓存块不会丢数据（前提是没改过）。**

### 6.2 ⚠️ 第三种情况的隐含风险

> **如果缓存里那块数据被「修改过」怎么办？**

| 策略 | 说明 | 讲次 |
|---|---|---|
| **Write-through（写直达）** | 写同时写缓存和内存 → 缓存永远是最新的 | L28 |
| **Write-back（写回）** | 只在缓存里改，换出时才写内存 → 需要 dirty 位 | L28 |

> **本讲还没提这个问题 —— 这是「写策略」，L28 详讲。**

## 七、⭐ 缓存温度（Cache Temperatures）

> **课件用「温度」比喻缓存状态：**

| 状态 | 含义 |
|---|---|
| **Cold（冷）** | **缓存是空的** |
| **Warming（升温中）** | **缓存正在填充「你希望很快会再次访问」的值** |
| **Warm（温）** | **缓存在正常工作，命中率尚可** |
| **Hot（热）** | **缓存表现很好，命中率很高** |

> ⭐ **「Cold start（冷启动）」这个词就来自这里 ——**
> **程序刚启动时缓存全空，开头几百条指令会很慢。**

## 八、⭐ 关键指标

### 8.1 四个术语

| 术语 | 定义 |
|---|---|
| **Hit rate（命中率）** | **访问中命中的比例** |
| **Miss rate（未命中率）** | **`1 − Hit rate`** |
| **Miss penalty（未命中代价）** | **从下层替换一个块到缓存所需的时间** |
| **Hit time（命中时间）** | **访问缓存的时间（含 tag 比较）** |

### 8.2 ⭐ 平均访问时间公式

```
AMAT = Hit time + Miss rate × Miss penalty
```

> **（Average Memory Access Time，平均内存访问时间）**

**示例：**

```
Hit time   = 1 ns
Miss rate  = 2%
Miss penalty = 100 ns

AMAT = 1 + 0.02 × 100 = 1 + 2 = 3 ns
```

> ⭐ **「2% 的 miss，让访问时间变成 3 倍。」**

### 8.3 为什么 miss rate 的「小变化」很致命

| Miss rate | AMAT（hit=1, penalty=100）| 倍数 |
|---|---|---|
| **0%** | **1 ns** | 1× |
| **1%** | **2 ns** | **2×** |
| **2%** | **3 ns** | **3×** |
| **5%** | **6 ns** | **6×** |
| **10%** | **11 ns** | **11×** |

> ⭐ **「miss penalty 大时，miss rate 就是杠杆 —— 每 1% 都是巨大的代价。」**

## 九、⭐ Valid Bit（有效位）

### 9.1 问题

> **「当启动一个新程序时，缓存里「没有这个程序的有效信息」。」**

**具体：**

```
上电瞬间，SRAM 里是「随机值」。
如果某个随机值「碰巧等于」tag —— 会虚假命中！
```

### 9.2 解法

> **「加一个「有效位（valid bit）」到缓存 tag 条目里。」**

| Valid | 行为 |
|---|---|
| **0** | **缓存未命中（miss）—— 即使地址碰巧等于 tag** |
| **1** | **若处理器地址 == tag，则命中（hit）** |

### 9.3 ⭐ 完整条目结构

```
┌───────┬────────┬─────────────┐
│ Valid │  Tag   │    Data     │
├───────┼────────┼─────────────┤
│  1 b  │ T bits │  Block size │
└───────┴────────┴─────────────┘
```

> ⭐ **总共的「开销」= `Valid(1) + Tag(T)` 位每块。**
> **这部分「不存数据」，纯粹是「簿记（bookkeeping）」。**

## 十、⭐ 真实例子：16 KB 直接映射缓存、16 B 块

### 10.1 先算 TIO

| 参数 | 计算 | 结果 |
|---|---|---|
| **块大小** | 16 B = 2⁴ | **Offset = 4 bit** |
| **缓存大小** | 16 KB = 2¹⁴ B | |
| **块数** | 2¹⁴ / 2⁴ = 2¹⁰ = 1024 | **Index = 10 bit** |
| **地址宽度** | RV32 = 32 bit | |
| **Tag** | 32 − 10 − 4 | **18 bit** |

### 10.2 缓存结构

```
┌───────┬──────────┬──────────────────┐
│ Valid │   Tag    │      Data        │
│  1b   │  18b     │      128b        │
├───────┼──────────┼──────────────────┤
│   0   │   0x0    │  0xc-f  0x8-b …  │
│   0   │   0x1    │  0x4-7  0x0-3 …  │
│   0   │   0x2    │       …          │
│   …   │    …     │       …          │
│   0   │   0x3FF  │       …          │
└───────┴──────────┴──────────────────┘
 索引 0 到 1023，共 1024 行
```

**每行的位宽：**

```
1（valid）+ 18（tag）+ 128（16 B 数据）= 147 位
```

**总容量：**

```
1024 × 147 位 = 150,528 位 ≈ 18.4 KB
```

> ⭐ **「存储 16 KB 数据，实际用了 18.4 KB —— 开销约 15%。」**

### 10.3 开销分析

| 组成 | 位数 | 占比 |
|---|---|---|
| **数据** | 128 | **87%** |
| **Tag** | 18 | **12.2%** |
| **Valid** | 1 | **0.7%** |

> ⭐ **「块越大，tag 开销占比越小 ——**
> **这就是为什么块大小通常 ≥ 16 字节。」**

## 十一、课程结论（原话）

> **「我们学习了直接映射缓存的操作。**
> **它是「存储层次中各层之间「透明搬运数据」的机制：**
> - **一组「地址→值」的绑定**
> - **地址 → 索引 → 一组候选**
> - **把「想要的地址」和 tag 比较**
> - **服务命中或未命中**
> - **未命中时载入新块和绑定」**

## 十二、我的笔记与理解

### 12.1 TIO 是「地址的三种用途」

> **一个地址位，只能有「一种语义」。**

```
高 29 位：我是「哪一块」   → Tag（身份）
中 2 位： 我落在「哪一格」 → Index（位置）
低 1 位： 我是「块内第几字节」→ Offset（内部偏移）
```

> ⭐ **「Tag 回答「你是谁」，Index 回答「你在哪」，Offset 回答「你要哪个字节」。」**

### 12.2 为什么「直接映射」最便宜但也最糟

**优点：**

| 优点 | 说明 |
|---|---|
| **查找只有「一个位置」** | 无需搜索 → 极快 |
| **硬件极简** | 一个比较器 + 一个 MUX |
| **无需替换策略** | 新块永远覆盖老的 |

**缺点：**

| 缺点 | 说明 |
|---|---|
| **冲突未命中（Conflict Miss）** | **两个块映射到同一索引 → 反复互相踢出** |

**经典例子：**

```c
int a[1024], b[1024];
for (int i = 0; i < 1024; i++)
    sum += a[i] + b[i];
```

**如果 `a` 和 `b` 的起始地址相差「缓存大小」的整数倍：**

```
a[0] → 索引 0
b[0] → 索引 0   ← 冲突！
a[1] → 索引 1
b[1] → 索引 1   ← 冲突！
```

> ⭐ **每次访问都 miss —— 命中率 0%，尽管缓存「完全够用」。**

> **这就是 L28 要引入「组相联（set-associative）」的动机。**

### 12.3 为什么「tag 不用全地址」

> **课件给了两个理由，可以合并成一句：**

```
同一块内的所有地址，只有 offset 不同 → 它们「本来就是同一块」
```

> ⭐ **所以 tag 存「块号」而不是「字节地址」。**
> **等价地：tag = 地址 >> (index_bits + offset_bits)。**

**节省量：**

```
全地址 tag：32 位 × 1024 块 = 32,768 bit
块号 tag：  18 位 × 1024 块 = 18,432 bit
节省 44%
```

### 12.4 「Cold start」的性能影响

> **程序启动时，每条指令、每个数据都要从内存取。**

| 阶段 | 行为 |
|---|---|
| **前几百条指令** | **几乎 100% miss** |
| **预热后** | **命中率上升到 90%+** |

**估算：**

```
假设 1000 条指令的预热期，每次 miss penalty = 100 周期
总开销 = 1000 × 100 = 100,000 周期

如果程序总长 100 万条（理想 100 万周期）
→ 预热占 10%
```

> ⭐ **「这就是为什么「短程序」的性能主要由「冷启动」决定 ——**
> **也是为什么基准测试要「预热（warm up）」。」**

### 12.5 Valid bit 的必要性（一个容易忽略的点）

> **上电时 SRAM 里的值是什么？**

| 假设 | 后果 |
|---|---|
| **全是 0** | 如果程序第一条指令的 tag 也是 0 → **虚假命中！读到垃圾** |
| **全是随机** | **1/2^18 的概率虚假命中** |

> ⭐ **「Valid bit 把「上电状态」显式标记为「无效」—— 这是一个「安全默认值」。」**

> **这也解释了为什么缓存「不能简单地用 tag 匹配判断命中」——**
> **必须有 valid 位。**

### 12.6 缓存开销的「反直觉」

> **16 KB 数据要用 18.4 KB 空间 —— 多出 15%。**

**为什么可接受？**

| 对比 | 开销 |
|---|---|
| **直接映射（块 16 B）** | **15%** |
| **块 4 B（更小）** | **约 45%！**（tag 仍 18 位，数据只 32 位）|
| **块 64 B（更大）** | **约 4%** |

> ⭐ **「块越大，tag 开销越低 —— 但块太大又会导致「取来用不上的数据」（空间局部性变差）。」**

> **16–64 字节是「甜点区」。**

### 12.7 与前面讲的呼应

| 前面讲的 | 缓存里的对应 |
|---|---|
| **L16 二进制表示** | **TIO 的位划分** |
| **L17 布尔代数** | **tag 比较器（XNOR + 32 输入 AND）** |
| **L18 关键路径** | **hit time = tag 比较 + 数据读出** |
| **L21 MUX** | **索引选择块 + offset 选择字节** |
| **L24 IMEM/DMEM** | **就是两块 L1 缓存** |

> ⭐ **「L21 的 32 位宽 N 选 1 MUX —— 那就是索引选择块的物理实现。」**

| 术语 | 中文 | 说明 |
