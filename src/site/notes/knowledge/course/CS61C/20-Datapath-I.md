## 五、复习：三个关键积木

### 5.1 上次学的

| 积木 | 说明 |
|---|---|
| **简单 ALU** | add、sub、and、or |
| **1 位宽 2 选 1 MUX** | 由 `s` 选择 `a` 或 `b` |
| **32 位宽 2 选 1 MUX** | 每个 bit 各一个 1 位 MUX |

### 5.2 本次用的

| 积木 | 说明 |
|---|---|
| **32 位寄存器** | 带 Write Enable |
| **寄存器堆（RegFile）** | 32 个寄存器 |
| **内存（MEM）** | IMEM 和 DMEM |

### 5.3 ⭐ 时钟周期的核心规则

> **在一个时钟周期内：**

| 时刻 | 发生什么 |
|---|---|
| **①** | **组合逻辑经过延迟后更新** |
| **②** | **状态元件在「下一个上升沿」更新** |

> **具体流程：**
> 1. **状态元件的当前输出 → 驱动组合逻辑的输入**
> 2. **组合逻辑的输出 → 在「下一个上升沿之前」稳定在状态元件的输入上**
> 3. **所有状态元件用组合逻辑的输出更新**
> 4. **执行进入下一个周期**

### 5.4 CPU 里的状态元件

| 元件 | 说明 |
|---|---|
| **PC** | 程序计数器（寄存器）|
| **Reg[ ]** | 寄存器堆 |
| **IMEM** | 指令内存 |
| **DMEM** | 数据内存 |

> **执行时，每条 RV32I 指令都读取/更新这些状态元件。**

## 六、三个核心状态元件详解

### 6.1 32 位寄存器（PC 用它）

| 项 | 说明 |
|---|---|
| **输入** | N 位数据输入总线 + **Write Enable 控制位**（1 = 断言，0 = 未断言）|
| **输出** | N 位数据输出总线 |
| **行为** | **若上升沿时 Write Enable = 1，则 Data Out = Data In** |
| **其他时候** | **Data Out 不变，保持当前值** |

> ⭐ **「只有写操作受时钟影响。」**

### 6.2 寄存器堆（RegFile）

| 端口 | 位宽 | 说明 |
|---|---|---|
| **wdata** | 32 | 一个数据输入总线 |
| **rs1** | 5 | 读口 1 的选择 |
| **rs2** | 5 | 读口 2 的选择 |
| **rd** | 5 | 写口的选择 |
| **RegWEn** | 1 | 写使能控制位 |
| **rdata1** | 32 | 读口 1 输出 |
| **rdata2** | 32 | 读口 2 输出 |

**行为：**

| 操作 | 机制 |
|---|---|
| **读** | **`rs1` 选中寄存器 → 值放到 `rdata1`** |
| | **`rs2` 选中寄存器 → 值放到 `rdata2`** |
| **写** | **`rd` 选中寄存器，`RegWEn=1` 时把 `wdata` 写入** |
| **写时机** | **上升沿** |

> ⭐⭐ **关键洞察：**
> **「时钟只在写操作时才有影响！」**
> **所有读操作都像组合逻辑块 —— `rs1`/`rs2` 有效后，经过访问时间 `rdata1`/`rdata2` 就有效。**

### 6.3 内存（MEM）

| 端口 | 说明 |
|---|---|
| **addr** | 32 位地址 |
| **rdata** | 32 位读数据 |
| **wdata** | 32 位写数据 |
| **MemRW** | 1 = 写，0 = 读 |

**访问方式：**

| 操作 | 步骤 |
|---|---|
| **读** | **`addr` 选中字 → 放到 `rdata`**（`MemRW=0`）|
| **写** | **`MemRW=1`，`addr` 选中字，用 `wdata` 写入** |

> **与 RegFile 一样，"时钟只影响写"。**
> **读操作（`MemRW=0`）时，内存表现得像组合逻辑块。**

### 6.4 IMEM 与 DMEM 的分工

> **当前的抽象：内存把指令和数据放在「同一个连续的 32 位空间」里。**

> **但我们的处理器用「两个独立的内存」：**

| 内存 | 用途 | 特性 |
|---|---|---|
| **IMEM** | **取指令（fetch）** | **只读 → 永远像组合逻辑块** |
| **DMEM** | **load（读）/ store（写）数据字** | 读写都有 |

> ⭐ **底层上，这两个是 L1 缓存（L1i、L1d）的占位符。**

## 七、从 add 开始搭

### 7.1 add 指令做了什么

```asm
add rd, rs1, rs2
```

| 元件 | 作用 |
|---|---|
| **RegFile** | `Reg[rd] = Reg[rs1] + Reg[rs2]` |
| **PC** | `PC = PC + 4` |

**编码：**
```
31      25 24 20 19 15 14 12 11 7 6      0
funct7    rs2   rs1   funct3  rd  opcode
0000000   源2   源1   000     目标 0110011
```

### 7.2 数据通路搭建（四个步骤）

> **① 拆分指令，用来索引 RegFile**
> **② 递增 PC 到下一条指令**
> **③ 把读出的寄存器值喂进加法器**
> **④ 把加法器输出写到目标寄存器**

```
+4
 ▲
 │  ┌─────────┐
PC ──►│  pc+4   │
 │   └─────────┘
 │        │
 │   ┌────▼────┐    inst
 └───┤   PC    ├───────► IMEM ──┐
     └─────────┘                │
                          ┌─────▼──────┐
                          │ 拆分指令    │
                          └──┬───┬───┬─┘
                    inst[11:7]│   │   │inst[24:20]
                    (rd)     │   │   │(rs2)
                  inst[19:15]│   │   │
                  (rs1)      │   │   │
                        ┌────▼───▼───▼───┐
                        │     Reg[ ]      │
                        └──┬──────────┬───┘
                     rdata1│          │rdata2
                        ┌──▼────┐  ┌──▼──┐
                        │   A   │  │  B  │
                        │  ┌────▼──▼───┐ │
                        │  │   Adder   │ │
                        │  └────┬──────┘ │
                        └───────┼────────┘
                                │ alu
                          ┌─────▼──────┐
                          │  wdata     │──► 回 Reg[rd]
                          └────────────┘
```

**控制信号（此时只有两个）：**

| 信号 | 值 | 作用 |
|---|---|---|
| **RegWEn** | **1** | **允许写寄存器** |
| **ALUSel** | **Add(0)** | **ALU 做加法** |

> **约定：`Add(0)`、`Sub(1)`。**

### 7.3 sub 指令

```asm
sub rd, rs1, rs2         # R[rd] = R[rs1] - R[rs2]
```

**编码差异（只有两处不同）：**

| 字段 | add | sub |
|---|---|---|
| **funct7** | `0000000` | **`0100000`** |
| **funct3** | `000` | `000`（相同）|

> ⚠️ **课件原话：「细节留给控制逻辑。」**
> **亚注意：`sub` 和 `add` 的 `funct3` 相同，靠 `funct7` 区分。**

**控制：**

| 信号 | 值 |
|---|---|
| **RegWEn** | 1 |
| **ALUSel** | **Sub(1)** |

> ⭐ **注意：funct7 不进入 datapath，它只进控制逻辑 → 控制逻辑输出 `ALUSel`。**

## 八、五个执行阶段

> **所有必要操作，从「取指令」开始。**

### 8.1 为什么分阶段

> **「更小的段更容易设计！」**
> **「模块化：容易优化某一段而不碰其他段。」**

> **（但注意：这个图「很难按原样实现」—— 这是抽象。）**

### 8.2 五个阶段

```
① IF  (Instruction Fetch)    取指令
② ID  (Instruction Decode)   译码 + 读寄存器
③ EX  (Execute)              ALU 运算
④ MEM (Memory Access)        访存
⑤ WB  (Write Back)           写回寄存器
```

```
   ① IF          ② ID           ③ EX         ④ MEM      ⑤ WB
  ┌──────┐    ┌──────────┐   ┌───────┐   ┌───────┐  ┌──────┐
  │  PC  │    │           │   │       │   │       │  │      │
  │ IMEM │    │  Reg[ ]   │   │  ALU  │   │ DMEM  │  │      │
  └──────┘    └──────────┘   └───────┘   └───────┘  └──────┘
```

> ⭐ **关键：本讲（单周期）里，「一条 RV32I 指令的所有阶段都在同一个时钟周期内完成」。**

### 8.3 控制逻辑接入

> **控制逻辑产生：MUX 选择信号、ALU 操作选择、写使能等。**

> ⭐ **控制逻辑「读指令」，然后「告诉各单位做什么」。**

### 8.4 ⚠️ 哪些是「时钟驱动的」状态元件

**问题：PC、Reg[ ]、IMEM、DMEM、寄存器——哪些是 synchronous state element（同步状态元件）？**

| 元件 | 是同步状态元件吗 | 原因 |
|---|---|---|
| **PC** | ✅ **是** | 寄存器，上升沿更新 |
| **Reg[ ]** | ✅ **是**（写时）| 上升沿写 |
| **DMEM** | ✅ **是**（写时）| 上升沿写 |
| **IMEM** | ❌ **不是** | **只读，像组合逻辑** |
| **存储器读** | ❌ 不是 | 读完就出 |

> ⭐ **「不是所有状态元件都是时钟驱动的 —— 像 IMEM 这种就像组合逻辑一样工作。」**

## 九、addi：加入立即数

### 9.1 addi 做了什么

```asm
addi rd, rs1, imm        # R[rd] = R[rs1] + imm
```

**编码（I-Type）：**
```
31        20 19    15 14   12 11    7 6      0
imm[11:0]     rs1    000     rd    0010011
```

### 9.2 需要的改动

> **要算 `R[rs1] + imm`，就得把「立即数」喂进 ALU 的 B 输入，而不是 `R[rs2]`。**

**① 加一个 MUX 到 ALU 的 B 输入**

| `BSel` | B 的输入 |
|---|---|
| **0** | **`R[rs2]`**（默认）|
| **1** | **`imm`** ✅ |

**② 加一个立即数生成块（Imm Gen）**

> **把指令里的位拼成 32 位立即数。**

| 信号 | 说明 |
|---|---|
| **`ImmSel`** | **选择「按哪种格式」生成立即数** |
| | 本讲只用到 **`I`** |

### 9.3 I-Type 立即数的生成

```
指令 inst[31:0]:
 31      20 19   15 14  12 11   7 6      0
┌──────────┬───────┬──────┬──────┬────────┐
│ imm[11:0]│  rs1  │funct3│  rd  │ opcode │
└──────────┴───────┴──────┴──────┴────────┘

立即数 imm[31:0]:
 31          12 11        0
┌──────────────┬───────────┐
│ imm[31:12]   │ imm[11:0] │
│  ssss...s    │ inst[31:20]│
└──────────────┴───────────┘
```

**两条规则：**

| 步骤 | 说明 |
|---|---|
| **① 拷贝低 12 位** | **`inst[31:20]` → `imm[11:0]`** |
| **② 符号扩展** | **`inst[31]`（符号位）→ `imm[31:12]`（重复 20 次）** |

> ⭐ **「`inst[31]` 永远是符号位」—— 这个观察在 L21 支撑所有格式的立即数生成。**

### 9.4 addi 时的冗余

> ⚠️ **`inst[24:20]` 仍然喂进 Reg[ ]，Reg[ ] 仍然输出 `R[rs2]`。**
> **但因为 `BSel=1`，`R[rs2]` 这条数据线被「忽略」了。**

> **这是硬件的常态：以「多算一个用不到的值」换取「少一个控制判断」。**

## 十一、我的笔记与理解

### 11.1 「读像组合逻辑，写受时钟控制」

> **这是本讲最重要的一句话，出现在 RegFile 和 MEM 两处。**

```
读：地址 → (延迟) → 数据      ← 纯组合逻辑，无时钟
写：上升沿 + 使能 → 数据落盘   ← 只有这里需要时钟
```

**为什么这样设计？**

| 好处 | 说明 |
|---|---|
| **读无延迟惩罚** | 同周期内可以「读→算→再读」|
| **写有明确边界** | 状态只在边沿改变，时序可分析 |
| **简化控制** | 不用为「读」安排额外的时钟相位 |

> ⭐ **这就是为什么「单周期 CPU」是可能的：**
> **读操作不消耗时钟相位，一路组合逻辑推到底，最后一个边沿统一写回。**

### 11.2 单周期 CPU 的根本矛盾

> **所有五个阶段挤在一个周期里 → 周期长度 = 最慢指令的延迟。**

```
add:  tIMEM + tReg + tALU           ← 短
lw:   tIMEM + tReg + tALU + tDMEM   ← 长
```

> **时钟周期必须按 `lw` 定 → `add` 就「浪费」了时间。**

> ⭐ **这就是 L23 流水线的动机：让每个阶段各占一个周期。**

### 11.3 funct7 / funct3 都不进 datapath

> **关键观察：指令的「编码细节」全部在控制逻辑里消化。**

```
datapath 只关心：rs1, rs2, rd, imm
控制逻辑关心：opcode, funct3, funct7
```

> **datapath 是「数据走的路」，控制逻辑是「路口的红绿灯」。**
> **指令的「语义」在控制逻辑里被翻译成「信号」。**

### 11.4 为什么 `sub` 用 ALUSel 而不是加一个减法器

> **L19 已经证明：加法器 + XOR + carry-in 就能做减法。**

> **所以 datapath 里只有一个 ALU，`ALUSel` 是它的模式开关。**
> **这也是「复用硬件」的原则：能共用的绝不重复造。**

### 11.5 IMEM 只读 → 天然的组合逻辑

> **「IMEM 是只读的，因此永远表现得像组合逻辑块。」**

**推论：**

| 事实 | 后果 |
|---|---|
| **IMEM 不写** | 不需要 Write Enable |
| **读是组合的** | 地址一到，指令就出 |
| **所以取指「不占时钟相位」** | 可以和后续逻辑同一周期串联 |

> ⭐ **这也解释了为什么很多架构把 IMEM 做成「I-Cache」：**
> **只读缓存 = 组合逻辑 = 快。**

### 11.6 从「一条指令」到「一套 ISA」的路径

```
L20:  add / sub / addi        ← 打地基
L21:  lw / sw / branch / jal / jalr / lui
L22:  控制逻辑（把信号全部生成）
```

> **L20 只搭了 3 条指令的通路，但已经把「骨架」立起来了。**
> **后面无非是加 MUX、加立即数格式、加比较器。**

### 11.7 与数据表示的联系

> **`imm` 的符号扩展用到 L02（数字表示）的知识：**

```
inst[31] = 1  →  高位补 1  →  负数
inst[31] = 0  →  高位补 0  →  正数
```

> **L02 学的「补码」，在 L20 变成了「一条连线」。**
> **`imm[31:12]` 全部接 `inst[31]` —— 就是这么简单。**

### 11.8 与后续的衔接

| 讲次 | 关系 |
|---|---|
| **L21** | 加 load/store/branch/jump/U-type，datapath 完整 |
| **L22** | 控制逻辑：把指令解码成所有信号 |
| **L23–L25** | 流水线：把单周期切成 5 段 |
| **L26–L29** | 缓存：IMEM/DMEM 的真实实现 |

## 十二、术语速查

| 术语 | 中文 | 说明 |
|---|---|---|
| **datapath** | 数据通路 | CPU 的「肌肉」 |
| **control** | 控制 | CPU 的「大脑」 |
| **PC** | 程序计数器 | 指向当前指令 |
| **RegFile** | 寄存器堆 | 32 个寄存器的集合 |
| **IMEM** | 指令内存 | 只读，像组合逻辑 |
| **DMEM** | 数据内存 | 读写，写受时钟控制 |
| **RegWEn** | 寄存器写使能 | 1 = 允许写 |
| **MemRW** | 内存读写控制 | 1 = 写，0 = 读 |
| **ALUSel** | ALU 操作选择 | Add / Sub / … |
| **BSel** | ALU 的 B 输入选择 | 寄存器 or 立即数 |
| **ASel** | ALU 的 A 输入选择 | 寄存器 or PC |
| **ImmSel** | 立即数格式选择 | I / S / B / J / U |
| **WBSel** | 写回源选择 | ALU / MEM / PC+4 |
| **PCSel** | 下一 PC 选择 | PC+4 / ALU / … |
| **IF / ID / EX / MEM / WB** | 五个执行阶段 | 取指/译码/执行/访存/写回 |
