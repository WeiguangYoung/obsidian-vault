# CS61C FA26 · L15 Running a Program — CALL

> UC Berkeley · Great Ideas in Computer Architecture
> 授课：Dan Garcia
> 对应课件 15-CALL（52 页）
> **CALL = Compile, Assemble, Link, Load**
> 本讲对应 **Great Idea #1：Abstraction**（从高层语言到机器码）

---

## 一、四个步骤总览

```c
foo.c  ──Compiler──→  foo.s  ──Assembler──→  foo.o  ──Linker──→  a.out  ──Loader──→  Memory
        (编译)           (汇编)             (+ lib.o)  (链接)              (加载)
```

| 步骤 | 输入 | 输出 | 命令 |
|---|---|---|---|
| **① Compiler** | `foo.c` | `foo.s`（**汇编**）| `gcc -S` |
| **② Assembler** | `foo.s` | `foo.o`（**目标文件**）| `gcc -c` |
| **③ Linker** | `foo.o` + `lib.o` | `a.out`（**可执行**）| `gcc foo.o` |
| **④ Loader** | `a.out` | **内存中的程序** | 运行它 |

> **「编译 C 代码成二进制」在口语里指整个过程，但实际上是 3 步（Compiler + Assembler + Linker）。**

**`gcc foo.c` 一键完成前三步，产出 `a.out`。**

## 二、Step 1：Compiler（编译）

### 2.1 输入输出

| 项 | 内容 |
|---|---|
| **输入** | 高层语言代码（`foo.c`）|
| **输出** | **汇编语言代码**（`foo.s`）|

### 2.2 ⚠️ 输出仍含伪指令

> **编译器输出的汇编里仍含伪指令！**

```asm
mv   a0, a1      # 伪指令
li   a0, 0x10    # 伪指令
call printf      # 伪指令
j    Loop        # 伪指令
```

> **这些由 Assembler 在下一步替换。**

---

## 三、Step 2：Assembler（汇编）

### 3.1 输入输出

| 项 | 内容 |
|---|---|
| **输入** | 汇编代码（`foo.s`）|
| **输出** | **机器语言模块**，即**目标文件**（`foo.o`）|

> ⚠️ **汇编器不知道「头部（headers）在哪里」——**
> **它把这种解析委托给下游的 Linker。**

### 3.2 两个核心任务

**任务 A：替换伪指令**

```asm
li a0, 0x0      →  addi a0, x0, 0
la a0, str1     →  lui a0, <hi> + addi a0, a0, <lo>
call printf     →  jal / jalr 组合
ret             →  jalr x0, ra, 0
```

**任务 B：产出目标文件（机器语言模块）**

### 3.3 机器码生成：哪些能确定，哪些不能

**✅ 能立即确定的（Text Segment）**

| 类型 | 例子 | 为什么 |
|---|---|---|
| **算术 / 逻辑指令** | R-Format、部分 I-Format | **所有信息都在指令里** |
| **PC 相对的跳转** | `beq` / `bne` / `jal` | **同一文件内部偏移已定** |

> **一旦伪指令被替换，所有「已知的 PC 相对寻址」都能算出。**

### 3.4 ⚠️ Forward Reference 问题：两遍扫描

```asm
Loop:
    beq x1, x2, End      # ← End 在后面！
    ...
    j   End              # ← 也是向后引用
    ...
End:
    ...
```

> **「前向引用」问题：**
> **分支/PC 相对跳转可能引用「程序后面」的标签。**
> **第一遍扫描时，精确的正偏移还不知道！**

**解决方案：两遍扫描（Two-Pass）**

| 遍 | 做什么 |
|---|---|
| **Pass 1** | **记住所有标签的位置**（存进 **Symbol Table**）|
| **Pass 2** | **用标签位置生成机器码**（算偏移）|

### 3.5 ⚠️ 无法确定的（绝对地址）

**两类引用需要其他文件或数据段的完整 32 位地址：**

| 类型 | 例子 |
|---|---|
| **外部文件引用** | `call(jalr)` 到 C 标准库的 `strlen` |
| **静态数据引用** | `la` 被拆成 `lui` + `addi`，需要数据的完整地址 |

> **汇编器把未解决的引用记录在两张表里：**

| 表 | 内容 |
|---|---|
| **Relocation Table**（重定位表）| **待修复的地址清单**（TODO）|
| **Symbol Table**（符号表）| **本文件的标签和可被引用的静态数据** |

> **所有绝对地址的解析都推迟到 Linker。**

## 四、目标文件的六个部分

### 4.1 Object File Format

| # | 部分 | 内容 |
|---|---|---|
| **1** | **Object File Header** | 其他部分的大小和位置 |
| **2** | **Text Segment** | **机器码** |
| **3** | **Data Segment** | **静态数据的二进制表示** |
| **4** | **Symbol Table** | **本文件的标签、可被外部引用的静态数据** |
| **5** | **Relocation Table** | **待 Linker 修复的代码行** |
| **6** | **Debugging Information** | 调试信息（**gdb 用**）|

> **可以想象成「书的目录」+「待办清单」。**

### 4.2 Symbol Table 的细节

> **列出本目标文件里的「条目」：**

| 内容 | 用途 |
|---|---|
| **指令标签** | 用于计算 PC 相对寻址（分支、函数调用）|
| **`.globl` 声明的标签** | **可被其他文件引用** |
| **Data 段里的东西** | 标记为 `.data` 段的都进此表 |

> **调试器（gdb）也用 Symbol Table！**

### 4.3 Relocation Table 的细节

> **列出本文件「还需要地址的 TODO 项」：**

| 内容 | 说明 |
|---|---|
| **跳转到外部标签** | 例如 lib 文件里的 |
| ├ `jal ext_label` | |
| └ `lui` + `addi` / `auipc` + `jalr` | 伪指令展开后 |

## 五、Directives（伪指令/指示符）

### 5.1 什么是 Directives

> **Directives 给汇编器「指示」：**
> - 通常由编译器（上一阶段）生成
> - **不产生机器指令！**
> - **而是告诉下游如何构建输出目标文件的各部分**

### 5.2 常用 Directives

| 指示符 | 作用 |
|---|---|
| **`.text`** | 后续内容放进**用户 Text 段（机器码）** |
| **`.data`** | 后续内容放进 **Data 段** |
| **`.section .rodata`** | 放进**只读数据段** |
| **`.align 2` / `.balign 4`** | 按 2² / 4 字节**对齐** |
| **`.globl main`** | 声明 `main` 为**全局符号**（可被外部引用）|

## 六、Step 3：Linker（链接）

### 6.1 输入输出

| 项 | 内容 |
|---|---|
| **输入** | 多个目标文件（`foo.o`、`lib.o`）|
| **输出** | **可执行的机器码**（`a.out`）|

### 6.2 为什么需要 Linker

> **Linker 让「分别编译文件」成为可能。**
> **改一个文件，不需要重新编译全部。**

### 6.3 拼接多个目标模块

```
file1.o               Linker                a.out
┌────────┐                           ┌─────────────────┐
│ Text 1 │                           │ Relocated Text 1│
│ Data 1 │         ──────→           │ Relocated Text 2│
│ Info 1 │                           │ Relocated Data 1│
└────────┘                           │ Relocated Data 2│
file2.o                              │ Agg. Info 1+2   │
┌────────┐                           └─────────────────┘
│ Text 2 │
│ Data 2 │    Info = symbol table, relocation table, etc.
│ Info 2 │
└────────┘
```

**三个步骤：**

1. **把各 `.o` 的 text 段拼起来**
2. **把各 `.o` 的 data 段拼起来，接在第 1 步后面**
3. **解析引用**

### 6.4 哪些地址需要重定位

| 类型 | 谁处理 |
|---|---|
| **PC 相对寻址** | ✅ **Assembler 已完成** |
| ├ 单个目标模块内的指令偏移 | |
| └ `beq`、`bne`、`jal`、`auipc`+`addi` | |
| **外部函数引用** | ⚠️ **Linker 必须重定位** |
| ├ 通常是 `jal` 或 `auipc`/`jalr` | |
| └ 地址在其他目标模块，汇编时未知 | |
| **静态数据引用** | ⚠️ **Linker 必须重定位** |
| ├ `lw`/`sw`（静态数据）| |
| └ Data 段现在被重排了 | |

### 6.5 解析引用的算法

> **RV32 下，Linker 假设第一个 text 段从 `0x10000` 开始。**（虚拟内存后续讲）

**Linker 知道：**

- 每个 text 和 data 段的**长度**
- text 和 data 段的**顺序**

**Linker 计算：**

- 每个要跳转的标签的**绝对地址**
- 每块被引用数据的**绝对地址**

**Linker 解析引用：**

1. 在**所有「用户」符号表**里搜索引用（数据或标签）
2. **找不到 → 搜索库文件**（如 `stdio`）
3. 找到就填地址，更新机器码

### 6.6 需要被编辑的指令

| 类型 | 说明 |
|---|---|
| **J-Format** | 外部跳转（如 C 库）|
| **U-Format** | `lui` 用于 `li` / `la` 伪指令 |
| **I-Type** | `auipc`/`jalr` 组合 |
| **S-Type** | 访问 `.data` 变量的 load/store |

> **B-Type 不需要编辑** —— **条件跳转都在模块内部**。

### 6.7 Global Pointer（gp）

> **`gp` 是一个指向 data（静态）段的指针。**
> **让 `lw`/`sw` 访问全局变量时能用短偏移（12 位够用）。**

## 七、Step 4：Loader（加载）

### 7.1 输入输出

| 项 | 内容 |
|---|---|
| **输入** | 可执行代码（`a.out`，**存在磁盘上**）|
| **输出** | **（程序开始运行）** |

> **运行可执行文件时，Loader 先把程序载入内存，然后启动它。**

### 7.2 Loader 实际做什么（Take CS162!）

> **把程序载入新创建的地址空间：**

| # | 步骤 |
|---|---|
| **1** | 读 `a.out` 文件头，得到 text / data 段的**大小** |
| **2** | 创建**足够大的新地址空间**（含 text、data、stack 段）|
| **3** | 把指令和数据**从可执行文件复制**到新地址空间 |
| **4** | 把**传给程序的参数**复制到栈上 |
| **5** | **初始化机器寄存器** |
| | └ 大多数寄存器清零 |
| | └ **`sp` 赋值为「第一个空栈地址」** |

> **现实中：加载是操作系统的职责。**

## 八、完整示例：Hello, World!

### 8.1 源代码 `hello.c`

```c
#include <stdio.h>

int main() {
    printf("Hello, %s\n", "world");
    return 0;
}
```

### 8.2 Step 1：编译 `hello.c` → `hello.s`

```asm
.text
.align 2
.globl main
main:
    addi sp, sp, -4
    sw   ra, 0(sp)
    la   a0, str1        # ← 伪指令
    la   a1, str2        # ← 伪指令
    call printf          # ← 伪指令
    lw   ra, 0(sp)
    addi sp, sp, 4
    li   a0, 0           # ← 伪指令
    ret                  # ← 伪指令

.section .rodata
.balign 4
str1: .string "Hello, %s!\n"
str2: .string "world"
```

**Directives 说明：**

| 指示符 | 含义 |
|---|---|
| `.text` | 进入 text 段 |
| `.align 2` | 按 2² = 4 字节对齐代码 |
| `.globl main` | 声明 `main` 为全局符号 |
| `.section .rodata` | 进入只读数据段 |
| `.balign 4` | 数据段按 4 字节对齐 |

**四个伪指令**：`la`、`la`、`call`、`li`、`ret`

### 8.3 Step 2：汇编 `hello.s` → `hello.o`

**Text 段（伪指令已被替换）：**

```
00000000 <main>:
   0: ff010113   addi sp, sp, -16
   4: 00112623   sw   ra, 12(sp)
   8: 00000537   lui  a0, 0x0        ← 地址占位符！
   c: 00050513   addi a0, a0, 0      ← 地址占位符！
  10: 000005b7   lui  a1, 0x0        ← 地址占位符！
  14: 00058593   addi a1, a1, 0      ← 地址占位符！
  18: 000080e7   jalr ra, ra, 0      ← 地址占位符！
  1c: 00c12083   lw   ra, 12(sp)
  20: 01010113   addi sp, sp, 16
  24: 00000513   addi a0, x0, 0
  28: 00008067   jalr x0, ra, 0
```

> **「下划线（占位符）」是那些 `0x0`：**
> **指代 `str1`、`str2`、`printf` 的地址，汇编时还不知道。**

**目标文件内容：**

```
Text:  ff010113 00112623 00000537 00050513
       000005b7 00058593 000080e7 ...
Symbol Table: main, str1, str2
Relocation Table: 需要修复 8、c、10、14、18 处
```

### 8.4 Step 3：链接 `hello.o` → `a.out`

```
    000101b0 <main>:
    101b0: ff010113   addi sp, sp, -16
    101b4: 00112623   sw   ra, 12(sp)
    101b8: 00021537   lui  a0, 0x21          ← 已填高 20 位
    101bc: a1050513   addi a0, a0, -1520     ← # 20a10 <str1>
    101c0: 000215b7   lui  a1, 0x21
    101c4: a1c58593   addi a1, a1, -1508     ← # 20a1c <str2>
    101c8: 288000ef   jal  ra, 10570         ← printf 地址已定
    101cc: 00c12083   lw   ra, 12(sp)
    101d0: 01010113   addi sp, sp, 16
    101d4: 00000513   addi a0, x0, 0
    101d8: 00008067   jalr x0, ra, 0
```

**Linker 做了什么：**

| 动作 | 说明 |
|---|---|
| **压平所有 `.o` 文件** | 合成一个整体 |
| **更新符号表** | 记录最终地址 |
| **对每个重定位表项** | 替换占位符为真实地址 |
| **更新机器码** | 生成最终比特 |

> ⚠️ **注意起始地址变成 `0x101b0`** ——
> **不再是 `0x0`，因为前面还有其他模块的内容。**

## 九、Peer Instruction：什么时候确定全部比特

### 9.1 题目

**下列指令的机器码比特，分别在哪一步确定？**

```asm
1. add x6, x7, x8
2. jal x1, fprintf
```

| 选项 | 1. `add` | 2. `jal` |
|---|---|---|
| A. After compilation | | |
| B. **After assembly** | ✅ | |
| C. **After linking** | | ✅ |
| D. After loading | | |

### 9.2 答案与理由

**① `add x6 x7 x8`**

> **汇编后（After assembly）** ——
> **所有信息都在指令本身**（两个源寄存器 + 一个目的寄存器），
> **不需要任何外部地址。**

**② `jal x1, fprintf`**

> **链接后（After linking）** ——
> **`fprintf` 是外部函数（C stdio）**，
> **它的地址要等 Linker 从库文件里找到并填进去。**

### 9.3 通用规律

| 指令类型 | 何时确定 |
|---|---|
| **R-Type / I-Type 算术** | **汇编后** |
| **PC 相对的 branch / jal（同文件）** | **汇编后**（两遍扫描后）|
| **外部函数调用** | **链接后** |
| **静态数据地址** | **链接后** |
| **全局变量实际地址（PIE）** | **加载后** |

## 十、静态链接 vs 动态链接

### 10.1 静态链接（Static Linking）

> **传统方式：库被直接塞进可执行文件。**

| 优点 | 缺点 |
|---|---|
| ✅ **可执行文件自包含** | ❌ 库更新后**不会自动获得修复** |
| | ❌ 可执行文件**包含整个库**（哪怕只用一部分）|

### 10.2 动态链接（Dynamic Linking / DLL）

> **Windows & UNIX 平台的常见方式。**

| 优点 | 缺点 |
|---|---|
| ✅ **磁盘空间更少** | ⚠️ **运行时开销**（额外时间做动态链接）|
| ✅ **传输时间更短** | ⚠️ **光有可执行文件不够了！** 还需要 `.so` |
| ✅ **多程序共享同一库**（省内存）| |
| ✅ **升级方便**：替换 `libXYZ.so` 就升级了所有用它的程序 | |

> **DLL 的主流做法是「用机器码作为最低公约数」。**

## 十一、番外：解释 vs 翻译

### 11.1 两种方式

| 方式 | 定义 |
|---|---|
| **Interpreter（解释器）** | **直接执行源语言程序** |
| **Translator（翻译器/编译器）** | **把程序从源语言转成另一种等价语言** |

> **翻译到更低级语言，几乎总是意味着更高的效率、更高的性能。**

### 11.2 语言执行连续谱

```
  易编程                                          难编程
     ↑                                               ↑
  Python → Java → C++ → C → Java bytecode → 汇编 → 机器码
     ← 解释低效                              高效翻译 →
```

### 11.3 如何选择

> **通常：**
> - **效率不关键时，解释高层语言**
> - **需要性能时，翻译到更低级语言**

### 11.4 解释器的四个特点

| 特点 | 说明 |
|---|---|
| **更容易写** | 你在 CS61A 写过！ |
| **错误信息更好** | 更接近高层语义（如 VENUS）|
| **更慢（约 10×），代码更小（约 2×）** | |
| **指令集无关** | 任何机器都能跑 |

### 11.5 为什么还要用软件解释机器语言

| 场景 | 说明 |
|---|---|
| **VENUS 模拟器** | 学习/调试 RISC-V |
| **Apple Macintosh 转换** | 从 Motorola 680x0 到 PowerPC（在 x86 之前）|
| └ 方式 | **让可执行文件同时含新旧机器码，必要时软件解释旧代码（emulation）** |

### 11.6 翻译的另一个优势：隐藏源码

> **翻译/编译帮助「隐藏」程序的「源码」不让用户看到。**
>
> | 模式 | 例子 |
> |---|---|
> | **闭源** | Microsoft 保密全部源码 |
> | **开源** | 发布源码，培养开发者社区 |

## 十二、本讲总结（课程原话）

| 步骤 | 做什么 |
|---|---|
| **Compiler** | 把**一个高层语言文件**转成**一个汇编文件** |
| **Assembler** | **移除伪指令**、**尽可能转成机器语言**、**给 Linker 创建清单（重定位表）** |
| **Linker** | **合并多个 `.o` 文件**、**解析绝对地址** |
| **Loader** | **把可执行文件载入内存**、**初始化寄存器**、**启动** |

## 十三、我的笔记与理解

### 13.1 「CALL」这个名字的深意

```
C = Compile
A = Assemble
L = Link
L = Load
```

> **四个步骤，每一步都是「抽象层的一次下降」。**

```
C 源码     →  汇编（伪指令）
汇编       →  机器码（未知地址）
目标文件   →  可执行（地址已定）
磁盘文件   →  内存（可运行）
```

### 13.2 每一步「知道什么、不知道什么」

这是理解 CALL 的核心：

| 阶段 | 知道 | 不知道 |
|---|---|---|
| **Compiler** | C 语义 | 目标架构细节 |
| **Assembler** | 指令编码、本文件内偏移 | 外部符号、数据段地址 |
| **Linker** | 所有符号地址（跨文件）| 加载到内存的地址（PIE）|
| **Loader** | 最终内存地址 | — |

> **每个阶段只解决「它能解决的」，剩下的用「表」传给下游。**
> **这就是 Symbol Table 和 Relocation Table 存在的意义。**

### 13.3 两张表的分工

```
Symbol Table      =  「我有什么」（导出）
Relocation Table  =  「我需要什么」（导入）
```

> **Linker 的工作就是：把所有人的「需要」和「有」对上账。**
> **找不到 → 报错 `undefined reference`。**

### 13.4 「两遍扫描」的必然性

**前向引用是汇编的固有问题：**

```asm
j    End       # 我还不知道 End 在哪
...
End:
```

**Why 不能一遍搞定？**

> **因为读到 `j End` 时，还没读到 `End`。**
> **程序是「顺序读」的，但引用可以「向后」。**

**解决方案**：

```
Pass 1: 只记标签位置（不生成码）
Pass 2: 位置已知，生成码时算偏移
```

> **这是所有汇编器/链接器的通用解法。**

### 13.5 为什么 B-Type 不需要重定位

> **条件分支永远是「模块内部」的跳转。**

```c
if (x > 0) { ... }      // 在同一个函数里
for (int i = 0; ...) { ... }  // 同一个函数
```

> **编译器生成的分支，跳的都是「同一个 .o 文件"里的标签」**
> 所以偏移在汇编阶段就能算出来。

**而函数调用可能跳到「其他文件」** → 需要 Linker。

### 13.6 静态 vs 动态链接的工程权衡

| 场景 | 推荐 |
|---|---|
| **容器/微服务** | **静态**（镜像小、无依赖）|
| **桌面应用** | **动态**（共享库省内存）|
| **系统工具** | **动态**（安全更新能立刻生效）|
| **嵌入式/固件** | **静态**（无动态加载器）|

> **Go 默认静态链接，就是这个哲学。**
> **Rust 可选，C/C++ 默认动态。**

### 13.7 `gp` 寄存器的妙用

> **`gp` 指向 data 段，让「全局变量访问」用 12 位偏移就够。**

```
没有 gp：lui + addi（两条指令，64 位地址）
有 gp：  lw rd, offset(gp)（一条指令，12 位偏移）
```

> **前提：全局变量都集中在 data 段，且总大小 < 4 KB。**
> **这就是为什么小程序的全局变量访问很便宜。**
