## 一、从电路到「可编程电路」

### 1.1 历史的两个节点

| 机器 | 年份 | 特征 |
|---|---|---|
| **ENIAC** | 1946 | **物理重新接线**，限制极强 |
| **EDSAC** | 1949 | **第一台通用存储程序计算机** |

> **CPU 的基本工作：执行大量指令。**

### 1.2 什么是 ISA

| 概念 | 定义 |
|---|---|
| **Instruction（指令）** | CPU 可执行的**原始操作** |
| **ISA（指令集架构）** | 定义某个 CPU **支持哪些操作**，以及**如何实现** |
| **Assembly language** | 低层的 CPU 指令（人可读） |
| **Machine language** | 同一指令的**比特表示** |

**类比**（课程原话）：

> 就像一句话：**操作（动词）作用于操作数（宾语）**，按顺序处理。

```
操作      操作数
  ↓          ↓
add   x1 x2 x3
```

### 1.3 RISC vs CISC

| 架构 | 特点 | 例子 |
|---|---|---|
| **CISC**（Complex Instruction Set Architecture） | **给 CPU 加越来越多指令**做复杂操作 | x86 |
| **RISC**（Reduced Instruction Set Computer） | **简化指令集**，哲学：「Kee[p it simple]」 | RISC-V、ARM |

**CISC 的极端例子：**

> **VAX 架构有一条「计算多项式」的指令！**

**RISC 的起源**：Cocke（IBM）、Patterson、Hennessy，1980 年代。

> **Patterson 和 Hennessy 获 2017 年图灵奖。**

### 1.4 为什么选 RISC-V

> **2015 年发布的、开源、免许可费的 ISA 规范。**

| 特点 | 说明 |
|---|---|
| **开源生态** | 有不断增长的共享软件生态 |
| **全层次适用** | 从微控制器到超级计算机 |
| **多种位宽** | 32 / 64 / 128 位（**本课用 32 位**） |

**为什么不用 Intel x86-64？**

> **RISC-V 简单优雅，我们不会陷入琐碎细节。**

**现状**：从微控制器到 CPU 到仓库级计算机，采用率**指数增长**。

**起源**：2010 年夏，为支持 UC Berkeley 的开放研究与教学而启动，血统可追溯到 1980 年代的 RISC-I/II。

## 二、寄存器：CPU 的内部存储

### 2.1 为什么需要寄存器

> **计算机有两大部件：**
> - **CPU**：负责**计算**
> - **主存（Main Memory）**：负责**长期存储**

**速度对比（关键）：**

| 层级 | 延迟 |
|---|---|
| **CPU（3.33 GHz）** | **0.3 ns / 指令**（光在 0.3 ns 走 10 cm） |
| **主存** | **约 100 ns** |

> **CPU 快 300 倍** —— 所以必须在内部存一小份数据：**寄存器**。

> **这就是 Great Idea #3：Principle of Locality / Memory Hierarchy。**

### 2.2 32 个寄存器

> **RISC-V 有 32 个寄存器。**

**为什么是 32？（Goldilocks 原则）**

> 「这碗粥太烫；这碗粥太冷；这碗粥刚刚好。」
>
> **更少更快，但太少会坏事。**

**代价**：

- 寄存器**固化在硬件里**，数量固定
- **RISC-V 代码必须精心组织才能高效利用寄存器**
- 如今：**编译器负责把 C 变量映射到寄存器**（跨声明、跨函数调用）

### 2.3 寄存器编号与命名

```c
x0, x1, x2, ..., x31        // 编号 0 到 31
```

| 寄存器 | 特殊之处 |
|---|---|
| **x0** | **硬件永为 0**（hardwired to zero） |

> **所以只有 31 个寄存器能存变量值。**
> 每个寄存器都能用**编号**或**名字**引用（名字下一讲解释）。

## 三、算术指令：add / sub

### 3.1 语法（严格）

```
opname  rd  rs1  rs2
         ↑    ↑    ↑
     目的   源1   源2
   （得到结果） （操作数1）（操作数2）
```

> **语法是刚性的：1 个操作符，3 个操作数。**
> **Why? 保持硬件简单——通过规整性。**（后面几周会讲）

### 3.2 基础指令

| RISC-V | C 对应 | 含义 |
|---|---|---|
| `add x1 x2 x3` | `a = b + c;` | `R[x1] = R[x2] + R[x3]` |
| `sub x4 x5 x6` | `d = e - f;` | `R[x4] = R[x5] - R[x6]` |

> ⚠️ **`sub` 的操作数顺序很重要！** `e - f` ≠ `f - e`。

### 3.3 高层语言 vs 汇编（两大差异）

**差异 1：数据表示**

| C / Java | RISC-V |
|---|---|
| 变量**先声明、带类型** | **汇编的操作数是寄存器** |
| 变量只能表示声明类型的值 | **寄存器没有类型** |
| **类型决定操作** | **操作决定「类型」**（如何解释寄存器内容） |

**差异 2：操作粒度**

| C / Java | RISC-V |
|---|---|
| 一行可含**多个操作**<br>`a = b * 2 - (arr[2] + *p);` | **每条指令只做一件事** |
| | 一行汇编**最多 1 条指令** |

> **编译器负责把高层语言翻译成汇编。**

### 3.4 例题 1

```c
a = b + c + d - e;
```

**寄存器映射**：`a→x10, b→x1, c→x2, d→x3, e→x4`

**解答**（分解成多条指令）：

```asm
add x10 x1 x2      # a_temp = b + c
add x10 x10 x3     # a_temp = a_temp + d
sub x10 x10 x4     # a = a_temp - e
```

> **一行 C 可能拆成多行 RISC-V。**

### 3.5 例题 2（多解）

```c
f = (g + h) - (i + j);
```

**寄存器映射**：`f→x19, g→x20, h→x21, i→x22, j→x23`

**解法 A：用临时寄存器**

```asm
add x5  x20 x21    # temp1 = g + h
add x6  x22 x23    # temp2 = i + j
sub x19 x5  x6     # f = temp1 - temp2
```

> ⚠️ `x5`、`x6` 里原有的数据**会被覆盖**。

**解法 B：编译器巧妙避免临时寄存器**

```asm
add x19 x20 x21    # f = g + h
sub x19 x19 x22    # f = f - i
sub x19 x19 x23    # f = f - j
```

> **两种解法都有效，各有取舍。**

### 3.6 关于注释（很重要）

> **Margaret Hamilton**，MIT Instrumentation Lab 软件工程主任
> 构建了 **Apollo Guidance Computer** 的指挥舱（导航、登月）
> **Eagle 号（Apollo 11, 1969）机载内存只有 72 KB**
> 2016 年获**总统自由勋章**

**课程提醒：**

> **RISC-V 里注释比其他语言重要得多。**
> **因为 RISC-V 没有变量名！**
> **未注释的 RISC-V 代码几乎不可能正确调试。**

```asm
add x10 x1 x2      # a = b + c    ← 用 # 注释
```

## 四、立即数与 x0

### 4.1 立即数（Immediates）

> **Immediates 是数值常量。**
> 它们在代码里**出现频繁**，因此有**专门的指令**。

```asm
addi x3, x4, 10     # f = g + 10
```

**语法与 `add` 相似，但最后一个操作数必须是数字，不是寄存器。**

### 4.2 ⚠️ RISC-V 没有 subi

> **为什么？**
> **要减一个立即数，用 `addi` 就好！**

```asm
addi x3, x4, -10    # f = g - 10
```

> **这就是 RISC 哲学：Reduced（简化）。**

### 4.3 x0：硬件永为 0 的寄存器

> **数字 0 在代码里出现得非常频繁。**

```asm
add x3,  x4, x0      # f = g        （+0 不影响）
addi x3, x0, 0xff    # f = 0xff     （从 0 加）
```

**关键性质：**

```asm
add x0, x3, x4       # no-op！什么都不做
```

> **x0 在硬件中被定义为 0，写入无效。**
> **这对伪指令（pseudoinstructions）很有用。**

## 五、概念检查

**判断题：**

| # | 陈述 | 答案 | 理由 |
|---|---|---|---|
| 1 | 在 C 里**类型与声明关联**，但在 RISC-V 里**类型与指令（操作符）关联** | **T** | 寄存器无类型，操作决定解释方式 |
| 2 | 因为只有 32 个寄存器，所以**含 32 个变量的 C 表达式无法写 RISC-V** | **F** | 前面的例子已展示如何拆成更小的式子 |
| 3 | 若 `p`（存在 `x9`）是指向 int 数组的指针，则 `p++;` 是 `addi x9,x9,1` | **F** | 应加 `sizeof(int)` = 4，即 `addi x9,x9,4` |

> **第 3 题是经典陷阱**：C 的指针算术**自动按类型大小缩放**，汇编里要**手动乘 sizeof**。

## 七、本讲总结（课程原话）

**在 RISC-V 汇编语言里：**

- **寄存器取代 C 变量**
- **每行一条指令**（简单操作）
- **Simpler is Better, Smaller is Faster**（简单更好，更小更快）

**RV32 中，word 是 32 位。**

**指令：**

```asm
add   rd rs1 rs2
addi  rd rs1 imm
sub   rd rs1 rs2
```

**寄存器：**

- **32 个寄存器，记作 x0 - x31**
- **x0 永远为 0**

## 八、我的笔记与理解

### 8.1 这一讲的定位

L09 是**整个课程的分水岭**：

```
L01-L08  软件抽象（C、数字表示）
   ↓
L09      下降到硬件接口（ISA）
   ↓
L16+     再下降到硬件实现（电路）
```

**课件第 2 页放「开手动挡」的图**——这个比喻很准确：C 是自动挡，汇编是手动挡，你必须知道每个齿轮在干什么。

### 8.2 「RISC-V 不是关于 RISC-V」

这句话值得琢磨：**它教的是「ISA 这个概念」**，RISC-V 只是一个**简单到能在一学期讲完的样板**。

学会了 RISC-V，看 ARM、MIPS 都能举一反三。

### 8.3 三个反直觉的设计

| 设计 | 直觉上 | 实际上 |
|---|---|---|
| **1 操作符 + 3 操作数** | 太啰嗦 | **规整性让硬件简单** |
| **没有 subi** | 应该对称 | `addi` 加负数就行，**少一条指令** |
| **x0 硬连为 0** | 浪费一个寄存器 | **免费的「0 常量」**，还能做伪指令 |

> **每一个「看起来多余的约束」，都是为了简化硬件。**

### 8.4 为什么必须是 32 个寄存器

| 数量 | 优点 | 缺点 |
|---|---|---|
| 8 | 极快（编码短） | 太少，频繁溢出到内存 |
| **32** | **平衡点** | |
| 64 | 少溢出 | 编码占位多，硬件慢 |

**深层原因**：寄存器编号占 **5 位**（2⁵ = 32），这是一个指令编码的自然边界。**32 位指令里，3 个寄存器 = 15 位**，剩下 17 位给操作码和立即数。

### 8.5 「类型与操作关联」的深刻含义

这是 C 与汇编最本质的差异：

```c
uint8_t x, *y;
x = *y;          // C：编译器看类型，生成 lbu
```

```asm
lb  x1, 0(x3)    # 有符号扩展
lbu x1, 0(x3)    # 无符号扩展
```

> **C 里是「类型决定指令」，汇编里是「指令决定类型」。**
> **这正是抽象层级的反转。**

### 8.6 与后续的衔接

| 讲次 | 关系 |
|---|---|
| **L10** | 数据传送：`lw` / `sw` / `lb` / `sb`，寄存器 ↔ 内存 |
| **L11** | 控制流：分支、循环、`pc` 寄存器 |
| **L12** | 函数调用：`jal` / `jr` / 栈帧 / calling convention |
| **L13-14** | 指令格式：把上面的所有指令编码成 32 位比特 |
