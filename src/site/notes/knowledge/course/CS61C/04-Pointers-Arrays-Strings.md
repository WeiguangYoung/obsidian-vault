## 一、内存模型：一个巨大的字节数组

### 1.1 基本抽象

> **把内存想象成一个「按字节编址的数组」。**

- 每个单元格有**一个地址**
- 每个单元格**存一个值**
- 当前先假设可以访问**无限内存**，地址从 0 开始
- **地址习惯用十六进制书写**

```
地址      值
0x100    ...
0x101    ...
0x102    'b'   ← 变量 x 所在
0x103    ...
0x104    'y'
0x105    'e'
0x106    '\0'
...
```

**现代机器是 byte-addressable：**
- 硬件内存由 **8 位存储单元**组成，**每个字节有唯一地址**
- 我们常按 **word size**（机器字长）思考：**地址的位数**

### 1.2 指针的定义

> **Pointer：一个存放「另一个变量的地址」的变量。**
> 换句话说，它**指向**一个内存位置。

```c
int *p;      // p 是「指向 int 的指针」
int x = 3;
p = &x;      // & 是「取地址运算符」
printf("p points to %d\n", *p);   // * 是「解引用运算符」
*p = 5;      // 通过 p 修改 x
```

### 1.3 `*` 的两种用法（关键）

| 位置 | 含义 |
|---|---|
| `int *p;`（声明处） | 表示 **p 是指针** |
| `*p`（表达式中） | **解引用**：取 p 指向的值 |

```c
int *p;        // ① 声明：p 是 int 指针
p = &x;        // p 现在存 x 的地址
printf("%d", *p);   // ② 解引用：读 x 的值
*p = 5;        // ② 解引用：写 x
```

### 1.4 内存演化图（跟着代码走）

```c
1  int *p;
2  int x = 3;
3  p = &x;
4  printf("p points to %d\n", *p);
5  *p = 5;
```

| 执行到 | `p` 的值 | `x` 的值 |
|---|---|---|
| 第 1 行后 | `???`（未初始化！） | — |
| 第 2 行后 | `???` | `3` |
| 第 3 行后 | **`0x104`**（x 的地址） | `3` |
| 第 4 行后 | `0x104` | `3`（只读） |
| 第 5 行后 | `0x104` | **`5`**（被改写） |

### 1.5 ⚠️ 指针的风险

> **Pointers are probably the single largest source of bugs in C.**

- 动态内存管理时最易出问题
- **悬垂引用（dangling references）**
- **内存泄漏（memory leaks）**

## 二、为什么需要指针

### 2.1 C 是「按值传递」（pass-by-value）

> **函数参数得到的是实参值的副本。改副本，改不动原件。**

```c
void addOne(int x) {
    x = x + 1;      // 改的是副本
}

int y = 3;
addOne(y);
// ⚠ y 仍然是 3
```

### 2.2 用指针就能改

```c
void addOne(int *p) {
    *p = *p + 1;    // 通过地址改原件
}

int y = 3;
addOne(&y);
// ✅ y 现在是 4
```

### 2.3 另外两个理由

| 理由 | 说明 |
|---|---|
| **传大对象更高效** | 传 `struct` 或数组的指针，避免复制大量数据 |
| **历史原因** | 1970 年代编译器优化差，C 把灵活性交给程序员；**如今计算机快 10 万倍，编译器也强得多** |

### 2.4 ⚠️ 常见 bug：垃圾地址

> **声明一个指针，只是分配了「存指针的空间」，并没有分配「它要指的东西」！**

```c
void f() {
    int *ptr;      // 未初始化，ptr 里是垃圾值
    *ptr = 5;      // 💥 往一个随机地址写 5
}
```

## 三、指针的进阶用法

### 3.1 指向不同类型的指针

```c
int *xptr;                    // 指向 int
char *str;                    // 指向 char
struct llist *foo_ptr;        // 指向结构体
```

> **正常情况下，一个指针只能指向一种类型。**

### 3.2 `void *`：通用指针

```c
void *p;   // 可以指向任何东西
```

> **慎用**——它会导致程序 bug、安全问题等。

### 3.3 函数指针

```c
int (*fn)(void *, void *) = &foo;
// fn 是一个函数，接受两个 void* 参数，返回 int
```

### 3.4 NULL 指针

> **全 0 的指针是特殊的。**

```c
char *p = NULL;      // p = 0x00000000
```

- **读写 null 指针 → 程序应当崩溃**
- **因为 0 为假，判断很容易：**

```c
if (!p) { /* p 是空指针 */ }
if (q)  { /* q 不是空指针 */ }
```

### 3.5 结构体指针

```c
typedef struct {
    int x;
    int y;
} Coord;

Coord coord1, coord2;
Coord *ptr1, *ptr2;

/* 点号记法 */
int h = coord1.x;
coord2.y = coord1.y;

/* 箭头记法 = 解引用 + 取成员 */
int k;
k = (*ptr1).x;
k = ptr1->x;      // 等价，更常用
```

> ⚠️ `ptr1 = ptr2;` **会编译通过**，但它只复制了**地址**，不是结构体内容。

## 四、数组与指针算术

### 4.1 数组就是一大块内存

```c
int arr[2];                  // 声明 2 元素 int 数组
int arr[] = {795, 635};      // 声明 + 初始化
```

```
arr ──> [ 795 ][ 635 ]
```

### 4.2 索引是语法糖

> **`a[i]` ⟺ `*(a+i)`**

```c
arr[0];      // 795
arr[1];      // 635
*(arr+1);    // 635（等价写法）
```

### 4.3 指针算术规则

| 运算 | 实际效果 |
|---|---|
| **`pointer + n`** | 地址 **加 `n × sizeof(指向的类型)`** |
| **`pointer - n`** | 地址 **减 `n × sizeof(指向的类型)`** |

```c
// 32 位无符号 int 数组
uint32_t arr[] = {50, 60, 70};
uint32_t *q = arr;

// 假设 arr 在 0x100
// arr[0] @ 0x100 = 50
// arr[1] @ 0x104 = 60   ← 每个 int 占 4 字节
// arr[2] @ 0x108 = 70

printf("*q: %d is %d\n", *q, q[0]);        // 50 is 50
printf("*(q+1): %d is %d\n", *(q+1), q[1]); // 60 is 60
printf("*(q-1): %d is %d\n", *(q-1), q[-1]); // 越界！
```

> **关键**：`q+1` 不是「地址 +1」，而是 **「地址 +4」**，因为类型是 `uint32_t`。

### 4.4 ⚠️ 想让函数改变「指针的指向」？要传指针的指针

**失败的尝试：**

```c
void increment_ptr(int32_t *p) {
    p = p + 1;      // 只改了副本
}

int32_t arr[3] = {50, 60, 70};
int32_t *q = arr;
increment_ptr(q);
printf("*q is %d\n", *q);   // 输出：*q is 50（没变！）
```

**原因**：C 是 pass-by-value，`p` 是 `q` 的**副本**。

**正确做法：传「指针的指针」（handle）**

```c
void increment_ptr(int32_t **h) {
    *h = *h + 1;    // 改的是 q 本身
}

int32_t arr[3] = {50, 60, 70};
int32_t *q = arr;
increment_ptr(&q);
printf("*q is %d\n", *q);   // 输出：*q is 60 ✅
```

**声明方式**：`data_type **h`

## 五、数组的陷阱

### 5.1 陷阱 #1：魔法数字

**不好的写法：**

```c
int i, arr[10];
for (i = 0; i < 10; i++) { ... }    // 10 出现两次
```

**推荐写法：**

```c
int ARRAY_SIZE = 10;
int i, a[ARRAY_SIZE];
for (i = 0; i < ARRAY_SIZE; i++) { ... }
```

> **Why? SINGLE SOURCE OF TRUTH!**
> 避免维护两份相同的数字。

### 5.2 数组 vs 指针：几乎相同，但有关键差异

| 表达 | 是否等价 |
|---|---|
| `char *string` vs `char string[]` | **几乎**完全一样 |
| `arr[0]` vs `*arr` | ✅ 相同 |
| `arr[2]` vs `*(arr+2)` | ✅ 相同 |

**但**：

- 递增操作不同
- 声明已填充数组的方式不同
- **K&R 原话：`An array name is not a variable.`**

### 5.3 数组的真实布局（容易误解）

```c
int *p, *q, x;
int a[4];
p = &x;
q = a + 1;

*p = 1;
printf("*p:%d, p:%x, &p:%x\n", *p, p, &p);
*q = 2;
printf("*q:%d, q:%x, &q:%x\n", *q, q, &q);
*a = 3;
printf("*a:%d, a:%x, &a:%x\n", *a, a, &a);
```

**输出：**

```
*p:1, p:108, &p:100      ← p 自己存在 0x100，值是 0x108
*q:2, q:110, &q:104      ← q 自己存在 0x104，值是 0x110
*a:3, a:10c, &a:10c      ← 注意！a 和 &a 相同
```

> **`a` 和 `&a` 输出相同**——因为数组名「**不是一个变量**」，它没有自己的存储，只是一个指向首元素的常量标记。

### 5.4 陷阱 #2：数组边界不检查

```c
int N = 100;
int foo[N];
int i;
for (i = 0; i <= N; ++i) {    // ⚠ 应该是 < N
    foo[i] = 0;               // 写越界！
}
```

**后果：**

- 破坏程序的其他部分（**包括 C 内部的元数据**）
- 可能**很久之后**才崩溃
- 这叫 **Buffer overflow（缓冲区溢出）**——也是**最常见的安全漏洞**

### 5.5 陷阱 #3：数组作为参数会「退化」成指针

```c
// 这两个签名等价：
int bar(int arr[], unsigned int size)
int bar(int *arr,    unsigned int size)
```

> **后果：数组大小信息丢失！** 用 `sizeof()` 要格外小心。

**所以必须显式传长度：**

```c
bar(a, 5);    // 数组 + 长度一起传
```

### 5.6 陷阱 #4：局部数组在作用域结束后失效

```c
// ❌ 错误
char *foo() {
    char string[32];
    ...
    return string;    // 返回栈上数组的地址 → 悬垂引用
}
```

> **解决方案**：动态内存分配（`malloc`，见 L05）

### 5.7 三大陷阱总结

| # | 陷阱 | 后果 |
|---|---|---|
| 1 | **边界不检查** | Buffer overflow |
| 2 | **传参退化为指针** | 大小信息丢失 |
| 3 | **只在作用域内有效** | 悬垂引用 |

> 后果：**Segmentation fault、bus error……而且极难定位。**
> Lab 02 会用 `gdb` 教你调试这些。

## 六、字符串

### 6.1 C 字符串的本质

> **C 字符串就是「字符数组 + null 终止符」。**

- **Null terminator**：字节 0（数字），也就是 `'\0'` 字符

```c
char str[] = "abc";
```

```
str ──> [ 'a' ][ 'b' ][ 'c' ][ '\0' ]
          0x0    0x1    0x2    0x3
```

> **长度为 3，但内存需要 4 字节。**

### 6.2 标准库的假设

`<string.h>` **假定字符串以 null 终止**。

**`strlen` 的可能实现：**

```c
int strlen(char s[]) {
    int n = 0;
    while (s[n] != '\0') n++;
    return n;
}
```

```c
strlen(str);   // 3（不含 '\0'）
```

> ⚠️ Lab 01 会讲 `strcpy()` vs `strncpy()` 的安全差异。

## 七、内存布局与字节序（补充）

### 7.1 如何读字节地址

```
      +3   +2   +1   +0
0x0   xx   xx   xx   xx
0x4   xx   xx   xx   xx
...
```

> **每个字（word，通常 4 字节）从高地址往低地址排**，`+0` 是最低地址。

### 7.2 Word Alignment（字对齐）

> 我们通常希望**字对齐**：
> 某些 32 位处理器**不允许**你访问不在 4 字节边界上的 32 位值。

### 7.3 Endianness（字节序）

**hive 机器是 little endian（小端）：**

> **一个字里，最低有效字节（LSB）存在最低地址。**

```
int32_t value = 0x12345678;

地址        值
0x...168   0x78   ← LSB 在前
0x...169   0x56
0x...16A   0x34
0x...16B   0x12
```

**对比 big endian（大端）：** `0x12 0x34 0x56 0x78`（MSB 在前）

**gdb 验证：**

```bash
$ gdb endianness
(gdb) b 12              # 在第 12 行设断点
(gdb) r                 # 运行
(gdb) p/x str           # 看字符串字节
(gdb) p/x str2          # 看一个 word（十六进制）
(gdb) x/1wx 0x7fffffffe164
(gdb) <enter>           # 重复上一个命令
```

### 7.4 结构体的内存布局与 padding

```c
struct foo {
    int32_t a;
    char b;
    struct foo *c;
};
```

**32 位架构上的实际布局：**

```
      +3   +2   +1   +0
0x0   a    a    a    a      ← 4 字节 for a
0x4   pad  pad  pad  b      ← 1 字节 for b + 3 字节 padding
0x8   c    c    c    c      ← 4 字节 for c
```

> **`sizeof(struct foo) == 12`**（不是 9）
> **原因**：编译器为了**对齐**，插入了 **3 字节 padding**。

> 课程原话：**「A struct 其实就是告诉 C：如何把一堆字节排在一个桶里。」**

## 八、本讲总结（课程原话）

- **C 的指针和数组几乎一样**，除了函数调用时
- **C 知道如何递增指针**（按类型大小）
- **C 是高效的语言，但几乎没有保护**：
  - 数组越界**不检查**
  - 变量**不自动初始化**
- **用 handle（指针的指针）来改变指针**
- **字符串是带 null 终止符的字符数组**
  - 长度 = 字符数，但**内存要多 1 字节存 `\0`**
- ⚠️ **效率的代价是程序员更多的负担**

## 九、我的笔记与理解

### 9.1 本讲的知识密度最高

L04 是前半程**最难的一讲**，因为它把 C 的三个核心概念一次讲完：

```
指针  →  地址 + 解引用 + 指针算术
数组  →  本质是指针 + 语法糖
字符串  →  本质是数组 + null 终止
```

**三者是同一件事的不同视角。**

### 9.2 为什么指针这么难

因为它**打破了两层通常的抽象**：

| 普通变量 | 指针 |
|---|---|
| 名字 → 值 | 名字 → 地址 → 值 |
| 一层间接 | **两层间接** |

再加 C 的「不检查、不初始化」，就很容易出错。

### 9.3 三个必记的等价关系

```c
a[i]  ⟺  *(a + i)
&a    ⟺  a              （数组名没有自己的存储）
ptr->x ⟺ (*ptr).x
```

### 9.4 为什么 `a` 和 `&a` 输出相同

这是本讲最反直觉的点：

- `a` 是**数组名**，它不是变量，**没有自己的存储空间**
- 它的「值」就是**首元素地址**
- `&a` 求「数组的地址」——而数组的起始地址**就是首元素地址**

> 所以两者数值相同，但**类型不同**：
> - `a` 的类型是 `int *`（退化后）
> - `&a` 的类型是 `int (*)[N]`（指向整个数组的指针）

**这解释了为什么 `a+1` 和 `&a+1` 差得很多**：
- `a+1` → 前进 1 个元素（4 字节）
- `&a+1` → 前进**整个数组**（4N 字节）

### 9.5 缓冲区溢出的安全意义

```c
for (i = 0; i <= N; ++i) foo[i] = 0;   // 越界 1 个
```

这 1 个越界写，可能覆盖的正是：
- 相邻变量的值
- **函数的返回地址**（→ 经典栈溢出攻击）
- 堆上的元数据

> **这就是为什么 C 程序是安全漏洞的重灾区。** Rust 的诞生正是为了解决这个。

### 9.6 与 L05 的衔接

本讲留了两个「下次再说」：

| 问题 | 答案在 |
|---|---|
| 局部数组返回后失效，怎么解决？ | **L05：malloc / 堆** |
| 数组大小丢失，怎么处理？ | **L05：显式传长度** |

## 十、术语速查

| 术语 | 中文 | 说明 |
|---|---|---|
| **dereference** | 解引用 | `*p` 取指针指向的值 |
| **address-of** | 取地址 | `&x` |
| **dangling reference** | 悬垂引用 | 指向已释放的内存 |
| **memory leak** | 内存泄漏 | 分配了但没释放 |
| **pointer arithmetic** | 指针算术 | `p+n` 按类型大小偏移 |
| **array decay** | 数组退化 | 传参时数组名变指针 |
| **buffer overflow** | 缓冲区溢出 | 写越界 |
| **null terminator** | 空终止符 | `'\0'`，值为 0 |
| **endianness** | 字节序 | little / big endian |
| **padding** | 填充 | 为对齐插入的空字节 |
| **handle** | 句柄 | 指针的指针 `**h` |
