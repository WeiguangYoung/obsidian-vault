| **2^60** | **exbi** | ~10¹⁸ | |
| **2^70** | **zebi** | ~10²¹ | |
| **2^80** | **yobi** | ~10²⁴ | |

> **课件标注：「MEMORIZE！」**

### 1.2 练习：2³⁴？

> **2³⁴ = 2⁴ × 2³⁰ = 16 GiB**

### 1.3 「2.5 TiB 需要多少位地址？」

```
2.5 TiB ≈ 2^41 字节（2 TiB = 2^41，2.5 略大）
lg(2^41) = 41 位
```

> **答案：约 41–42 位。**

### 1.4 ⚠️ 两种单位的陷阱

| 单位制 | 谁在用 | 后果 |
|---|---|---|
| **Base-10（SI）** | **硬盘厂商、电信** | **「1 TB」实际只有约 90% 的预期容量** |
| | | **1 Mbit/s 连接 = 10⁶ bps** |
| **Base-2（IEC）** | **RAM 和缓存** | **本课严格区分** |

> ⭐ **「RAM 和缓存用 2 的幂。」**
> **买 1TB 硬盘只得到 931 GiB —— 就是这个原因。**

## 二、⭐ 图书馆类比

### 2.1 为什么大内存慢

> **「在大图书馆找一本书要多久？」**

| 步骤 | 延迟来源 |
|---|---|
| **① 查卡片目录** | **把「书名/作者」映射到「索引号」** |
| **② 往返走书库取书** | **物理距离** |

> **「图书馆越大，两个延迟都越糟。」**

### 2.2 电子内存的同样问题

> **「电子内存有同样的问题，而且「存储一位所用的技术」也随密度增加而变慢（例如 SRAM vs DRAM vs 磁盘）。」**

| 技术 | 速度 | 密度 | 成本 |
|---|---|---|---|
| **SRAM** | **最快（0.5 ns）** | 最低 | 最高 |
| **DRAM** | 中（~10 ns）| 中 | 中 |
| **磁盘/SSD** | 慢（μs–ms）| 最高 | 最低 |

> ⭐ **「我们想要的是：又大又快的内存！」**
> **—— 这在物理上不可能，所以需要「层次结构」。**

### 2.3 写报告的类比

> **用图书馆的书写报告（例如 J.D. Salinger 的作品）：**

| 动作 | 对应 |
|---|---|
| **① 去图书馆查书、从书库取出、放到阅览桌上** | **把数据取到 cache** |
| **② 如果需要更多，借出来放在自己桌上** | **放到更近的层级** |
| **③ 「不要把先借的书还回去 —— 可能还要用！」** | **局部性：保留最近用过的** |

> ⭐ **「你希望桌上这 10 本书就够写报告，尽管 10 本只占 UC Berkeley 图书馆藏书的 0.00001%。」**

> **这就是缓存的核心赌注：一小部分数据能满足大部分需求。**

## 三、⭐ 处理器-DRAM 差距

### 3.1 历史对比

| 年代 | 差距 |
|---|---|
| **1980** | **微处理器执行约 1 条指令 = 1 次 DRAM 访问** |
| **2020** | **微处理器执行约 1000 条指令 = 1 次 DRAM 访问** |

> ⭐ **「慢速 DRAM 访问对 CPU 性能有灾难性影响！」**

### 3.2 这个差距怎么来的

```
CPU 性能：每年 ~50%（1986–2003），之后 ~20%
DRAM 延迟：每年 ~7%
        ↓
差距不断扩大
```

> **这就是「Memory Wall（内存墙）」—— 处理器等数据的时间越来越长。**

## 四、⭐ 存储层次（Memory Hierarchy）

### 4.1 Great Idea #3

> **「原理：局部性 / 存储层次」**

```
        极快              极贵            极小容量
    ┌──────────┐
    │  寄存器   │  ← Processor chip
    └──────────┘
        更快            更贵          小容量
    ┌──────────┐
    │  L1 缓存  │  ← On-chip
    └──────────┘
        快              价格合理        中等容量
    ┌──────────┐
    │ 主存 DRAM │  ← DDR3/4/5、HBM/HBM2/3
    └──────────┘
```

> ⭐ **「Cache 听起来像 Cash，所以用 `$` 简写。」** —— UC Berkeley EECS 的发明

### 4.2 Jim Gray 的距离类比

> **「数据离你有多远？」** —— Jim Gray（图灵奖，Cal 1966 学士 / 1969 博士）

| 层级 | 延迟 | 类比距离 |
|---|---|---|
| **寄存器** | **< 1 ns** | **「我的脑袋」** |
| **On-chip cache** | **~1 ns** | **「这个房间」** |
| **内存** | **~100 ns** | **「萨克拉门托」（1.5 小时）** |

> ⭐ **「100 ns 外的数据 ≈ 开车 1.5 小时去取。」**

### 4.3 各层的「块大小」

> **「每一层的数据块大小：」**

| 层 | 块大小 |
|---|---|
| **寄存器** | **4–8 字节（word）** |
| **Cache ($)** | **8–32 字节（block）** |
| **主存** | **1 到 4 个块** |
| **二级存储** | **1,024+ 字节（磁盘扇区 = page）** |

### 4.4 ⭐ 包含性（Inclusion）

> **「L1 缓存里的内容 ⊂ 主存里的内容 ⊂ 二级存储里的内容」**

```
L1$ ⊆ MM ⊆ SM
```

> **「包含性（Inclusive）」—— 上层是下层的「子集」。**

### 4.5 典型层次的量化

| 层 | 大小 | 成本 | 速度（周期）|
|---|---|---|---|
| **RegFile** | **几百字节** | **最高** | **½** |
| **Instr Cache** | **几十 KB** | | **1** |
| **Data Cache** | **几十 KB** | | **1** |
| **Main Memory（DRAM）** | **几十 GB** | | **几百** |
| **Secondary（Disk/Flash）** | **几 TB** | **最低** | **上千万** |

> ⭐ **「速度跨度：0.5 周期 → 10,000,000 周期。」**

### 4.6 ⭐ 核心抽象

> **「抽象：给处理器呈现出「最大容量（用最便宜的技术）+ 最快速度（用最快的技术）」的内存。」**

| 事实 | 说明 |
|---|---|
| **每一层更靠近处理器则** | ✅ **更小** |
| | ✅ **更快** |
| | ✅ **更贵** |
| | ✅ **是下层的子集（含最近使用数据）** |
| **最低层（磁盘）** | **含全部可用数据** |

> ⭐ **「存储层次给处理器一个「巨大且极快内存」的幻觉。」**
> **—— 这就是 Abstraction 的力量。**

## 五、各层技术详解

### 5.1 主存 = DRAM

> **Dynamic Random Access Memory**

| 参数 | 值 |
|---|---|
| **首次访问延迟** | **~10 ns（~30–40 处理器周期）** |
| **后续连续访问** | **0.5–1 ns** |
| **每次取多少** | **64 位（8 字节），支持 burst** |
| **成本** | **~$3/GB** |

**两个「缺陷」（其实是设计取舍）：**

| 特性 | 含义 |
|---|---|
| **Dynamic（动态）** | **用电容存位，需要周期性刷新（refresh）来维持电荷** |
| **Volatile（易失）** | **断电即丢数据** |

> ⭐ **「D（动态）+ V（易失）= 便宜 + 高密度。」**

### 5.2 SRAM（用于缓存）

> **Static RAM**

| 特性 | 说明 |
|---|---|
| **Static（静态）** | **无电容** |
| **Volatile** | **仍然易失** |
| **速度** | **更快（0.5 ns）** |
| **成本** | **更贵、密度更低** |

> **「现在也做非易失 SRAM（nvSRAM）—— 对医疗应用有用。」**

### 5.3 二级存储

> **作为外设 I/O 设备连接。非易失（non-volatile）。**

| 类型 | 访问延迟 | 成本 |
|---|---|---|
| **SSD（固态硬盘）** | **40–100 μs（~10 万周期）** | **$0.05–0.5/GB** |
| | 通常是 flash 存储 | |
| **HDD（机械硬盘）** | **< 5–10 ms（1000–2000 万周期）** | **$0.01–0.1/GB** |
| | **机械式** | |

> ⭐ **SSD 比 HDD 快 100 倍、贵 5 倍 —— 典型的「性能换成本」。**

## 六、⭐ 局部性原理

### 6.1 缓存在做什么

> **「缓存包含「正在被使用的数据」的副本。」**
> **「缓存基于「时间局部性」和「空间局部性」两个原理工作。」**

### 6.2 两种局部性

| 原理 | 定义 | 图书馆类比 | 内存含义 |
|---|---|---|---|
| **Temporal Locality（时间局部性）** | **「现在用了它，很可能「很快还会再用」」** | **「去借另一本书时，把这本书留在桌上」** | **「如果一个内存位置被引用，它很快会被再次引用 → 把最近访问的数据靠近处理器」** |
| **Spatial Locality（空间局部性）** | **「用了一块内存，很可能「很快会用到邻近的块」」** | **「既然借了第 1 卷，就顺手借第 2 卷」** | **「如果一个内存位置被引用，附近地址很快也会被引用 → 把「连续的多个字」组成的行移到靠近处理器」** |

> ⭐ **「缓存 = 「赌你还会再用」。**
> **时间局部性 = 赌同一个地址；空间局部性 = 赌邻居地址。」**

### 6.3 两种局部性的代码示例

**时间局部性（循环变量）**

```c
for (int i = 0; i < n; i++)
    sum += a[i];      // i 每次循环都被访问
```

**空间局部性（数组）**

```c
for (int i = 0; i < n; i++)
    sum += a[i];      // a[0], a[1], a[2]... 连续地址
```

**两者兼有：**

```c
for (int i = 0; i < n; i++)
    sum += a[i];      // i 时间局部 + a[i] 空间局部
```

> ⭐ **这段代码同时吃两种红利 —— 这就是为什么数组遍历这么快。**

## 七、⭐ 缓存的四个设计问题

> **「我们如何组织缓存？」**

| # | 问题 |
|---|---|
| **①** | **每个内存地址映射到缓存的「哪里」？** |
| | **（记住：缓存是内存的子集，所以多个内存地址映射到同一个缓存位置）** |
| **②** | **我们怎么知道「哪些元素在缓存里」？** |
| **③** | **我们怎么「快速定位」它们？** |
| **④** | **替换策略：缓存满了踢谁？** |

> ⭐ **这四个问题就是 L27–L29 的全部内容。**

## 八、⭐ 层次由谁管理

> **「层次结构是如何管理的？」**

| 层间 | 管理者 |
|---|---|
| **寄存器 ↔ 内存** | **编译器（或汇编级程序员）** |
| **缓存 ↔ 主存** | **缓存控制器硬件** |
| **主存 ↔ 磁盘** | **操作系统（虚拟内存）** |
| | **虚拟→物理地址映射由硬件辅助（TLB）** |
| **文件** | **程序员** |
| | **（文件也是一种缓存）** |

> ⭐ **「每一对的「局部性管理者」不同 —— 这是理解整个系统的关键。」**

**为什么是这些分工：**

| 层间 | 为什么是它 |
|---|---|
| **寄存器↔内存** | 编译器知道变量生命周期 |
| **缓存↔主存** | 硬件必须「透明」且「极快」 |
| **内存↔磁盘** | OS 有全局视角 + 需要安全隔离 |

## 十、我的笔记与理解

### 10.1 「缓存」这个词的双重含义

```
① 硬件缓存（L1/L2/L3）  ← 本讲主题
② 任何「把常用数据放近处」的结构  ← 文件缓存、DNS 缓存、浏览器缓存
```

> ⭐ **「文件也是一种缓存」—— 课件明确这么说。**
> **因为「磁盘上的文件」是对「持久存储」的缓存。**

### 10.2 为什么必须「包含性（Inclusive）」

> **如果 L1 里有 L2 没有的数据会怎样？**

| 场景 | 后果 |
|---|---|
| **L1 有、L2 没有（非包含）** | 从 L1 踢出的数据直接丢失 → 需要写回复杂逻辑 |
| **L1 ⊆ L2 ⊆ MM（包含）** | ✅ 简单：踢出时下层一定有一份 |

> ⭐ **包含性让「写回策略」简单化 —— 这是工程取舍。**

> **（现代 CPU 有「非包含（exclusive）」设计，但需要更多簿记。）**

### 10.3 「1000 条指令 = 1 次 DRAM 访问」的含义

> **如果每条指令都要访存，性能会下降 1000 倍。**

**实际的影响：**

| 情况 | 影响 |
|---|---|
| **命中缓存（L1）** | 1 周期，无影响 |
| **命中 L2** | ~10 周期 |
| **命中 L3** | ~40 周期 |
| **miss 到 DRAM** | **~200–400 周期** ← 灾难 |

> ⭐ **「99% 命中率」听起来很好，但 1% miss × 300 周期 = 平均 3 周期额外开销 —— 相当于 CPI 从 1 变 4。**

> **这就是为什么缓存设计是 CPU 设计中最关键的环节之一。**

### 10.4 图书馆类比的两个层次

> **类比其实揭示了「两个独立的延迟」：**

| 延迟 | 对应硬件 |
|---|---|
| **① 查目录（找索引）** | **TLB 查表（虚地址→物理地址）** |
| **② 走书库（取数据）** | **访问内存阵列** |

> ⭐ **「大图书馆的两个延迟都变糟」—— 对应「更大的内存 → 更大的页表 + 更长的布线」。**

### 10.5 DRAM 的「Dynamic」不是缺陷

> **「电容需要刷新」听起来很差。**

**但正是它让 DRAM 便宜：**

| 设计 | 每 bit 的晶体管数 |
|---|---|
| **SRAM** | **6 个（6T）** |
| **DRAM** | **1 个 + 1 个电容** |

> ⭐ **「6 倍面积差 = 6 倍成本差 = 为什么缓存贵、内存便宜。」**

> **刷新开销（~1% 时间）换来 6 倍密度 —— 极其划算。**

### 10.6 为什么「每层更贵更小」是必然

> **因为「更快」需要「更少的容量」：**

```
延迟 ≈ 物理距离（电容充放电、信号传播）
容量 ≈ 面积
```

**在固定面积下：**

> **要么「很多慢单元」要么「少量快单元」。**

> ⭐ **层次结构不是「设计选择」，而是「物理约束下的必然」。**
> **—— 寄存器、缓存、内存、磁盘，每一层都是「速度/容量/成本」三角上的不同点。**

### 10.7 与前面讲的呼应

| 前面讲的 | 在缓存这里的作用 |
|---|---|
| **L19 ALU**（组合逻辑）| cache 的 tag 比较器 |
| **L18 关键路径** | cache 访问时间 = 关键路径 |
| **L23 流水线** | IF/MEM 阶段要等 cache |
| **L24 结构冒险** | IMEM/DMEM = L1i/L1d |
| **L17 布尔代数** | cache 的「valid 位 + tag 比较」逻辑 |

> ⭐ **「IMEM 和 DMEM 就是 L1i 和 L1d」—— L24 说的这句话，现在落地了。**

## 十一、术语速查
