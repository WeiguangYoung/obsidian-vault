# CS61C FA26 · L05 C Memory (Mis)Management

> UC Berkeley · Great Ideas in Computer Architecture
> 授课：Dan Garcia
> 对应课件 05-C Memory (Mis)Management（46 页）
> 本讲对应 **Great Idea #1：Abstraction**（内存的分区与管理）

> 标题里的 **"(Mis)Management"** 是双关：既是「内存管理」，也是「**管理不善**」——这正是 C 的主要 bug 来源。

---

## 一、热场题：`sizeof` 的陷阱

```c
// 假设 hive 架构：short 是 16 位，指针是 64 位
void mystery(short arr[], int len) {
    printf("%d ", len);
    printf("%d\n", sizeof(arr));
}

int main() {
    short nums[] = {1, 2, 3, 99, 100};
    printf("%d ", sizeof(nums));
    mystery(nums, sizeof(nums)/sizeof(short));
}
```

**输出**：`10 5 8`

| 位置 | 值 | 为什么 |
|---|---|---|
| `sizeof(nums)` in main | **10** | 数组在其**声明作用域内**，总大小 = 5 × 2 字节 |
| `len` | **5** | `10 / 2` |
| `sizeof(arr)` in mystery | **8** | ⚠️ **数组已退化成指针**，指针是 8 字节 |

> **这就是 L04 说的「数组传参后大小信息丢失」的真实后果。**

## 二、数组的本质（回顾与深化）

### 2.1 数组不是指针

| 说法 | 出处 |
|---|---|
| **A pointer is a variable.** | 定义 |
| **"An array name is not a variable."** | K&R |
| **"A C array is really just a big block of consecutive things in memory with certain properties."** | Dan Garcia |

### 2.2 数组的两个关键性质

1. **数组索引是语法糖**：`a[i] ⟺ *(a+i)`
2. **数组名在作为函数参数时会「退化」成指针**

```c
// 形式参数 int arr[] 实际上就是 int *arr
int bar(int arr[], unsigned int size) { ... }
```

> **后果：数组大小丢失，`sizeof()` 结果不可靠。**
> **必须显式传长度。**

### 2.3 数组的三个原始缺陷（复习）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 访问时不检查边界 | Buffer overflow |
| 2 | 传参退化成指针 | 大小丢失 |
| 3 | 声明数组只在作用域内有效 | 悬垂引用 |

第 3 点是本讲的重点——**它和栈的工作方式直接相关**。

## 三、内存、字与字节序

### 3.1 字节编址

> **现代机器是 byte-addressable（按字节编址）。**

- 硬件内存由 **8 位存储单元**组成
- **每个字节有唯一地址**
- 我们常按 **word size**（字长）思考：也就是**地址的位数**

```
      +3   +2   +1   +0
0x0   xx   xx   xx   xx
0x4   xx   xx   xx   xx
0x8   xx   xx   xx   xx
...
```

### 3.2 实际内存示例

```c
#include <stdio.h>
#include <stdint.h>

int main(int argc, char *argv[]) {
    int32_t value = 0x12345678;
    ...
}
```

```
地址             +3    +2    +1    +0
0x...164         0xaa  0xbb  xx    xx
0x...168         0x12  0x34  0x56  0x78   ← value
0x...16C         'y'   'b'   xx    xx
0x...170         'e'   'h'   '\0'  'e'    ← 字符串
0x...174         '\0'  'o'   'l'   'l'
```

### 3.3 Endianness（字节序）

> **hive 机器是 little endian（小端）。**
> **字的最低位字节（LSB）存在最低地址。**

`0x12345678` 在小端下：

```
最低地址 → 0x78 0x56 0x34 0x12 ← 最高地址
```

对比 **big endian（大端）**：`0x12 0x34 0x56 0x78`（MSB 在前）

> **实际影响**：跨机器交换二进制数据时必须约定字节序（网络协议统一用 big endian）。

### 3.4 Word Alignment（字对齐）

> 我们通常希望**字对齐**——某些 32 位处理器**不允许**访问不在 4 字节边界上的 32 位值。

### 3.5 结构体的 padding（再访）

```c
struct foo {
    int32_t a;        // 4 字节
    char b;           // 1 字节
    struct foo *c;    // 4 字节（32 位架构）
};
```

**实际布局（32 位）：**

```
      +3   +2   +1   +0
0x0   a    a    a    a        ← 4 字节
0x4   pad  pad  pad  b        ← 1 字节 + 3 字节 padding
0x8   c    c    c    c        ← 4 字节
```

> **`sizeof(struct foo) == 12`**（而不是 9）

**原话**：**「A struct 其实就是告诉 C：如何把一堆字节排在一个桶里。」**

## 四、C 程序的内存布局

### 4.1 四个区域（高地址在上）

```
0xFFFF FFFF  ┌──────────────────┐
             │      Stack       │  ← 局部变量，向下增长
             │        ↓         │
             │                  │
             │        ↑         │
             │       Heap       │  ← malloc 分配，向上增长
             ├──────────────────┤
             │  Data (Static)   │  ← main 外部声明的变量，不增不减
             ├──────────────────┤
             │  Text (Code)     │  ← 程序启动时载入，不改变
0x00000000   └──────────────────┘
```

| 区域 | 内容 | 增长 |
|---|---|---|
| **Stack** | 函数内部的局部变量 | **向下** |
| **Heap** | `malloc()` 请求的空间 | 动态，**向上** |
| **Data（Static）** | `main` 外部声明的变量 | 不增不减 |
| **Text（Code）** | 程序代码 | 不变 |

> ⚠️ **`0x00000000` 附近的 chunk 不可读写**，这样访问 NULL 指针会立刻崩溃（而不是静默出错）。

### 4.2 必须知道数据存在哪

> **C 编程要求你知道数据在内存的哪里。** 否则行为和预期不符。
> 相比之下，**Java 隐藏了对象的位置**。

| 声明位置 | 归属 | 何时释放 |
|---|---|---|
| 函数外 | **Global**，在 data 段 | 程序结束 |
| 函数内（如 `main()`） | **Local**，在栈上 | **函数返回时** |

> 这两者都是「**自动内存管理**」——你不用操心释放。**难点在于堆。**

## 五、栈（Stack）

### 5.1 栈帧（Stack Frame）

> **每次函数调用，都会在栈上分配一个新的栈帧。**

**栈帧里装什么：**

- 局部变量的空间
- **返回地址**——「谁调用了我？」
- **函数参数**

```c
fooA() { fooB(); }
fooB() { fooC(); }
fooC() { ... }
```

```
┌──────────────┐
│ fooA 的 frame │  ← 先压入
├──────────────┤
│ fooB 的 frame │
├──────────────┤
│ fooC 的 frame │  ← 最后压入，最先弹出
└──────────────┘
```

### 5.2 函数结束后栈帧被「扔掉」

- 函数结束时，栈帧被弹出
- 内存被「**释放**」给后续的栈帧复用
- **栈帧构成连续的内存块**
- **栈指针（stack pointer, sp）** 决定「栈顶在哪」

### 5.3 栈是 LIFO（后进先出）

```c
int main() { a(0); ... }
void a(int m) { b(1); }
void b(int n) { c(2); }
void c(int o) { d(3); }
void d(int p) { }
```

```
栈（从 0xFFFFFFFF 向下增长）
┌────────┐
│  main  │  ← 最高地址
├────────┤
│   a    │
├────────┤
│   b    │
├────────┤
│   c    │
├────────┤
│   d    │  ← 最低地址（栈顶）
└────────┘
0x00000000
```

> **栈向下增长**：`a()` 的局部变量地址**低于** `main()` 的。
> **sp 决定「分配」与「释放」。**

### 5.4 ⚠️ 为什么不能返回栈上的指针

```c
// ❌ 错误
char *foo() {
    char string[32];
    ...
    return string;
}
```

**原因**：`string` 在 `foo` 的栈帧里。`foo` 一返回，栈帧被弹出，**那块内存会被后续的函数调用覆盖**。

### 5.5 什么时候用栈指针是安全的

| 操作 | 安全性 |
|---|---|
| **把栈上的东西的指针作为参数传进去** | ✅ 安全（数据仍在有效栈帧里） |
| **返回指向栈上的指针** | ❌ **灾难性** |

> **后果**：**Dangling reference（悬垂引用）**——你的数据不再保证存在。

## 六、堆（Heap）

### 6.1 什么是堆

> **堆是动态内存**：可以在**运行时**分配、调整大小、释放。

- 适合需要**跨函数调用持久存在**的内存
- 类似 Java 的 `new`，**但关键差异导致 C 最大的内存泄漏/bug 来源**

**特点：**

- **巨大的内存池**（通常远大于栈）
- **不按连续顺序分配**：连着的请求可能拿到相距很远的块
- **但单次请求返回的是连续内存块**

### 6.2 `malloc`：分配

```c
void *malloc(size_t n)
```

| 项 | 说明 |
|---|---|
| `size_t n` | 无符号整数类型，大到足以「数」内存字节 |
| 返回 | 指向堆上内存块的 `void *` |
| **返回 NULL** | 表示**内存耗尽**——**必须检查！** |
| 内存内容 | **未初始化**（不是清零！） |

**用法示例：**

```c
// 分配一个结构体
typedef struct { ... } TreeNode;
TreeNode *tp = malloc(sizeof(TreeNode));

// 分配 20 个 int 的数组
int *ptr = malloc(20 * sizeof(int));
```

> **`sizeof(type)`**：返回该类型的字节数。**注意不要写死数字。**

### 6.3 要不要给 malloc 的返回值加类型转换？

```c
// 现代 C：隐式转换，可以直接写
TreeNode *tp = malloc(sizeof(TreeNode));        // ✓ okay

// 前 ANSI C（1990 前）：必须显式转换
TreeNode *tp = (TreeNode *)malloc(sizeof(TreeNode));

// C++：不同语言！必须显式转换，否则报错
TreeNode *tp = (TreeNode *)malloc(sizeof(TreeNode));
```

> **本课程推荐现代 C 的写法**（不加转换）。

### 6.4 `free`：释放

```c
void free(void *ptr)
```

- `ptr` 必须是 **`malloc()` / `realloc()` 返回的原始地址**
- **传原始地址之外的东西 → 崩溃（或更糟）**

```c
int *ptr = malloc(sizeof(int) * 20);
...
free(ptr);    // 隐式转换成 (void *)
```

### 6.5 堆管理示例：碎片化

```
初始状态：
┌──────────────────────────────┐
│       （空闲的整块堆）        │
└──────────────────────────────┘

请求 R1（100 字节）：
┌───────────┬──────────────────┐
│  R1(100)  │    空闲          │
└───────────┴──────────────────┘

请求 R2（10 字节）：
┌───────────┬──────┬───────────┐
│  R1(100)  │R2(10)│   空闲    │
└───────────┴──────┴───────────┘

释放 R1：
┌───────────┬──────┬───────────┐
│  空闲     │R2(10)│   空闲    │
└───────────┴──────┴───────────┘
       ⚠ 碎片！

请求 R3（50 字节）：
→ 只能用右边那块，左边的 100 字节闲置
```

> **这就是「外部碎片」**：空闲字节总数够，但不连续，装不下大请求。

### 6.6 `realloc`：调整大小

```c
void *realloc(void *ptr, size_t size)
```

- 把 `ptr` 指向的块调整为 `size` 字节
- **返回新的地址**（可能和原来不同！）
  - 因为它**可能需要把数据搬到新位置**

**特殊情况：**

```c
realloc(NULL, size);    // 等价于 malloc(size)
realloc(ptr, 0);        // 等价于 free(ptr)
```

> ⚠️ **永远检查返回值是否为 NULL**——那意味着内存耗尽。

## 七、堆的实现（不考，但值得看）

### 7.1 K&R 的 malloc/free 实现

来自《The C Programming Language》第 8.7 节：

- 代码用了些本课还没讲的语言特性，风格很紧凑，**看不懂没关系**
- **每个内存块前面有一个 header**，含两个字段：
  - **块大小**
  - **指向下一个块的指针**
- **所有空闲块组成一个循环链表**
- 已分配的块里，header 的指针字段不使用

### 7.2 分配与释放的算法

**`malloc()`**：
1. 在空闲链表里找一个够大的块
2. 找不到 → 向操作系统要更多内存
3. 要不到也不够 → 失败（返回 NULL）

**`free()`**：
1. 检查**相邻的块是否也空闲**
2. 是 → **合并（coalesce）** 成更大的空闲块
3. 否 → 直接加回空闲链表

### 7.3 三个设计目标

| 目标 | 说明 |
|---|---|
| **快** | `malloc` / `free` 要快 |
| **开销小** | 内存开销最小化 |
| **避免碎片** | 别让空闲内存碎成小块 |

> **碎片化的本质**：空闲字节很多，但不连续，**装不下一个大请求**。

### 7.4 选择哪个空闲块？（三种策略）

| 策略 | 规则 |
|---|---|
| **best-fit**（最佳适配） | 选**够用的最小块** |
| **first-fit**（首次适配） | 选**第一个够大的块** |
| **next-fit**（下次适配） | 像 first-fit，但**记住上次搜索结束的位置**，从那里继续 |

## 八、链表示例（课后自学）

课程放了一个完整的链表实现，用到了本讲全部知识：

```c
typedef struct _node node_t;
struct _node {
    char *data;
    node_t *next;
};

void add_to_front(node_t **head_ptr, char *data) {
    node_t *node = (node_t *)malloc(sizeof(node_t));
    node->data = (char *)malloc(strlen(data) + 1);   // ⚠ +1 给 '\0'
    strcpy(node->data, data);
    ...
}

int main() {
    node_t *head = NULL;
    add_to_front(&head, "abc");
    ...
    // 释放节点和字符串
}
```

**这个例子体现了：**

| 知识点 | 体现在哪 |
|---|---|
| **指针的指针** | `&head`，才能修改 head 本身 |
| **`sizeof`** | `sizeof(node_t)` |
| **动态分配** | `malloc` 两次（结构体 + 字符串） |
| **字符串 + \0** | `strlen(data) + 1` |
| **手动释放** | 注释提醒要 free |

## 九、本讲总结

| 主题 | 核心 |
|---|---|
| **数组是原始的** | 不检查边界、传参退化、作用域受限 |
| **内存布局** | Stack ↓ / Heap ↑ / Data / Text |
| **栈** | LIFO，自动管理，**不能返回栈指针** |
| **堆** | `malloc` / `free` / `realloc`，**必须手动管理** |
| **字节序** | little endian（LSB 在低地址） |
| **对齐与 padding** | 结构体大小可能大于字段之和 |

## 十、我的笔记与理解

### 10.1 「(Mis)Management」这个名字的含义

标题用括号把 **Mis** 括起来，是刻意的双关：

- 「内存**管理**」——这是本讲的内容
- 「**错误**管理」——这是 C 程序员每天在做的事

**核心矛盾：C 把内存的完全控制权交给你，代价是你必须承担全部责任。**

### 10.2 栈与堆的根本区别

| 维度 | 栈 | 堆 |
|---|---|---|
| **分配方式** | 自动（函数调用时） | 手动（`malloc`） |
| **释放方式** | 自动（函数返回时） | **手动（`free`）** |
| **速度** | 极快（只移动 sp） | 慢（查找空闲块） |
| **大小限制** | 小（默认几 MB） | 大（可达 GB） |
| **碎片问题** | 无 | **有** |
| **典型 bug** | 返回栈指针 | **内存泄漏 / 悬垂引用** |

> **一句话**：栈是「租的房子」（到期自动收回），堆是「买的房子」（你不退就一直在，但你忘了退就永远租着）。

### 10.3 为什么 Java/Python 没这个烦恼

它们用 **GC（垃圾回收）**：

- 自动追踪「哪些内存还有人在引用」
- 没人引用就自动释放

**代价**：

- 运行时开销
- **停顿（stop-the-world）**
- 不可预测的延迟

**C 的代价相反**：极高的性能和控制力，但你得自己管。

### 10.4 三大内存 bug

| bug | 成因 | 症状 |
|---|---|---|
| **内存泄漏** | `malloc` 后从不 `free` | 内存持续上涨 |
| **悬垂引用** | `free` 后还继续用 | 随机崩溃 / 数据错乱 |
| **重复释放** | 同一个指针 `free` 两次 | 堆结构损坏 |

> 这三者都不会立刻报错，是 C 最阴险的地方。

### 10.5 `sizeof(nums)` vs `sizeof(arr)` 的教训

| 位置 | 结果 | 本质 |
|---|---|---|
| `main` 里 | 10（整个数组） | 数组名在其作用域内是**数组** |
| 函数里 | 8（指针大小） | 已**退化成指针** |

> **这解释了一切「为什么函数里算不出数组长度」**。

**正确做法**：在数组还在「数组形态」时算好，作为参数传进去。

```c
int len = sizeof(nums) / sizeof(nums[0]);
mystery(nums, len);
```

### 10.6 结构体 padding 的实际后果

```c
struct foo { int32_t a; char b; struct foo *c; };
// 字段之和：4 + 1 + 4 = 9
// sizeof == 12（多出 3 字节 padding）
```

**实际影响：**

- 序列化/反序列化时**不能假设紧凑**
- 网络协议里要**逐字段处理**，不能直接 memcpy 结构体
- 大数组的结构体会**浪费大量内存**

### 10.7 与后续的衔接

| 讲次 | 关系 |
|---|---|
| **L06** | 泛型与函数指针 → 会用 `void *` 做「任意类型」 |
| **L07** | 位运算与 ADT → 会用 struct 实现抽象数据类型 |
| **L08** | 浮点数 |
| **L09+** | RISC-V → 会看到栈帧在汇编层面如何工作 |

> **L05 是 C 部分的顶点**：讲完指针、数组、内存，你才算真正入门 C。

## 十一、术语速查

| 术语 | 中文 | 说明 |
|---|---|---|
| **stack frame** | 栈帧 | 每次函数调用分配的内存块 |
| **stack pointer (sp)** | 栈指针 | 指向栈顶 |
| **heap** | 堆 | 动态内存区 |
| **dangling reference** | 悬垂引用 | 指向已释放的内存 |
| **memory leak** | 内存泄漏 | 分配后未释放 |
| **fragmentation** | 碎片化 | 空闲内存不连续 |
| **coalesce** | 合并 | 相邻空闲块合成大的 |
| **best-fit / first-fit / next-fit** | 最佳/首次/下次适配 | 分配策略 |
| **byte-addressable** | 按字节编址 | 每个字节有唯一地址 |
| **little endian** | 小端 | LSB 在低地址 |
| **padding** | 填充 | 为对齐插入的空字节 |
| **LIFO** | 后进先出 | 栈的特性 |
