> **本讲补齐剩下三种格式：U、B、J**（课件标题配了 Kris Kross - Jump）

## 一、jalr：I-Type 的跳转

### 1.1 指令语义

```asm
jalr rd, rs1, imm
    R[rd] = PC + 4
    PC = R[rs1] + imm
```

| 步骤 | 说明 |
|---|---|
| **① 写返回地址** | `PC + 4` 存进 `rd` |
| **② 无条件跳转** | 到地址 `R[rs1] + imm` |

### 1.2 字段布局

```
 31            20 19    15 14    12 11      7 6      0
┌────────────────┬────────┬────────┬──────────┬────────┐
│   imm[11:0]    │  rs1   │ funct3 │    rd    │ opcode │
└────────────────┴────────┴────────┴──────────┴────────┘
   ↑ offset         ↑ base            ↑ 返回地址
```

| 字段 | 说明 |
|---|---|
| **`imm[11:0]`** | **offset**，加到基址形成目标 PC |
| **`rs1`** | **base**，跳转的基地址 |
| **`rd`** | **destination**，得到「返回地址」`PC+4` |

> **公式**：`PC = (Base Register) + (Immediate Offset)`

### 1.3 `jr` 是伪指令

```asm
jr rs1    →    jalr x0, rs1, 0
```

| 效果 | 说明 |
|---|---|
| **写到 x0** | **不保存「下一条」指令地址**（x0 写入无效）|
| **跳转** | 到 `R[rs1] + 0` |

> **这就是函数返回 `jr ra` 的本质：`jalr x0, ra, 0`。**

## 二、U-Type：高位立即数

### 2.1 两条指令

**`lui`：Load Upper Immediate**

```asm
lui rd, immu
    imm = immu << 12
    R[rd] = imm
```

> **把 20 位立即数写到 rd 的高 20 位，低 12 位清零。**

**`auipc`：Add Upper Immediate to PC**

```asm
auipc rd, immu
    imm = immu << 12
    R[rd] = PC + imm
```

> **把「高 20 位立即数」加到 PC 上。**

### 2.2 字段布局

```
 31        12 11      7 6      0
┌─────────────┬─────────┬───────┐
│  imm[31:12] │   rd    │opcode │
│   20 bit    │  5 bit  │ 7 bit │
└─────────────┴─────────┴───────┘
```

| 指令 | opcode |
|---|---|
| **`lui`** | `0110111` |
| **`auipc`** | `0010111` |

> **注意：U-Type 没有 `rs1`、`rs2`、`funct3` —— 只剩立即数和 `rd`。**

### 2.3 `lui` + `addi` = 任意 32 位立即数

```asm
li x10, 0x87654321
    →  lui  x10, 0x87654      # 高 20 位
       addi x10, x10, 0x321   # 低 12 位
```

| 步骤 | 结果 |
|---|---|
| `lui x10, 0x87654` | `x10 = 0x87654000` |
| `addi x10, x10, 0x321` | `x10 = 0x87654321` ✅ |

> **这就是 `li` 伪指令的实现方式。**

### 2.4 ⚠️ 边界情况：`addi` 会符号扩展！

**问题代码：**

```asm
li x10, 0xB0BACAFE
    →  lui  x10, 0xB0BAC
       addi x10, x10, 0xAFE
```

**结果错误！**

```
lui  x10, 0xB0BAC     →  x10 = 0xB0BAC000
addi x10, x10, 0xAFE  →  ⚠ 0xAFE 的最高位是 1（= -1282）
                          符号扩展成 0xFFFFFAFE
                       →  x10 = 0xB0BAC000 + 0xFFFFFAFE
                              = 0xB0BABAFE   ❌ 不是 0xB0BACAFE！
```

**原因：**

> **`addi` 对 12 位立即数做符号扩展。**
> **如果立即数的符号位是 1（即它被视为负数），就会从高 20 位「借 1」。**

### 2.5 正确解法：主动 +1

```asm
li x10, 0xB0BACAFE

# ❌ 错的
lui  x10, 0xB0BAC
addi x10, x10, 0xAFE

# ✅ 对的
lui  x10, 0xB0BAD      # ← 高 20 位主动加 1
addi x10, x10, 0xAFE
```

**验算：**

```
lui  x10, 0xB0BAD     →  x10 = 0xB0BAD000
addi x10, x10, 0xAFE  →  加 0xFFFFFAFE
                          = 0xB0BAD000 + 0xFFFFFAFE
                          = 0xB0BACAFE ✅（进位溢出）
```

> **规则：若低 12 位的最高位是 1，则高 20 位要 +1。**
> **这是汇编器必须处理的一个细节。**

## 三、PC 相对寻址

### 3.1 基本思想

> **几乎所有情况下，指令用 PC 相对（PC-Relative）更新 PC：**

```
PC = PC + offset
```

**通过提供一个有符号偏移。**

| 指令类型 | 偏移 |
|---|---|
| **算术 / load / store** | **+4**（顺序执行）|
| **分支 / 大多数跳转** | **各自计算** |

### 3.2 例子

```
0x0c  Loop:
0x10        beq x19, x10, End
0x14        add x18, x18, x10
0x18        addi x19, x19, -1
0x1c        j Loop
      End:
```

**问题**：`beq` 和 `j` 的 PC 相对偏移是多少？

| 指令 | 执行位置 | 目标位置 | 偏移 |
|---|---|---|---|
| **`beq x19 x10 End`** | at `0x10` | `0x1c` | **`0x1c - 0x10 = +12`** |
| **`j Loop`** | at `0x1c` | `0x0c` | **`0x0c - 0x1c = -16`** |

> ⚠️ **关键：偏移是「相对于当前指令的地址」，不是「相对于下一条」。**
> **（因为 PC 在取指时已经指向当前指令。）**

### 3.3 为什么用相对寻址：位置无关代码（PIC）

> **Why？Position-Independent Code.**
> **如果整段代码被移动到别处，这些相对偏移不会改变！**

**对比绝对寻址：**

| 方式 | 公式 | 问题 |
|---|---|---|
| **PC 相对** | `PC = PC + offset` | ✅ 代码移动后仍有效 |
| **绝对寻址** | `PC = R[rs1] + imm` | ❌ 地址写死，移动就崩 |

> **标签（Label）在机器码里根本不存在** ——
> **它们只是在汇编阶段被翻译成「偏移量」。**

## 四、B-Type：条件分支

### 4.1 语义

```asm
beq rs1, rs2, Label
    if (R[rs1] == R[rs2])
        PC = <Label 的地址> = PC + offset
```

> **Label 在汇编时被翻译成 PC 相对地址，再编码为有符号立即数偏移。**

### 4.2 字段布局（立即数被「旋转」成两段！）

```
 31            25 24    20 19    15 14    12 11           7 6      0
┌────────────────┬────────┬────────┬────────┬───────────────┬────────┐
│ imm[12|10:5]   │  rs2   │  rs1   │ funct3 │ imm[4:1|11]   │ opcode │
│     7 bit      │ 5 bit  │ 5 bit  │ 3 bit  │    5 bit      │ 7 bit  │
└────────────────┴────────┴────────┴────────┴───────────────┴────────┘
```

**opcode = `1100011`（B-Type）**

### 4.3 ⚠️ 两个关键设计问题

**问题 1：为什么只存 12 位，却有 13 位的偏移？**

> **`imm[0]` 永远是 0。**

**原因**：

> **RISC-V 支持 16 位压缩指令扩展（C 扩展）。**
> **因此所有分支目标都是「半字对齐」（2 字节倍数）。**
> **既然最低位永远是 0，就不用存了 —— 白赚 1 位范围。**

### 4.4 分支范围的推导

**13 位有符号偏移，最低位恒 0：**

```
可表示范围：[-4096, +4094] 字节
除以 4（每个指令 4 字节）
= [-1024, +1023.5] 指令
≈ ±2¹⁰ 条指令
```

**答案：`±2¹⁰ instructions from PC`**

### 4.5 ⚠️ 代价：一半的目标会出错

> **本课用的 RISC-V 处理器只支持 32 位指令。**
> **但编码格式为 16 位指令留了位。**
> **所以「一半可能的分支目标」会是错误地址。**

**具体**：偏移最低位恒为 0，意味着**分支目标地址的最低 1 位 = 0**。

### 4.6 为什么「比特旋转」

> **问题 2：为什么立即数的位在指令里「乱序」？**

**答案：为了同时满足两个约束。**

**约束 A：寄存器字段位置固定**

`rs1`（bits 19:15）、`rs2`（bits 24:20）、`funct3`（bits 14:12）**必须和 R/I/S 型一致**。

**约束 B：立即数尽量对齐**

**观察立即数在各格式中的位置：**

```
I-Type:  imm[11:0]  →  bits 31:20
S-Type:  imm[11:5]  →  bits 31:25
         imm[4:0]   →  bits 11:7
B-Type:  imm[12]    →  bit  31
         imm[10:5]  →  bits 30:25
         imm[4:1]   →  bits 11:8
         imm[11]    →  bit  7
```

> **可以看到：`imm[10:5]` 在 S 和 B 型里都在 bits 30:25。**
> **`imm[4:1]` 在 S 和 B 型里都在 bits 11:8。**

**这就是「旋转（swirl）」的目的：让硬件复用同一套立即数提取逻辑。**

### 4.7 编码例子：`beq x19 x10 End`

**已知布局：**

```
0x0c  Loop:
0x10        beq x19 x10 End    ← 编码这一条
0x14        add x18 x18 x10
0x18        addi x19 x19 -1
0x1c  End:
```

**第 1 步：算偏移**

```
offset = End - beq_addr = 0x1c - 0x10 = +12 = 0b1100
```

**第 2 步：扩展成 13 位，最低位置 0**

```
偏移 +12 = 0b 0 0000 0000 110 0
            ↑ 12位      ↑10:5 ↑4:1 ↑[0]恒0
```

**13 位表示：`0000000001100`**

**第 3 步：拆分到各字段**

| 位 | 值 |
|---|---|
| `imm[12]` | 0 |
| `imm[10:5]` | `000000` |
| `imm[4:1]` | `0110` |
| `imm[11]` | 0 |

**第 4 步：拼装**

```
imm[12|10:5]  rs2    rs1    funct3  imm[4:1|11]  opcode
0000000       01010  10011  000     01100        1100011
```

| 字段 | 值 |
|---|---|
| rs2 | `01010`（x10）|
| rs1 | `10011`（x19）|
| funct3 | `000`（beq）|
| opcode | `1100011` |

### 4.8 B-Type funct3 表

| 指令 | funct3 |
|---|---|
| **`beq`** | 000 |
| **`bne`** | 001 |
| **`blt`** | 100 |
| **`bge`** | 101 |
| **`bltu`** | 110 |
| **`bgeu`** | 111 |

> **规律：bit[2] = 1 表示「无符号」（和 load 一样）！**

## 五、J-Type：无条件跳转

### 5.1 语义

```asm
jal rd, Label
    R[rd] = PC + 4
    PC = <Label 地址> = PC + offset
```

> **J-Type（教材称 UJ-Type）只用于 `jal`。**

**与分支一样用 PC 相对寻址，但跳得更远。**

### 5.2 一个陷阱：同名伪指令

> ⚠️ **`jal Label` 是同名伪指令！**
> **实际展开为 `jal ra, Label`。**

```asm
jal Label      →    jal ra, Label
```

### 5.3 字段布局（21 位偏移，位序极其混乱）

```
 31                            12 11    7 6      0
┌────────────────────────────────┬────────┬───────┐
│ imm[20|10:1|11|19:12]          │   rd   │opcode │
│          20 bit                │ 5 bit  │ 7 bit │
└────────────────────────────────┴────────┴───────┘
```

**opcode = `1101111`**

**偏移结构：**

```
offset = imm[21:0]
- imm[0] 恒为 0（半字对齐）
- 21 位有符号整数
- PC = PC + offset
```

### 5.4 位序混乱的原因

> **「Bit swirling 是为了降低硬件成本（课后自己验证）。」**

**实际规律：**

```
指令中的位:  31 30:25 24:21 20    19:12      11:8   7
偏移中的位:  20 10:5  4:1   11    19:12      —      —
                                    ↑
                          imm[19:12] 在原位！
```

> **`imm[19:12]` 保持在 bits 19:12 不变** ——
> **这样硬件可以把「立即数的高位部分」统一处理。**

### 5.5 J-Type 的范围

**21 位有符号偏移，最低位恒 0：**

```
范围 = [-2^20, +2^20 - 2] 字节
除以 4
≈ ±2^18 条指令
```

> **比 B-Type 的 ±2¹⁰ 大了 256 倍！**

## 六、四种跳转指令的完整对比

| 指令 | 格式 | 语义 | 用途 |
|---|---|---|---|
| **`jal rd, Label`** | **J-Type** | `rd = PC+4; PC += offset` | **调用函数** |
| **`j Label`**（伪）| J-Type | `jal x0, Label` | **无条件跳转** |
| **`jalr rd, rs1, imm`** | **I-Type** | `rd = PC+4; PC = R[rs1]+imm` | **函数指针 / 绝对地址** |
| **`jr rs1`**（伪）| I-Type | `jalr x0, rs1, 0` | **函数返回** |

### 6.1 谁写返回地址

| 指令 | 写返回地址 |
|---|---|
| **`jal`** | ✅ 写到 `rd` |
| **`jalr`** | ✅ 写到 `rd` |
| **`j`** | ❌ 写到 x0（无效）|
| **`jr`** | ❌ 写到 x0（无效）|

### 6.2 谁读返回地址

| 指令 | 读返回地址 |
|---|---|
| **`jal`** | ❌（偏移基于 PC）|
| **`jalr` / `jr`** | ✅（`R[rs1]`）|

### 6.3 寻址方式对比

| 方式 | 指令 | 公式 |
|---|---|---|
| **PC 相对** | `jal`、`j`、所有 branch | `PC = PC + offset` |
| **PC 绝对** | `jalr`、`jr` | `PC = R[rs1] + imm` |

## 七、⚠️ 万能跳转：`jal` 的范围不够怎么办

### 7.1 问题

> **`jal`（J-Type）范围有限：±2¹⁸ 条指令。**
> **如果要跳到任意 32 位地址怎么办？**

### 7.2 解法：`lui` + `jalr` 组合

**调用函数（保存返回地址）**

```asm
# jal ra, Label  的等价实现（任意绝对地址）
lui  ra, <hi20bits>      # ra = 高 20 位
jalr ra, ra, <lo12bits>  # ra = PC+4; PC = ra + 低 12 位
```

> ⚠️ **注意顺序：`lui` 先写 `ra` 作为地址，`jalr` 再把它覆盖成返回地址。**

**无条件跳转（不保存返回地址）**

```asm
# j Label  的等价实现
auipc ra, <hi20bits>     # ra = PC + 高 20 位
jalr  x0, ra, <lo12bits> # 跳到 ra + 低 12 位
```

> **`auipc` 在这里的关键作用**：它让地址是**相对于当前 PC** 的，
> **因此代码移动后仍然正确（PIC）。**

### 7.3 分支范围不够怎么办

> **B-Type 只有 ±2¹⁰。**

**解法：取反 + 无条件跳转**

```asm
beq x10, x0, far
# 下一条指令

# 等价于（但能跳更远）
bne x10, x0, next    # 不相等就跳过
j   far              # 相等才跳
next:
# 下一条指令
```

> **「功能等价」：把 `beq far` 拆成「`bne next` + `j far`」。**
> **`j` 的范围是 `bne` 的 256 倍。**

### 7.4 通用模式总结

| 需求 | 短距离方案 | 长距离方案 |
|---|---|---|
| **条件分支** | `beq` / `bne` | `bne next` + `j far` |
| **函数调用** | `jal` | `lui` + `jalr` |
| **无条件跳转** | `j` | `auipc` + `jalr` |

## 八、六种格式完整总览

| 格式 | 用途 | 指令 |
|---|---|---|
| **R** | 寄存器-寄存器 | `add` `sub` `and` `or` `xor` `sll` `srl` `sra` `slt` `sltu` |
| **I** | 寄存器-立即数 | `addi` `andi` `ori` `xori` `slli` `srli` `srai` `slti` `sltiu` |
| **I**（Load） | 读内存 | `lb` `lbu` `lh` `lhu` `lw` |
| **I**（jalr） | 寄存器跳转 | `jalr` |
| **S** | 写内存 | `sb` `sh` `sw` |
| **B** | 条件分支 | `beq` `bne` `blt` `bge` `bltu` `bgeu` |
| **U** | 高位立即数 | `lui` `auipc` |
| **J** | 跳转 | `jal` |

```
R-Type:  funct7 | rs2 | rs1 | funct3 | rd    | opcode
I-Type:  imm[11:0]    | rs1 | funct3 | rd    | opcode
S-Type:  imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode
B-Type:  imm[12|10:5]| rs2 | rs1 | funct3 | imm[4:1|11] | opcode
U-Type:  imm[31:12]                 | rd    | opcode
J-Type:  imm[20|10:1|11|19:12]      | rd    | opcode

opcode 表：
R: 0110011    I-算术: 0010011    I-load: 0000011
I-jalr: 1100111    S: 0100011    B: 1100011
U-lui: 0110111    U-auipc: 0010111    J: 1101111
```

## 十、我的笔记与理解

### 10.1 六种格式的设计哲学

**一条主线贯穿：**

```
寄存器字段位置固定  →  硬件可以并行读寄存器  →  更快
立即数位置尽量对齐  →  硬件可复用提取逻辑  →  更简单
```

**为此付出的代价：**

- S-Type 劈开立即数
- B-Type 立即数「旋转」
- J-Type 立即数「乱序」
- `imm[0]` 恒为 0（白占一位编码空间）

> **每一个「看起来奇怪的编码」，背后都是硬件成本的考量。**

### 10.2 `imm[0] 恒为 0` 的双重含义

| 层面 | 含义 |
|---|---|
| **好处** | 13 位偏移覆盖 4 KB 范围（而不是 8 KB 的一半）|
| **代价** | 本课的纯 32 位处理器**浪费一半目标地址** |

**来源**：RISC-V 支持 **16 位压缩指令（C 扩展）**。
指令可以是 2 字节对齐，所以跳转目标最低位必须是 0。

### 10.3 `auipc` 的真正用途

```asm
auipc ra, <hi20>       # ra = PC + (hi20 << 12)
jalr  x0, ra, <lo12>   # 跳到 ra + lo12
```

> **这是「PC 相对 + 32 位范围」的组合。**
> **用于大程序的函数跳转，同时保持位置无关。**

**为什么需要 PC 相对？**

| 场景 | 绝对地址 | PC 相对 |
|---|---|---|
| **单机运行** | ✅ 行 | ✅ 行 |
| **动态链接库（.so）** | ❌ 加载地址随机（ASLR）| ✅ 行 |
| **固件/ROM 代码** | ❌ 可能重定位 | ✅ 行 |

### 10.4 `lui` + `addi` 的「+1」修正

```asm
lui  x10, 0xB0BAD      # 注意：不是 0xB0BAC，而是 +1
addi x10, x10, 0xAFE
```

**为什么？**

```
addi 的 12 位立即数做了符号扩展：
  0xAFE 的 bit[11] = 1  →  被当成负数 -1282
  →  实际加的是 0xFFFFFAFE（而不是 0x00000AFE）
  →  相当于从高位「借 1」
```

> **修正方式：提前把高 20 位 +1，让「借 1」正好抵消。**
>
> **这个细节是汇编器必须处理的** —— 手写汇编时极易出错。

### 10.5 B-Type 的位序「旋转」怎么记

```
原始偏移（13 位）：
  imm[12] imm[11] imm[10:5] imm[4:1] imm[0]

填入指令：
  31       30:25      24:20   19:15   14:12   11:8      7      6:0
  imm[12]  imm[10:5]  rs2     rs1     funct3  imm[4:1]  imm[11] opcode
```

**记忆技巧**：

> **「最高位放在最前面（bit 31），最低位放在 funct3 后面（bit 7），中间 10:5 靠左，4:1 靠右。」**
>
> 换句话说：**高位往两头散，`imm[11]` 被挤到了 bit 7 这个奇怪的位置。**

### 10.6 J-Type 的位序更乱

```
offset（21 位）： imm[20] imm[19:12] imm[11] imm[10:1] imm[0]

填入指令：
  31       30:21       20      19:12      11:0
  imm[20]  imm[10:1]   imm[11]  imm[19:12]  rd+opcode
                                    ↑
                          这一段保持原位！
```

> **只有 `imm[19:12]` 在原位（bits 19:12）。**
> **其余全部打散。**
>
> **实操建议：用参考卡反向查表，不要手算。**

### 10.7 「范围不够」的三种解法

这是本讲最实用的工程知识：

| 需求 | 短 | 长 |
|---|---|---|
| **条件分支** | `beq` | `bne next; j far` |
| **函数调用** | `jal` | `lui ra, hi; jalr ra, ra, lo` |
| **无条件跳转** | `j` | `auipc ra, hi; jalr x0, ra, lo` |

> **这三套替换模式，是编译器生成代码时的必备知识。**
> **也是理解「为什么会有 U-Type」的答案。**
