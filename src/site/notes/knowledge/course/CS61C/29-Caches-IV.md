## 一、⭐⭐ N 路组相联缓存（N-Way Set Associative）

### 1.1 地址字段

| 字段 | 说明 |
|---|---|
| **Tag** | **和之前一样** |
| **Offset** | **和之前一样** |
| **Index** | **指向正确的「行」（这里叫「组 / set」）** |

### 1.2 ⭐ 和直接映射的区别

> **「每组包含「多个块」。**
> **找到正确的组之后，必须和「组内所有 tag」比较才能找到数据。」**

**容量公式：**

```
缓存大小 = 组数 × (N 块/组) × 块大小
```

> ⭐ **「直接映射 = 1 路组相联；全相联 = M 路组相联（M = 总块数）。」**

### 1.3 最小例子：2 路组相联、2 组、2 块/组

```
内存           缓存
0x0  ┐
0x1  │  →  组 0：位置 0, 位置 1
0x2  │
0x3  │
0x4  ┤  →  组 1：位置 0, 位置 1
0x5  │
0x6  │
0x7  │
0x8  ┤  →  组 0（又回来了）
0x9  │
...
```

**映射关系：**

```
组号 = (内存地址 / 块大小) mod 组数
```

| 地址 | 组号 |
|---|---|
| **0x0, 0x4, 0x8, 0xC** | **组 0** |
| **0x1, 0x5, 0x9, 0xD** | **组 1** |

> **区别在于：组 0 里可以「同时装 2 个」不同的块。**

### 1.4 ⭐ 访问步骤（四步）

| # | 动作 |
|---|---|
| **①** | **用 Index 找到正确的「组」** |
| **②** | **用 Tag 和「该组内所有 tag」比较** |
| **③** | **若有一个匹配 → 命中（Hit）；否则 → 未命中（Miss）** |
| **④** | **用 offset 找到块内的目标数据** |

### 1.5 ⭐ 为什么它好

> **「哪怕只有「2 路组相联」，也能避免大量冲突未命中。」**
> **「硬件成本不算太差：只需要「N 个比较器」。」**

**成本对比：**

| 类型 | 比较器数 | 冲突 miss |
|---|---|---|
| **直接映射（1 路）** | **1** | ❌ 多 |
| **2 路组相联** | **2** | ✅ 大幅减少 |
| **4 路组相联** | **4** | ✅✅ 更少 |
| **8 路组相联** | **8** | ✅✅✅ |
| **全相联** | **块总数（如 16K）** | ✅✅✅✅ 无 |

> ⭐ **「2 路就把「最痛的冲突」解决掉大半 —— 性价比极高。」**

**统一视角：**

```
M 块缓存：
  1 路组相联    = 直接映射
  M 路组相联    = 全相联
  N 路（1<N<M） = 组相联
```

> **「这两种只是「更一般设计」的特例。」**

### 1.6 硬件结构：4 路组相联

```
                    Tag        Index
                     │           │
      ┌──────────────┼───────────┘
      │              │
      ▼              ▼
  ┌────────────────────────────┐
  │  用 Index 选中一个「组」    │
  │  ┌────┬────┬────┬────┐      │
  │  │ 路0│ 路1│ 路2│ 路3│      │
  │  │ == │ == │ == │ == │◄─────┼── Tag 并行比较 4 个
  │  │ V,T│ V,T│ V,T│ V,T│      │
  │  └─┬──┴─┬──┴─┬──┴─┬─┘      │
  │    │    │    │    │        │
  │    ▼    ▼    ▼    ▼        │
  │  "One Hot" Encoding        │
  │  (0001/0010/0100/1000)     │
  │    │    │    │    │        │
  │    └────┴────┴────┘        │
  │           ▼                │
  │      ┌─────────┐           │
  │      │ 4→1 MUX │◄── Block offset
  │      └────┬────┘           │
  └───────────┼────────────────┘
              ▼
           输出
```

> ⭐ **「One Hot 编码」：4 路里只有一路的命中信号为 1。**

## 二、⭐⭐ 块替换策略

### 2.1 三种缓存的「选择自由度」

| 类型 | 替换自由度 |
|---|---|
| **直接映射** | **索引完全决定「块能放哪」——无选择** |
| **N 路组相联** | **索引选「组」，但块可占「组内任意位置」** |
| **全相联** | **块可以写到「任何位置」** |

### 2.2 ⭐ 问题

> **「如果能选择，新来的块该写到哪里？」**

### 2.3 第一规则：优先填空位

> **「如果某路的 valid = 0，就把新块写进第一个无效位置。」**

> **这是最快、最自然的做法 —— 预热阶段几乎总是这样。**

### 2.4 第二规则：都满时选替换策略

> **「如果所有路都有效，就选一个「替换策略（replacement policy）」。**
> **也就是「miss 时哪个块被换出（cached out）」的规则。」**

### 2.5 三种策略

#### ① LRU（Least Recently Used，最近最少使用）

> **「思路：换出「最近最久没有被访问（读或写）」的块。」**

| 评价 | 说明 |
|---|---|
| **✅ 优点** | **利用时间局部性 —— 最近用过的很可能还会用；实际上这策略非常有效** |
| **⚠️ 缺点** | **2 路时容易记录（一个 LRU 位）；4 路或更多则需要「复杂硬件 + 大量时间」来跟踪** |

**2 路 LRU 的实现：**

```
每组一个 LRU 位：
  LRU = 0  → 路 1 是最久未用的（下次踢它）
  LRU = 1  → 路 0 是最久未用的
访问路 0 时：LRU = 1（表示路 1 变老了）
访问路 1 时：LRU = 0
```

> ⭐ **「1 位就够 —— 因为「两路里必有一个更久未用」。」**

**更多路的复杂度：**

| 路数 | LRU 状态位数 | 说明 |
|---|---|---|
| **2** | **1** | 简单 |
| **4** | **需要记录 4! = 24 种顺序 ≈ 5 位** | 需要复杂逻辑 |
| **8** | **8! = 40320 种 ≈ 16 位** | 实际几乎不用真 LRU |

> **所以真实 CPU 用「伪 LRU（pseudo-LRU）」。**

#### ② FIFO（First In First Out，先进先出）

> **「思路：忽略访问记录，只跟踪「最初的顺序」。」**

| 优点 | 缺点 |
|---|---|
| **实现极简**（一个循环指针）| **不利用局部性** |
| **无需额外状态** | **可能踢出「刚用过」的块** |

#### ③ Random（随机）

> **「如果工作负载的「时间局部性差」，效果尚可。」**

| 优点 | 缺点 |
|---|---|
| **最简** | **效果看运气** |
| **无需任何状态** | |

### 2.6 ⭐ 三种策略对比

| 策略 | 硬件成本 | 效果 | 用在 |
|---|---|---|---|
| **LRU** | 高（N>2 时）| ✅ 最好 | L1（伪 LRU）|
| **FIFO** | 低 | 中 | 某些嵌入式 |
| **Random** | 最低 | 中 | L2/L3（大路数时）|

> ⭐ **「大路数缓存（如 16 路 L3）常用「随机替换」—— 因为 LRU 的开销超过收益。」**

## 三、⭐⭐ 完整练习：2 路组相联 + LRU

### 3.1 题目

> **「还是那个 2 路组相联缓存：总容量 4 字节、块大小 1 字节。**
> **执行以下字节访问序列：」**

```
0, 2, 0, 1, 4, 0, 2, 3, 5, 4
```

> **「在 LRU 替换策略下，有多少次命中、多少次未命中？」**

### 3.2 先理清结构

| 参数 | 值 |
|---|---|
| **总容量** | **4 字节** |
| **块大小** | **1 字节** |
| **总块数** | **4** |
| **路数** | **2** |
| **组数** | **4 / 2 = 2** |
| **Index 位数** | **1（2 组）** |
| **Offset 位数** | **0（块 1 字节）** |
| **Tag 位数** | **剩余** |

**初始结构：**

```
        位置 0      位置 1     LRU
组 0    [空]       [空]        -
组 1    [空]       [空]        -
```

### 3.3 逐步走查

#### ① 访问 0

```
组号 = 0 / 2 = 0？不对 —— 用块号 mod 组数
```

> ⚠️ **注意：块大小 1 字节，所以「地址 = 块号」。**
> **组号 = 地址 mod 2（组数）。**

```
地址 0 → 组 0，Tag = 0
组 0 有空位 → 放入位置 0
```

```
        位置 0      位置 1     LRU
组 0    [0]        [空]        -
组 1    [空]       [空]        -
```

**结果：MISS** ❌

#### ② 访问 2

```
地址 2 → 组 2 mod 2 = 组 0，Tag = 2/2 = 1
组 0 还有空位 → 放入位置 1
```

```
        位置 0      位置 1          LRU
组 0    [0]        [2] (tag 1)    -
组 1    [空]       [空]           -
```

**结果：MISS** ❌

#### ③ 访问 0（再来）

```
地址 0 → 组 0，Tag 0
位置 0 里是 Tag 0 → 匹配！
```

```
        位置 0      位置 1          LRU
组 0    [0]        [2]           LRU=1（位置1更老）
组 1    [空]       [空]           -
```

**结果：HIT** ✅

#### ④ 访问 1

```
地址 1 → 组 1，Tag = 0
组 1 有空位 → 放入位置 0
```

```
        位置 0      位置 1          LRU
组 0    [0]        [2]           位置1老
组 1    [1]        [空]           -
```

**结果：MISS** ❌

#### ⑤ 访问 4

```
地址 4 → 组 4 mod 2 = 组 0，Tag = 4/2 = 2
组 0 已满（2 个位置都有）
LRU 显示位置 1（[2]）最久未用 → 替换它
```

```
        位置 0      位置 1          LRU
组 0    [0]        [4] (tag 2)    LRU=0（位置0更老）
组 1    [1]        [空]           -
```

**结果：MISS + 替换** ❌

#### ⑥ 访问 0

```
地址 0 → 组 0，Tag 0
位置 0 里是 Tag 0 → 匹配！
```

```
        位置 0      位置 1          LRU
组 0    [0]        [4]            LRU=1（位置1更老）
组 1    [1]        [空]           -
```

**结果：HIT** ✅

#### ⑦ 访问 2

```
地址 2 → 组 0，Tag 1
组 0 里是 Tag 0 和 Tag 2 → 都不匹配
LRU 显示位置 1（[4]）更老 → 替换它
```

```
        位置 0      位置 1          LRU
组 0    [0]        [2] (tag 1)    LRU=0
组 1    [1]        [空]           -
```

**结果：MISS + 替换** ❌

#### ⑧ 访问 3

```
地址 3 → 组 1，Tag = 3/2 = 1
组 1 位置 0 是 Tag 0，位置 1 空
→ 放入位置 1
```

```
        位置 0      位置 1          LRU
组 0    [0]        [2]            LRU=0
组 1    [1]        [3] (tag 1)    -
```

**结果：MISS** ❌

#### ⑨ 访问 5

```
地址 5 → 组 1，Tag = 5/2 = 2
组 1 里是 Tag 0 和 Tag 1 → 都不匹配
两都有效，需 LRU 判断
```

> ⚠️ **这里需要仔细跟踪 `组 1` 的 LRU 状态。**

**组 1 的访问历史：**

| 时刻 | 访问 | 结果 |
|---|---|---|
| ④ | 地址 1 → 位置 0（首次） | MISS |
| ⑧ | 地址 3 → 位置 1（首次） | MISS |

> **组 1 的 LRU：地址 1 更早被放入 → 位置 0 更老。**

```
替换组 1 的位置 0（[1]）
```

```
        位置 0      位置 1          LRU
组 0    [0]        [2]            LRU=0
组 1    [5] (tag 2) [3]           LRU=1
```

**结果：MISS + 替换** ❌

#### ⑩ 访问 4

```
地址 4 → 组 0，Tag 2
组 0 里是 Tag 0 和 Tag 1 → 都不匹配
替换最老的（位置 0，[0]）
```

```
        位置 0      位置 1          LRU
组 0    [4] (tag 2) [2]           LRU=1
组 1    [5]        [3]            LRU=1
```

**结果：MISS + 替换** ❌

### 3.4 ⭐ 结果统计

| 次数 | 地址 | 结果 |
|---|---|---|
| 1 | 0 | **MISS** |
| 2 | 2 | **MISS** |
| 3 | 0 | **HIT** ✅ |
| 4 | 1 | **MISS** |
| 5 | 4 | **MISS + 替换** |
| 6 | 0 | **HIT** ✅ |
| 7 | 2 | **MISS + 替换** |
| 8 | 3 | **MISS** |
| 9 | 5 | **MISS + 替换** |
| 10 | 4 | **MISS + 替换** |

**总计：**

```
命中 2 次，未命中 8 次（命中率 20%）
```

> ⚠️ **这个访问序列对缓存「很不友好」—— 工作集（0,1,2,3,4,5）有 6 个地址，但缓存只能装 4 个。**

## 四、⭐⭐ 大思想：如何做设计决策

> **「如何在「关联度、块大小、替换策略、写策略」之间选择？」**

### 4.1 核心方法

> **「针对一个「性能模型」来设计：」**

```
最小化：平均内存访问时间（AMAT）
      = Hit Time + Miss Penalty × Miss Rate
```

> **「受「技术」和「程序行为」影响。」**
> **「创造一个「大、便宜、快 —— 平均而言」的内存的幻觉。」**

> ⭐ **「缓存设计的全部工作：用「性能模型」在「多个维度」上做权衡。」**

### 4.2 五个可调旋钮

| 旋钮 | 影响 |
|---|---|
| **① 缓存大小** | **速度 vs 容量** |
| **② 块大小** | **空间局部性 vs miss penalty** |
| **③ 写策略** | **write-through vs write-back** |
| **④ 关联度 N** | **冲突 miss vs 硬件成本** |
| **⑤ 替换策略** | **LRU vs FIFO vs Random** |

## 五、⭐⭐ 降低 Miss Penalty：多级缓存

### 5.1 问题

> **「缓存刚流行时，miss penalty 约「10 个处理器周期」。」**
> **「今天 3 GHz 处理器（1/3 ns 每周期）去 DRAM 要 80 ns（~200 个周期！）」**

```
MEM  ←── 200 周期 ──  $  ←── 1 周期 ──  Proc
```

> ⭐ **「200 周期的 miss penalty 会毁掉流水线的所有收益。」**

### 5.2 解法：L2 缓存

> **「在「内存」和「处理器缓存」之间再加一层缓存：第二级（L2）缓存。」**

```
MEM  ←── 200 周期 ──  $2  ←── 5 周期 ──  $  ←── 1 周期 ──  Proc
```

### 5.3 ⭐ 完整层次

```
        ┌─────────────────────────────────┐
        │ Processor chip                  │
        │  ┌────────┐                     │
        │  │  Core  │                     │
        │  │ Registers                   │
        │  │  ┌──────────┐               │
        │  │  │ L1 Cache │ 极快/极贵/极小 │
        │  │  └──────────┘               │
        │  │  ┌──────────┐               │
        │  │  │ L2 Cache │ 快/贵/小       │
        │  │  └──────────┘               │
        │  │  ┌──────────┐               │
        │  │  │ L3 Cache │ 较快/合理/中   │
        │  │  └──────────┘               │
        │  └────────┘                     │
        └─────────────────────────────────┘
                     │
        ┌────────────▼──────────────┐
        │ DRAM (DDR3/4/5, HBM/HBM2/3)│
        └────────────┬──────────────┘
                     │
        ┌────────────▼──────────────┐
        │ SSD (Flash) / HDD (Magnetic)│
        └───────────────────────────┘
                     │
        ┌────────────▼──────────────┐
        │ Virtual Memory (Disk)      │
        └───────────────────────────┘
```

### 5.4 ⭐ Dan 的 Mac 实际配置

| 参数 | 值 |
|---|---|
| **`hw.cachelinesize`** | **128 字节** |
| **`hw.l1icachesize`** | **131,072（128 KiB = 2¹⁷ B）** |
| **`hw.l1dcachesize`** | **65,536（64 KiB = 2¹⁶ B）** |
| **`hw.l2cachesize`** | **4,194,304（4 MiB = 2²² B）** |

> ⭐ **「L1i 是 L1d 的两倍 —— 因为指令流更可预测，可以用更大的块。」**

## 六、⭐⭐ 多级缓存的 AMAT 计算

### 6.1 递归公式

```
AMAT = L1 Hit Time + L1 Miss Rate × L1 Miss Penalty

其中：
L1 Miss Penalty = L2 Hit Time + L2 Miss Rate × L2 Miss Penalty
```

**展开：**

```
AMAT = L1 Hit Time
     + L1 Miss Rate × (L2 Hit Time
                     + L2 Miss Rate × L2 Miss Penalty)
```

### 6.2 ⭐ 例 1：只有 L1（200 周期到内存）

**假设：**

```
L1 Hit Time   = 1 周期
L1 Miss Rate  = 5%
L1 Miss Penalty = 200 周期
```

**计算：**

```
AMAT = 1 + 0.05 × 200
     = 1 + 10
     = 11 周期
```

### 6.3 ⭐⭐ 例 2：L1 + L2

**假设：**

```
L1 Hit Time       = 1 周期
L1 Miss Rate      = 5%
L2 Hit Time       = 5 周期
L2 Miss Rate      = 15%  ← 注意：这是「L1 miss 中又 miss L2」的比例
L2 Miss Penalty   = 200 周期
```

**先算 L1 miss penalty：**

```
L1 Miss Penalty = 5 + 0.15 × 200
                = 5 + 30
                = 35 周期
```

**再算 AMAT：**

```
AMAT = 1 + 0.05 × 35
     = 1 + 1.75
     = 2.75 周期
```

### 6.4 ⭐ 对比：加上 L2 后快 4 倍

| 配置 | AMAT |
|---|---|
| **只有 L1** | **11 周期** |
| **L1 + L2** | **2.75 周期** |
| **加速比** | **4×** |

> ⭐ **「用 L2 缓存快 4 倍！（2.75 vs 11）」**

### 6.5 ⚠️ 「L2 Miss Rate 为什么这么高」

> **课件提问：L2 miss rate 为什么 10–20% 这么高？**

> ⭐ **因为分母不同！**

```
L1 Miss Rate = L1 miss / 总访问         （5%）
L2 Miss Rate = L2 miss / L1 miss 的次数  （15%）
```

**换算成「总访问」的比例：**

```
实际 L2 miss 占总访问 = 5% × 15% = 0.75%
```

> ⭐ **「0.75% 的访问真要去 DRAM —— 这才是「真正的」内存流量。」**

### 6.6 ⭐ 典型规模

| 层级 | 大小 | 命中时间 | Miss Rate |
|---|---|---|---|
| **L1** | **几十 KB** | **1 个周期内完成** | **1–5%** |
| **L2** | **几百 KB** | **几个周期** | **10–20%**（占 L1 miss）|
| **L3** | **几 MB** | **~40 周期** | **更低** |

> ⭐ **「L1 必须在「一个周期内完成」—— 这是它的设计硬约束（否则流水线要加阶段）。」**

> **这就是为什么 L1 只能几十 KB：更大的话，访问时间超过一个周期。**

## 七、⭐ 反例：直接映射有时能赢 2 路

### 7.1 题目

> **「同一个 2 路组相联缓存（总容量 4 字节、块 1 字节），**
> **但换成这个工作负载：」**

```
0, 2, 0, 4, 2
```

### 7.2 2 路组相联的结果

| 访问 | 结果 |
|---|---|
| **0** | **MISS** |
| **2** | **MISS** |
| **0** | **HIT** |
| **4** | **MISS**（踢出 2）|
| **2** | **MISS** ❌ |

**命中 1 次，miss 4 次。**

### 7.3 直接映射的结果

| 访问 | 结果 |
|---|---|
| **0** | **MISS** |
| **2** | **MISS** |
| **0** | **HIT** |
| **4** | **MISS** |
| **2** | **HIT** ✅ |

**命中 2 次，miss 3 次。**

### 7.4 ⭐ 为什么

> **直接映射的「固定位置」在这个序列里恰好「避免了互相踢出」。**

```
直接映射（4 块，1 路）：
  地址 0 → 索引 0
  地址 1 → 索引 1
  地址 2 → 索引 2
  地址 3 → 索引 3
  地址 4 → 索引 0（和 0 冲突，但 4 用完就被踢，2 还在索引 2）

2 路组相联（2 组，2 路）：
  地址 0 → 组 0
  地址 2 → 组 0  ← 和 0 同组！
  地址 4 → 组 0  ← 和 0、2 同组！三个抢两个位置 → 有 miss
```

> ⭐ **「关联度不是「越大越好」—— 取决于「访问模式的地址分布」。」**

> **这是「性能取决于程序行为」的最好例证。**

## 十、我的笔记与理解

### 10.1 组相联的「本质」：把「冲突」变成「容量」

> **直接映射的痛点是「两块抢一个位置」。**

**组相联怎么解决：**

```
直接映射：索引 → 1 个位置
组相联：  索引 → N 个位置（可以容纳 N 个冲突块）
```

> ⭐ **「N 路组相联 = 把「N 个不同地址映射到同一索引」的情况「容忍」下来。」**

**代价转化：**

| | 直接映射 | N 路组相联 |
|---|---|---|
| **冲突 miss** | 多 | **少** |
| **比较器** | 1 | **N** |
| **替换选项** | 无 | **N 选 1（需要策略）** |
| **hit time** | 最短 | **略长（N 路并行比较 + 选择）** |

> ⭐ **「关联度不是免费午餐 —— 换来的是「hit time 增加」（可能让周期变长）。」**

### 10.2 为什么 LRU 在 4 路以上就「不现实」

> **「4 路或更多需要「复杂的硬件和大量时间」跟踪。」**

**真 LRU 的状态空间：**

| 路数 | 可能的「访问顺序」数 | 需要的状态位 |
|---|---|---|
| **2** | **2! = 2** | **1** |
| **4** | **4! = 24** | **~5** |
| **8** | **8! = 40,320** | **~16** |
| **16** | **16! ≈ 2×10¹³** | **不可能** |

> ⭐ **「这是组合爆炸 —— 16 路缓存根本没法「精确」记录 LRU 顺序。」**

**实际做法：**

| 方案 | 说明 |
|---|---|
| **伪 LRU（tree-based）** | **用一棵二叉树记录「哪半边更老」** |
| **NRU（Not Recently Used）** | **每块 1 位「最近用过」标记** |
| **Random** | **L3 常用（16 路）** |

> ⭐ **「Intel/AMD 的 L3 用「随机或伪 LRU」，不是真 LRU —— 就是这个原因。」**

### 10.3 为什么「L1 miss rate 15% → 总 miss 0.75%」这个换算重要

> **同一个「15%」在两个语境下意义完全不同：**

| 说法 | 含义 | 影响 |
|---|---|---|
| **「L2 miss rate = 15%」** | 15% 的 L1 miss 又 miss L2 | 听起来还行 |
| **「总访问的 0.75% 去 DRAM」** | 0.75% × 总访问 | ✅ **这才是真实代价** |

> ⭐ **算 AMAT 时必须「统一分母」——**
> **这就是为什么公式里要「乘」：`L1 Miss Rate × L2 Miss Rate × L2 Penalty`。**

### 10.4 「4× 加速」的来源拆解

> **从 11 周期降到 2.75 周期：**

```
原：1 + 0.05 × 200           = 1 + 10    = 11
新：1 + 0.05 × (5 + 0.15×200) = 1 + 0.05×35
                              = 1 + 1.75  = 2.75
```

**关键：`0.05 × 200 = 10` 变成了 `0.05 × 35 = 1.75`。**

> ⭐ **「L2 把「miss penalty 从 200 降到 35」—— 这是唯一的变化，但效果巨大。」**

**为什么 L2 能有这么大效果？**

| 层级 | 命中率 |
|---|---|
| **L1** | **95%** |
| **L2** | **L1 miss 中 85% 命中** |
| **合计命中** | **95% + 5%×85% = 99.25%** |

> ⭐ **「只有 0.75% 的访问真的去 DRAM。」**

### 10.5 为什么「直接映射偶尔赢」

> **2 路组相联 `0,2,0,4,2` 输给直接映射 —— 这不是 bug。**

**根本原因：**

```
直接映射：4 个索引 × 1 路 = 「分散」保存
组相联：  2 个组 × 2 路 = 「集中」保存
```

| 序列 | 直接映射（4 个索引）| 2 路（2 组）|
|---|---|---|
| **0** | 索引 0 | 组 0 |
| **2** | **索引 2** ✅ 独立 | 组 0 |
| **4** | 索引 0（踢 0）| 组 0（踢）|
| **2** | **索引 2 — 还在！** ✅ | **组 0 — 被踢了** ❌ |

> ⭐ **「索引越多 = 「分散度」越高 = 某些访问模式下冲突越少。」**

**这揭示了一个深刻事实：**

```
关联度 (N) 和 组数 是「此消彼长」的：
  总块数 = 组数 × N
  组数多 → 分散好（少冲突）但 N 小
  N 大 → 容忍冲突但组数少
```

> **所以「2 路 vs 直接映射」不是简单的「2 路更好」，要看工作负载。**

### 10.6 缓存的「七维设计空间」

> **本课把所有旋钮都摆出来了：**

```
        缓存大小
           │
      块大小
           │
      写策略 ─┼─ 关联度 N
           │
      替换策略
           │
      L2?  L3?
```

> ⭐ **「没有一个「最优设计」—— 只有「针对某类程序、某代工艺、某个预算」的最优设计。」**

> **这就是为什么 CPU 厂商要针对 SPEC 基准、手机、服务器分别调参。**

### 10.7 「缓存是通用原则」的三个层次

| 层次 | 例子 |
|---|---|
| **硬件** | L1/L2/L3、TLB、分支预测器、写缓冲 |
| **操作系统** | 页缓存、inode 缓存、dentry 缓存 |
| **应用** | 浏览器缓存、CDN、Redis、memoization |

> ⭐ **「同一个模式在不同抽象层反复出现 ——」**
> **「代价高 + 反复做 → 做一次并缓存。」**

> **这就是 L26 开头说的「缓存处处都有」的具体表现。**

### 10.8 与整门课的关系

| 阶段 | 内容 | 缓存的作用 |
|---|---|---|
| **L09–L15** | RISC-V 指令集 | `lw`/`sw` 访问"内存" |
| **L16–L19** | 数字电路 | tag 比较器、MUX |

> ⭐ **「流水线优化「计算」，缓存优化「访存」—— 两者合起来才是完整的性能故事。」**
