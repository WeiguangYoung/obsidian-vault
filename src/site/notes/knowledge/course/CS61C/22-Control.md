## 一、进度：Datapath 已完整

> **我们已经设计出一个完整的 datapath：**

| 能力 | 说明 |
|---|---|
| **✅ 能执行全部 RISC-V 指令** | 每条一个周期 |
| **⚠️ 不是所有单元都被所有指令使用** | 很多硬件闲着 |
| **✅ 五个执行阶段** | IF、ID、EX、MEM、WB |
| **⚠️ 不是所有指令在所有阶段都活跃** | |

> **「Controller 指定如何执行指令 —— 我们还需要设计它。」**

## 二、单周期 CPU 全景图

```
        ┌──────────────────── 控制逻辑 ─────────────────────┐
        │  BrEq BrLT → PCSel │ ImmSel │ ASel BSel ALUSel     │
        │  MemRW │ RegWEn │ WBSel                          │
        └───┬────────┬────────┬────────┬────────┬──────────┘
            │        │        │        │        │
  ┌─────────▼────────▼────────▼────────▼────────▼──────────┐
  │                                                        │
  │  PC ──► IMEM ──► 拆分指令 ──► Reg[ ] ──► ALU ──► DMEM   │
  │   ▲                                       │        │     │
  │   └──────────── PCSel MUX ◄───────────────┘        │     │
  │                                                    ▼     │
  │                              WBSel MUX ──► Reg[ ] 写     │
  └────────────────────────────────────────────────────────┘
```

**输入：** `Inst[31:0]`（整个指令都进控制逻辑）
**输出：** 所有控制信号

## 三、逐指令走一遍（每个例子的信号值）

### 3.1 `sw reg, offset(regbaseptr)`

| 信号 | 值 | 为什么 |
|---|---|---|
| **ImmSel** | **S** | S 格式 |
| **PCSel** | **pc+4** | 顺序执行 |
| **RegWEn** | **0** | **不写寄存器** |
| **ASel** | **0** | 用 R[rs1] |
| **BSel** | **1** | 用 imm（算地址）|
| **ALUSel** | **add** | `addr = R[rs1] + imm` |
| **MemRW** | **Write** | **写内存** |
| **BrUn** | **\*** | 无关 |
| **BrEq / BrLT** | **\*** | 无关 |
| **WBSel** | **\*** | `RegWEn=0`，写回无关 |

### 3.2 `beq reg1, reg2, Label`

| 信号 | 值 | 为什么 |
|---|---|---|
| **ImmSel** | **B** | B 格式 |
| **PCSel** | **取决于 BrEq** | 成立跳转，否则 +4 |
| **RegWEn** | **0** | 不写 |
| **ASel** | **1** | **用 PC**（算 PC+imm）|
| **BSel** | **1** | 用 imm |
| **ALUSel** | **add** | `PC + imm` |
| **MemRW** | **Read** | 不写内存 |
| **BrUn** | **\*** | `beq` 无关符号 |
| **WBSel** | **\*** | 不写回 |

### 3.3 `add rd, reg1, reg2`

| 信号 | 值 | 为什么 |
|---|---|---|
| **ImmSel** | **\*** | 不用立即数 |
| **PCSel** | **pc+4** | 顺序 |
| **RegWEn** | **1** | **写寄存器** |
| **ASel** | **0** | R[rs1] |
| **BSel** | **0** | **R[rs2]** |
| **ALUSel** | **add** | 加法 |
| **MemRW** | **Read** | 不写内存 |
| **WBSel** | **1** | **选 ALU** |

### 3.4 `lw reg, offset(regbaseptr)`

| 信号 | 值 |
|---|---|
| **ImmSel** | **I** |
| **PCSel** | **pc+4** |
| **RegWEn** | **1** |
| **ASel** | **0** |
| **BSel** | **1** |
| **ALUSel** | **add** |
| **MemRW** | **Read** |
| **WBSel** | **0**（**选 mem**）|

## 四、⭐ 指令时序：关键路径计算

### 4.1 `add` 的关键路径

> **关键路径 = 从「某个寄存器的输出」到「某个寄存器的输入」的最长延迟路径。**

```
候选路径 1：PC → +4 加法器 → PC
           tAdd + tmux

候选路径 2：PC → IMEM → Reg[ ] → mux → ALU → mux → Reg[ ]
           tIMEM + tReg + tmux + tALU + tmux
```

**公式：**

```
关键路径 = t_clk-q + max{ tAdd + t_mux,
                          tIMEM + t_Reg + t_mux + t_ALU + t_mux }
                     + t_setup

        = t_clk-q + tIMEM + t_Reg + t_mux + t_ALU + t_mux + t_setup
```

> ⭐ **显然路径 2 更长 —— IMEM 和 Reg 读都是必经之路。**

### 4.2 `lw` 的关键路径（更长）

```
候选路径：
  ① tAdd + tmux
  ② tIMEM + tImm + tmux + tALU + tDMEM + tmux
  ③ tIMEM + tReg + tmux + tALU + tDMEM + tmux
```

**公式：**

```
T = t_clk-q + max{ tAdd + t_mux,
                   tIMEM + t_Imm + t_mux + t_ALU + t_DMEM + t_mux,
                   tIMEM + t_Reg + t_mux + t_ALU + t_DMEM + t_mux }
                + t_setup
```

> ⚠️ **`lw` 是单周期 CPU 中最长的指令 —— 它决定了整个时钟周期。**

## 五、⭐ 指令时序数字表

### 5.1 各阶段耗时

| 阶段 | 名称 | 耗时 |
|---|---|---|
| **IF** | I-MEM | **200 ps** |
| **ID** | Reg Read | **100 ps** |
| **EX** | ALU | **200 ps** |
| **MEM** | D-MEM | **200 ps** |
| **WB** | Reg Write | **100 ps** |
| **Total** | | **800 ps** |

### 5.2 每种指令用哪些阶段

| 指令 | IF | ID | EX | MEM | WB | **总计** |
|---|---|---|---|---|---|---|
| **add** | ✅ | ✅ | ✅ | ✗ | ✅ | **600 ps** |
| **beq** | ✅ | ✅ | ✅ | ✗ | ✗ | **500 ps** |
| **jal** | ✅ | ✅ | ✅ | ✗ | ✅ | **500 ps** ⚠️ |
| **lw** | ✅ | ✅ | ✅ | ✅ | ✅ | **800 ps** |
| **sw** | ✅ | ✅ | ✅ | ✅ | ✗ | **700 ps** |

> ⚠️ **课件里 `jal` 也标了 WB**（要写返回地址 `rd = PC+4`）**但没有 MEM。**
> **所以 `jal` = IF+ID+EX+WB = 200+100+200+100 = 600 ps？**
> 课件给的是 **500 ps** —— 说明它把某些阶段「重叠」计入。
> **关键结论不变：`lw` = 800 ps 是最长的。**

### 5.3 ⭐ 两个残酷的结论

```
f_max = 1 / 800 ps = 1.25 GHz
```

> **但注意：**

```
f_max,ALU = 1 / 200 ps = 5 GHz
```

> ⭐ **「大多数块在大多数时间是闲置的。」**

| 事实 | 后果 |
|---|---|
| **时钟按 lw 定 = 1.25 GHz** | `add` 只需 600 ps，浪费 200 ps |
| **ALU 本身能跑 5 GHz** | 但被 IMEM/Reg/DMEM 拖慢 |

> **这就是 L23 流水线的全部动机。**

|---|---|---|---|---|---|---|---|---|---|---|---|
| **add** | \* | \* | +4 | \* | \* | 0 | 0 | **Add** | Read | **1** | **ALU** |
| **sub** | \* | \* | +4 | \* | \* | 0 | 0 | **Sub** | Read | 1 | ALU |
| **R-R Op** | \* | \* | +4 | \* | \* | 0 | 0 | **Op** | Read | 1 | ALU |

| **bne(成立)** | **0** | \* | **ALU** | B | \* | 1 | 1 | Add | Read | 0 | \* |

### 6.1 表格里的「三处 \*最值钱」

| 位置 | 意义 |
|---|---|
| **sw 的 WBSel = \*** | `RegWEn=0`，整条写回路径随便 |
| **分支的 BrUn = \*** | `beq`/`bne` 不关心大小 |
| **jal 的 BrEq/BrLT = \*** | 无条件跳转 |

> **每多一个 `*`，控制逻辑就少一个门。**

## 七、控制逻辑的两种实现方式

### 7.1 方式一：ROM（只读存储器）

| 特点 | 说明 |
|---|---|
| **结构规整（regular structure）** | 适合手写设计 |
| **容易重新编程** | 可以修 bug、加指令 |
| **「手工设计控制逻辑时很流行」** | |

**结构：**

```
        ┌──────────────────────┐
 9 位    │  11 位地址译码器      │
 指令位 ─►│                      │
        │        ROM           │──► 15 位数据（控制字）
 BrEq ─►│                      │
 BrLT ─►│                      │
        └──────────────────────┘
```

| 输入 | 位宽 | 内容 |
|---|---|---|
| **指令位** | **9** | `Inst[30, 14:12, 6:2]` |
| **BrEq** | 1 | 分支相等 |
| **BrLT** | 1 | 分支小于 |
| **总地址** | **11** | |

| 输出（控制字）| 位宽 |
|---|---|
| **PCSel** | 1 |
| **ImmSel** | **3** |
| **BrUn** | 1 |
| **ASel** | 1 |
| **BSel** | 1 |
| **ALUSel** | **4** |
| **MemRW** | 1 |
| **RegWEn** | 1 |
| **WBSel** | **2** |
| **总数据** | **15** |

### 7.2 ⭐ RV32I 是「9 位 ISA」！

> **指令类型只用 9 位编码：**

```
inst[30]  +  inst[14:12]  +  inst[6:2]
   1 bit        3 bits          5 bits
                ↓
           共 9 bit
```

| 位段 | 含义 |
|---|---|
| **`inst[6:2]`** | opcode 的「有效部分」（bit[1:0] 恒为 `11`）|
| **`inst[14:12]`** | funct3 |
| **`inst[30]`** | funct7 的 bit[5] |

> ⭐ **为什么只要 9 位？**
> - **`inst[1:0]` 恒为 `11`**（所有 RV32I 指令都是 32 位）→ 不需编码
> - **funct7 只用 1 位**（区分 `add`/`sub`、`srl`/`sra`）→ 其余无效

### 7.3 方式二：组合逻辑

> **「今天，芯片设计者用逻辑综合工具把真值表转成门网络。」**

**手工推导例子：`add` 的解码**

```
add = i[30] · i[14] · i[13] · i[12] · R-type

其中：
R-type = i[6] · i[5] · i[4] · i[3] · i[2] · RV32I
RV32I  = i[1] · i[0]
```

**展开：**

```
add = i[30] · i[14] · i[13] · i[12]
    · i[6] · i[5] · i[4] · i[3] · i[2]
    · i[1] · i[0]
```

> **一个 11 输入的 AND 门（层次化搭建）就能识别 `add`。**

**为什么 `i[30]=1`？**

| 指令 | funct7 | `inst[30]` |
|---|---|---|
| **add** | `0000000` | **0** |
| **sub** | `0100000` | **1** |

> ⚠️ **课件写 `add = i[30]·...`，但按编码 `add` 的 `inst[30]=0`。**
> **这可能是课件笔误，或是用「反相」约定。记住：`inst[30]` 用来区分 `add` 和 `sub` 就够了。**

**为什么 `i[14]·i[13]·i[12]` 都是 1？**

> **`add` 的 funct3 = `000`，所以按位取反后是 `111`。**
> **若写成「正逻辑」则应为 `¬i[14]·¬i[13]·¬i[12]`。**

### 7.4 `BrUn` 的解码（最简）

```
BrUn = inst[13] · Branch
```

> **一个 2 输入 AND 门。**

| 指令 | funct3 | `inst[13]` | BrUn |
|---|---|---|---|
| **blt** | 100 | 0 | 0 |
| **bge** | 101 | 0 | 0 |
| **bltu** | 110 | **1** | **1** ✅ |
| **bgeu** | 111 | **1** | **1** ✅ |

> ⭐ **`inst[13]` 天然就是「有符号/无符号」开关 —— 编码设计的红利。**

## 八、🎉 结论：HW/SW 接触成功

> **「Call home, we've made HW/SW contact!」**

### 8.1 完整链条终于闭合

```
temp = v[k];          ┐
v[k] = v[k+1];        │ 高级语言（C）
v[k+1] = temp;        ┘
        ↓ 编译器
lw  x3, 0(x10)        ┐
lw  x4, 4(x10)        │ 汇编（RISC-V）
sw  x4, 0(x10)        │
sw  x3, 4(x10)        ┘
        ↓ 汇编器
1000 1101 1110 0010   ┐ 机器码
1000 0001 0000 0100   │
1010 0001 0010 1110   │
1010 1110 0010 0000   ┘
        ↓ 硬件架构描述（方块图）
       [PC][IMEM][Reg][ALU][DMEM]
        ↓ 逻辑电路描述（电路原理图）
       [与门][或门][触发器]...
        ↓
       硅
```

> ⭐ **「从一段 C 代码，一路走到硅片上的电子」—— 这就是 CS61C 的完整旅程。**

## 九、我的笔记与理解

### 9.1 单周期 CPU 的「优雅」与「愚蠢」

| 优雅之处 | 愚蠢之处 |
|---|---|
| **结构极简** | **周期 = 最慢指令** |
| **控制逻辑只是查表** | **`add` 浪费 200 ps** |
| **无冒险、无冲突** | **ALU 只用 1/4 的时间** |
| **好理解、好验证** | **频率被 `lw` 钉死在 1.25 GHz** |

> ⭐ **「大多数块在大多数时间闲置」—— 这句话是 L23 流水线的唯一动机。**

**利用率计算：**

```
add:  600/800 = 75%
beq:  500/800 = 62.5%
DMEM: 只有 lw/sw 用 → 2/15 ≈ 13%
```

> **如果 DMEM 占芯片面积的 20%，那它 87% 的时间在耗电却不干活。**

### 9.2 「9 位 ISA」的深层含义

> **RV32I 只用 9 位就能唯一确定「怎么做」。**

```
剩下的 23 位（rs1/rs2/rd/imm）都是「数据」而不是「控制」
```

**这解释了 datapath 与控制逻辑的分工：**

| 位段 | 去哪 |
|---|---|
| **`inst[30,14:12,6:2]`（9 位）** | **控制逻辑** |
| **`inst[31:20, 24:20, 19:15, 11:7]`** | **datapath（寄存器索引、立即数）** |

> ⭐ **「9 位决定做什么，23 位决定对谁做。」**

### 9.3 ROM 为什么不流行了

> **课件说「手工设计时很流行」，暗示今天不同。**

**ROM 的缺点（现代视角）：**

| 缺点 | 说明 |
|---|---|
| **访问延迟** | ROM 读出要时间，可能进关键路径 |
| **面积** | 2^11 × 15 bit ≈ 30k bit |
| **不可优化** | 无法跨指令共享逻辑 |
| **工艺不友好** | ROM 单元比逻辑门难缩小 |

**现代做法：逻辑综合 + 手工优化关键路径**

> **真实的 RISC-V 核（如 SiFive U74）的控制逻辑是「综合出来的门网络 + 手工修补」。**

### 9.4 `lw` 决定频率：一个残酷的巧合

> **为什么偏偏是最「重」的指令？**

```
lw 需要：IMEM + Reg + ALU + DMEM + Reg
add 需要：IMEM + Reg + ALU + Reg
```

> **差的就是 DMEM。**

| 缓解方式 | 说明 |
|---|---|
| **切流水线** | 让 DMEM 单独占一段 ← L23 |
| **DMEM 做在前半周期** | 但单周期不行 |
| **I-Cache / D-Cache** | 让 DMEM 变快 ← L26 |

### 9.5 关键路径的实战启示

> **算关键路径不是背公式，而是「枚举所有路径，取最长」。**

**练习步骤：**

| # | 动作 |
|---|---|
| **1** | **从每个状态元件的输出出发** |
| **2** | **沿数据流走到下一个状态元件的输入** |
| **3** | **累加延迟** |
| **4** | **取最大者，加 `t_clk-q` 和 `t_setup`** |

**常见错误：**

| 错误 | 说明 |
|---|---|
| **漏掉 `t_clk-q`** | 寄存器输出不是「瞬间」的 |
| **漏掉 `t_setup`** | 下一级寄存器要提前稳定 |
| **只看一条路径** | 必须枚举全部 |
| **把控制逻辑算进去** | 控制信号在「周期开始」就稳定，不在关键路径上 |

### 9.6 「don't care」的工程价值

> **真值表里的 `*` 不是「没想清楚」，而是「明确知道无所谓」。**

**好处：**

| 好处 | 说明 |
|---|---|
| **简化逻辑** | 综合工具可以自由选择最优值 |
| **减少门数** | 一个 `*` 可能省掉一个与门 |
| **便于验证** | 只需验证「非 `*` 的情况」 |

> ⭐ **「`sw` 的 `WBSel=*` 意味着：任何值都对，所以综合工具会挑「最省门」的那个。」**

### 9.7 与后续的衔接

| 讲次 | 关系 |
|---|---|
| **L23 Pipeline I** | 五级流水线：把单周期切成 5 段，频率 ×5 |
| **L24 Pipeline II** | 数据冒险、控制冒险、forwarding |
| **L25 Pipeline III** | 冒险的更多解法、性能计算 |
| **L26–L29** | 缓存：让 IMEM/DMEM 变快 |
